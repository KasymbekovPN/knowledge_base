## HRTB (Higher-Rank Trait Bounds)

## Философия: Зачем это нужно?

Обычно времена жизни работают по принципу «снаружи внутрь»: когда вы вызываете функцию, вызывающий код (тот, кто снаружи) решает, сколько живет ссылка.

Но представьте, что вы пишете функцию-обработчик, которая сама внутри себя создает данные, берет на них ссылку и передает их в замыкание (колбэк). В этом случае время жизни ссылки рождается внутри функции. Внешний код о нем ничего не знает.

## 🛑 Проблема без HRTB

Попробуем написать функцию, которая принимает замыкание и применяет его к локальной строке.

```rust
// Мы пытаемся сказать: "f принимает ссылку с временем жизни 'a"
fn process_data<'a, F>(f: F) 
where 
    F: Fn(&'a str) 
{
    let local_string = String::from("Данные"); // Данные созданы внутри
    f(&local_string); // ❌ ОШИБКА КОМПИЛЯЦИИ!
}
```

Почему компилятор ругается?  
Компилятор мыслит так: _«Ага, `'a` объявлено на уровне функции `process_data<'a, ...>`. Значит, это время жизни выбирает тот, кто эту функцию вызывает. Вызывающий может потребовать, чтобы `'a` длилось весь `main`. Но `local_string` умирает в конце `process_data`. Я не могу гарантировать, что `local_string` проживет так же долго, как внешнее `'a`»_.

## Решение с HRTB (`for<'a>`)

Нам нужно объяснить компилятору: _«Нам не важно, какое `'a` выберет вызывающий код. Нам нужно, чтобы замыкание `F` умело работать с абсолютно любым временем жизни `'a`, которое мы ему подкинем внутри»_.

```rust
// Читается так: "F реализует Fn(&str) ДЛЯ ВСЕХ ('for') времен жизни 'a"
fn process_data<F>(f: F) 
where 
    F: for<'a> Fn(&'a str) 
{
    let local_string = String::from("Локальные данные");
    f(&local_string); //  ТЕПЕРЬ РАБОТАЕТ!
}

fn main() {
    // Замыкание просто печатает то, что ему дали
    process_data(|text| println!("Получено: {}", text));
}
```

_Примечание:_ В современном Rust для простых замыканий синтаксис `for<'a>` часто выводится автоматически (это называется _Lifetime Elision_ для трейтов), но под капотом работает именно HRTB. Знать его синтаксис необходимо, когда вы строите сложные цепочки парсеров или асинхронных колбэков.
