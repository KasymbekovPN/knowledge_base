## Вариантность (Variance)

## Философия: Подтипы во временах жизни

В Rust нет классического наследования классов, но есть наследование времен жизни.  
Если время жизни `'long` длиннее, чем `'short`, то мы можем сказать, что `'long` является _подтипом_ `'short` (ведь если ссылка валидна долго, ее можно безопасно использовать там, где требуется короткий срок). Обозначается это как `'long: 'short`.

Вариантность — это свойство сложных типов (структур, ссылок, указателей), которое определяет, передается ли это отношение подтипов «внутрь» контейнера.

## Тип 1: Ковариантность (Covariant) — Сужение разрешено

Если тип ковариантен, вы можете передать длинное время жизни туда, где ожидается короткое.

- Пример: Обычная ссылка `&'a T` ковариантна по `'a`.

```rust
fn take_short_lifetime<'a>(text: &'a str) {
    println!("Короткая ссылка: {}", text);
}

fn main() {
    // 'static живет до конца программы (очень длинное)
    let static_str: &'static str = "Я вечен"; 
    
    // Передаем 'static туда, где ожидается обычное локальное 'a.
    // Это работает, потому что &'a T ковариантен по 'a (сжатие разрешено).
    take_short_lifetime(static_str); 
}
```

## Тип 2: Инвариантность (Invariant) — Строгое совпадение

Если тип инвариантен, компилятор требует идеального совпадения времен жизни. Никаких «длиннее/коротче».

- Пример: Мутабельная ссылка `&'a mut T` инвариантна по типу `T`.

Зачем это нужно? Защита от прострела колена! Если бы `&mut T` позволял ковариантность, мы могли бы записать короткоживущую ссылку в долгоживущий контейнер, а потом прочитать «мусор» (use-after-free).

```rust
fn evil_swap<'a>(important_place: &mut &'a str, cheap_trick: &'a str) {
    *important_place = cheap_trick; // Перезаписываем ссылку
}

fn main() {
    let mut main_ptr: &'static str = "Важная статическая строка";

    {
        let short_string = String::from("Короткая строка");
        
        // ОШИБКА КОМПИЛЯЦИИ: main_ptr имеет тип &'static str.
        // evil_swap пытается временно "сжать" 'static до времени жизни этого блока.
        // Из-за инвариантности по T, Rust говорит: "Нет, &mut &'static str 
        // нельзя превратить в &mut &'block str".
        evil_swap(&mut main_ptr, &short_string); 
    }

    // Если бы код скомпилировался, здесь main_ptr указывал бы на 
    // уже удаленную short_string! Был бы краш.
    println!("{}", main_ptr); 
}
```

## Тип 3: Контравариантность (Contravariant) — Расширение

Встречается только в одном месте: аргументы функций (`fn(T)`). Она позволяет передавать функцию, ожидающую _короткое_ время жизни, туда, где требуется функция, ожидающая _длинное_.

Представьте, что у вас есть две функции:

1. `fn( &'static str )` — принимает только статические строки.
2. `fn( &'a str )` — умеет работать с вообще любыми строками (всеядный менеджер).

Если системе нужна функция, которая обработает `&'static str`, вы можете подсунуть ей вторую («всеядную») функцию? Да, потому что если она умеет работать с любыми короткими строками, то со статической она точно справится. Время жизни аргумента «расширилось».

## Шпаргалка для практики

Когда вы проектируете свои структуры (особенно связанные со сложным управлением памятью или FFI/С-указателями):

1. Используйте `&'a T`, если структура должна просто читать данные. Она будет ковариантной, и с ней будет легко работать.
2. Используйте `&'a mut T` или `Cell / RefCell`, если структура будет изменять данные. Помните, что они сделают ваши типы инвариантными.
3. Используйте `PhantomData`, если пишете unsafe-код с сырыми указателями (`*const T` или `*mut T`), чтобы вручную подсказать компилятору, какую вариантность вы хотите для структуры.
