Раз уже прошли `match`, логично закрыть остальные конструкции ветвления и циклов — там тоже хватает отличий от C++.

## `if`/`else` — тоже выражение, не оператор

Это уже мелькало в разговоре про `let`, но стоит закрепить отдельно:

```rust
let x = 5;

let description = if x > 0 {
    "положительное"
} else if x < 0 {
    "отрицательное"
} else {
    "ноль"
};
```

В C++ пришлось бы либо использовать тернарный оператор (ограниченный одним выражением), либо объявлять переменную заранее и присваивать внутри блоков:

```cpp
std::string description;
if (x > 0) description = "положительное";
else if (x < 0) description = "отрицательное";
else description = "ноль";
```

Важное правило: если `if` используется как выражение (значение из него берётся), **все ветки обязаны возвращать один и тот же тип**, и `else` обязателен — иначе непонятно, что вернуть, если условие ложно:

```rust
let x = if condition { 5 } else { 6 };       // ОК, оба i32
let y = if condition { 5 } else { "six" };   // ОШИБКА: типы не совпадают
let z = if condition { 5 };                  // ОШИБКА: нет else, а тип должен быть ()
```

Если `if` используется как **оператор** (значение отбрасывается, просто side-effect), `else` не обязателен — как в C++.

## Условие — обязательно `bool`, никакого неявного приведения

```rust
let n = 5;
if n {} // ОШИБКА: expected bool, found integer
```

В C++ `if (n)` прекрасно скомпилируется — любое ненулевое число приводится к `true`. В Rust неявных приведений к `bool` нет вообще ни для чисел, ни для указателей — нужно писать явно `if n != 0`. Это устраняет целый класс опечаток (`if (x = 5)` вместо `if (x == 5)` — кстати, такая опечатка в Rust тоже не скомпилируется, потому что `=` возвращает `()`, а не `bool`, и `()` нельзя использовать как условие).
