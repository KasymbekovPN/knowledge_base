Продолжаем ту же логику: смотрим, что в Rust устроено иначе, а что — прямой перенос из C++.

## Базовый синтаксис

```rust
fn add(a: i32, b: i32) -> i32 {
    a + b // последнее выражение без `;` — неявный return
}

fn greet(name: &str) {
    println!("Hello, {name}!");
}
```

Явный `return` тоже работает и обязателен для раннего выхода:

```rust
fn abs(x: i32) -> i32 {
    if x < 0 {
        return -x;
    }
    x
}
```

## Модули вместо namespace/translation units

В C++ свободная функция живёт либо в глобальном пространстве имён, либо в `namespace`, а видимость между единицами трансляции регулируется заголовками и `extern`. В Rust всё организовано через **модули** (`mod`), и видимость — явная, через `pub`:

```rust
mod geometry {
    pub fn area(w: f64, h: f64) -> f64 {  // pub — видна снаружи модуля
        w * h
    }

    fn helper() -> f64 { // приватная по умолчанию — аналог static-функции в .cpp файле
        0.0
    }
}

fn main() {
    let a = geometry::area(3.0, 4.0); // как namespace::function в C++
}
```

Ключевое отличие: **приватность по умолчанию**. В C++ функция в `.cpp` файле без `static` по умолчанию имеет внешнее связывание (её видно линкеру из других единиц трансляции, если объявить extern) — это источник классических ODR-проблем. В Rust функция по умолчанию видна только внутри своего модуля, и `pub` нужно указывать явно на каждом уровне видимости.

## Нет перегрузки функций — важное отличие

В C++ ты пишешь несколько `add` с разными типами параметров, и компилятор выбирает нужную по сигнатуре:

```cpp
int add(int a, int b);
double add(double a, double b);
std::string add(const std::string& a, const std::string& b);
```

В Rust перегрузки по имени **не существует**. Варианты, которыми это заменяется:

**1. Дженерики с trait bounds** (если логика одна и та же для всех типов):

```rust
use std::ops::Add;

fn add<T: Add<Output = T>>(a: T, b: T) -> T {
    a + b
}
```

**2. Разные имена** (если логика разная — это на самом деле чаще идиоматично, чем в C++):

```rust
fn add_ints(a: i32, b: i32) -> i32 { a + b }
fn add_strings(a: &str, b: &str) -> String { format!("{a}{b}") }
```

**3. Трейты для "перегрузки" операторов** — это единственное место, где что-то похожее на overload resolution есть, но через явную реализацию типажа (`impl Add for MyType`), а не ad-hoc сигнатуры.

## Нет параметров по умолчанию

В C++ `void f(int a, int b = 10)` — привычная вещь. В Rust этого нет вообще. Идиоматичные замены:

```rust
// Вариант 1: Option
fn connect(host: &str, timeout: Option<u32>) {
    let t = timeout.unwrap_or(30);
}

// Вариант 2: builder-паттерн (см. прошлый пример с Builder)
// Вариант 3: несколько функций
fn connect_default(host: &str) { connect(host, 30) }
fn connect(host: &str, timeout: u32) { /* ... */ }
```

## extern "C" — свободные функции для FFI

Это будет важно для твоей темы интеропа с существующей C++ кодовой базой (Фаза 5 из плана):

```rust
#[no_mangle]
pub extern "C" fn rust_add(a: i32, b: i32) -> i32 {
    a + b
}
```

Прямой аналог `extern "C"` в C++ — отключает name mangling и Rust-специфичный ABI, чтобы функцию можно было слинковать из C/C++ кода. `#[no_mangle]` — обязателен, иначе Rust всё равно замангланит имя по-своему.

## Инлайнинг — иная семантика, чем в C++

```rust
#[inline]
fn small_fn(x: i32) -> i32 { x + 1 }
```

В C++ `inline` — это в первую очередь способ **разрешить множественные определения** в разных единицах трансляции без нарушения ODR (историческая причина существования ключевого слова), а подсказка компилятору — вторична. В Rust `#[inline]` — **только** подсказка оптимизатору (компилятор волен её проигнорировать), потому что вопрос ODR в Rust не стоит — модель компиляции другая (per-crate, без заголовочных файлов).

## Сводная таблица

|Особенность|C++|Rust|
|---|---|---|
|Организация|namespace + единицы трансляции|модули (`mod`)|
|Видимость по умолчанию|внешняя (external linkage)|приватная|
|Перегрузка по имени|Есть|Нет (generics/traits/разные имена)|
|Параметры по умолчанию|Есть|Нет (Option/builder/перегрузка имён)|
|Функции как значения|указатель / `std::function` / шаблон+лямбда|`fn` / `impl Fn` / `dyn Fn` — явно разные семантики|
|`inline`|ODR-механизм + подсказка|только подсказка оптимизатору|
|FFI-экспорт|обычная функция + `extern "C"`|`#[no_mangle] pub extern "C" fn`|

Дальше логично разобрать **трейты** (`trait`) — раз уже несколько раз всплыли (`Fn`, `Add`, `Clone`) и напрямую связаны с тем, как в Rust решается то, что в C++ закрывают перегрузка + шаблоны + виртуальные функции одновременно.
