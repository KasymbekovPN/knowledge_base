Разберём `let` подробно — это как раз то место, где сходятся почти все темы, которые уже обсуждали: mut, move, паттерны.

## Базовый синтаксис

```rust
let x = 5;
let y: i32 = 5; // с явной аннотацией типа
```

По умолчанию — неизменяемое связывание (мы это уже трогали в прошлый раз). Прямого аналога в C++ по сути два, склеенных в одно:

```cpp
const auto x = 5;   // если хочешь неизменяемость — как let без mut
auto y = 5;         // если просто хочешь вывод типа — как let mut
```

Разница принципиальная: в C++ `const` — опция, которую ты **выбираешь**. В Rust неизменяемость — **дефолт**, а `mut` — то, что добавляешь осознанно:

```rust
let mut x = 5;
x = 6; // ОК
```

## `let` — это не просто объявление переменной, это паттерн

Вот ключевая вещь, которой в C++ нет вообразимого аналога: слева от `=` в `let` стоит не имя переменной, а **паттерн** (pattern), и `let x = 5` — это частный случай, где паттерн — просто идентификатор.

```rust
let (a, b) = (1, 2);              // деструктуризация кортежа
let [first, second, third] = [1, 2, 3]; // деструктуризация массива
let Point { x, y } = Point { x: 1, y: 2 }; // деструктуризация struct

struct Point { x: i32, y: i32 }
```

Ближайший аналог в C++ — structured bindings (C++17):

```cpp
auto [a, b] = std::make_pair(1, 2);
```

Но в Rust это тот же самый механизм паттерн-матчинга, что используется в `match`, `if let`, параметрах функций — единая система, а не отдельная фича только для `let`. Можно даже игнорировать часть значения через `_`:

```rust
let (x, _, z) = (1, 2, 3); // средний элемент не нужен
let Point { x, .. } = p;    // остальные поля struct игнорируем
```

## Shadowing — вот чего в C++ нет вообще

Это, наверное, самая непривычная вещь для C++-разработчика. В Rust можно объявить `let` с тем же именем несколько раз в одной области видимости — каждое новое `let` **затеняет** предыдущее, создавая, по сути, новую переменную:

```rust
let x = 5;
let x = x + 1;      // новая переменная x, старая x (со значением 5) больше не видна
let x = x * 2;       // ещё одна новая x
println!("{x}");     // 12
```

Это **не то же самое**, что `mut`:

```rust
let mut y = 5;
y = y + 1; // мутация того же самого места в памяти, тот же тип обязателен

let x = 5;
let x = "теперь строка"; // shadowing позволяет ДАЖЕ СМЕНИТЬ ТИП — это новая переменная
```

В C++ такого нет — переобъявить переменную с тем же именем в той же области видимости просто нельзя (ошибка компиляции "redefinition"). Ближайшее по духу — вложенные `{}` блоки, где внутренняя переменная затеняет внешнюю, но shadowing в Rust работает и **в одной и той же области видимости**, последовательно, что чаще всего используют для цепочки преобразований одного значения без выдумывания имён `x1`, `x2`, `x_parsed`:

```rust
let input = "  42  ";
let input = input.trim();          // &str -> &str, но обрезанный
let input: i32 = input.parse().unwrap(); // &str -> i32, тип сменился
```

## `let` и move — прямое продолжение прошлого разговора

```rust
let s1 = String::from("hello");
let s2 = s1; // move: s1 больше не валиден
```

Уже разбирали это подробно раньше — здесь просто фиксируем, что `let` — это ровно то место, где происходит move при инициализации из уже существующей владеющей переменной.

## `let` без инициализации — отложенная инициализация

```rust
let x: i32; // объявлен, но не инициализирован

if condition {
    x = 1;
} else {
    x = 2;
}

println!("{x}"); // ОК — компилятор доказал, что x инициализирован на всех путях
```

Это похоже на C++, где тоже можно объявить переменную без инициализации:

```cpp
int x;
if (condition) x = 1; else x = 2;
```

Но с принципиальной разницей: в C++ если забыть присвоить `x` на одном из путей — это **неопределённое поведение** при чтении (компилятор в лучшем случае предупредит). В Rust компилятор **доказывает через анализ потока управления**, что переменная гарантированно инициализирована на любом пути к месту использования — если не доказал, это ошибка компиляции ("used binding is possibly-uninitialized"), а не рантайм-баг.

## `let else` — довольно новая конструкция (стабилизирована в 1.65)

Полезна, когда нужно либо успешно деструктурировать значение, либо сразу выйти из функции:

```rust
fn get_count(s: &str) -> u32 {
    let Ok(count) = s.parse::<u32>() else {
        return 0; // если parse не Ok — сразу выходим, count просто не существует дальше
    };
    count * 2 // здесь count уже гарантированно valid u32, без Option/Result обёртки
}
```

Это избавляет от вложенного `match`/`if let ... else` с дублированием кода — типичная альтернатива без `let else` выглядела бы так:

```rust
fn get_count(s: &str) -> u32 {
    match s.parse::<u32>() {
        Ok(count) => count * 2,
        Err(_) => return 0,
    }
}
```

Прямого аналога в C++ нет — ближе всего ранний `return` после проверки `if (!success) return ...;`, но без встроенной деструктуризации значения "успеха" в той же строке.

## `if let` / `while let` — `let` как условие

Отдельная форма, где `let`-паттерн используется как условие ветвления — очень частая идиома в Rust вместо `match` с одним значимым вариантом:

```rust
let maybe_value: Option<i32> = Some(5);

if let Some(x) = maybe_value {
    println!("Есть значение: {x}");
} else {
    println!("Пусто");
}
```

Это сахар для `match`, когда интересен только один паттерн:

```rust
match maybe_value {
    Some(x) => println!("Есть значение: {x}"),
    None => println!("Пусто"),
}
```

`while let` — то же самое, но в виде цикла, пока паттерн совпадает (классика — вычитывание из очереди/итератора):

```rust
let mut stack = vec![1, 2, 3];
while let Some(top) = stack.pop() {
    println!("{top}");
}
```

## `let` vs `const` vs `static` — три разных вещи, которые в C++ смешаны в одном `const`/`constexpr`

|Rust|Когда вычисляется|Мутабельность|Область видимости|C++ аналог|
|---|---|---|---|---|
|`let x = 5;`|В рантайме, при исполнении|опционально `mut`|локальная (block-scoped)|`auto x = 5;` / `int x = 5;`|
|`const X: i32 = 5;`|На этапе компиляции, всегда|никогда, инлайнится в каждое место использования|любая, в т.ч. глобальная|`constexpr int X = 5;`|
|`static X: i32 = 5;`|На этапе компиляции|обычно нет (мутабельный `static mut` — `unsafe`)|глобальная, фиксированный адрес в памяти на всю программу|`static const int X = 5;` (для глобальных)|

Важно: `const` в Rust — это не про "переменную только для чтения", как `const` в C++ (который применяется и к параметрам, и к методам, и к обычным переменным). Rust `const` — это буквально константа времени компиляции, которая **подставляется** в каждое место использования (нет фиксированного адреса в памяти), в то время как `static` — это ровно один объект на весь процесс с фиксированным адресом, ближе к глобальной `static`-переменной в C++.

## Сводная таблица `let`-related модификаторов

|Что пишешь|Что это даёт|
|---|---|
|`let x = v;`|неизменяемое связывание, move/copy из `v`|
|`let mut x = v;`|изменяемое связывание|
|`let ref x = v;`|`x` — ссылка на `v` (редко используется, обычно неявно через match ergonomics)|
|`let (a, b) = tuple;`|деструктуризация через паттерн|
|`let _ = v;`|явно проигнорировать значение (и, важно, сразу его уничтожить/drop)|
|`let _unused = v;`|связать, но подавить warning "unused variable", **не** уничтожая сразу (в отличие от `_`)|

Последняя строка — тонкий момент, который иногда ловит новичков: `let _ = mutex.lock();` **сразу дропает** guard (мьютекс тут же разблокируется), а `let _guard = mutex.lock();` держит его до конца области видимости. В C++ с RAII-объектом такой разницы синтаксически не возникает — там просто не назвал бы переменную, и время жизни временного объекта определяется концом полного выражения (temporary), что тоже неочевидно, но по другим причинам.
