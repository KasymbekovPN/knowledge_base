# Структура каталогов vcpkg

После клонирования и bootstrap в корне vcpkg появляется набор каталогов и файлов. Часть из них — исходные (приходят с репозиторием), часть генерируется при работе (установка пакетов, скачивание исходников). Разберём главное.

## Корневые файлы

```
vcpkg/
├── vcpkg(.exe)              ← исполняемый файл (появляется после bootstrap)
├── bootstrap-vcpkg.sh/.bat  ← скрипты сборки vcpkg
├── vcpkg.disable-metrics    ← (если создали) отключение телеметрии
├── .vcpkg-root              ← маркер: помечает корень установки vcpkg
└── README.md, LICENSE.txt   ← документация и лицензия
```

Файл `.vcpkg-root` — служебный маркер, по которому vcpkg и toolchain-файл понимают, что это корень установки. Удалять его нельзя.

## Ключевые каталоги

### `ports/`

Сердце vcpkg. Содержит **порты** — рецепты сборки для каждой библиотеки. Один подкаталог = одна библиотека.

```
ports/
├── fmt/
│   ├── portfile.cmake   ← инструкции: откуда взять и как собрать
│   └── vcpkg.json       ← метаданные: версия, зависимости, features
├── zlib/
├── boost/
└── ... (тысячи портов)
```

Когда вы пишете свои порты или патчите существующие, вы работаете именно здесь (или в overlay-каталоге вне репозитория).

### `triplets/`

Описания **триплетов** — целевых конфигураций (платформа + архитектура + тип линковки).

```
triplets/
├── x64-windows.cmake
├── x64-linux.cmake
├── arm64-osx.cmake
└── community/        ← менее распространённые триплеты
```

Каждый файл задаёт переменные: архитектуру, тип линковки (static/dynamic), CRT и т. д. Кастомные триплеты можно класть сюда или в отдельную overlay-папку.

### `installed/`

Сюда складываются **результаты установки** пакетов — собранные библиотеки и заголовки. Появляется после первой установки.

```
installed/
├── x64-windows/        ← по подкаталогу на каждый триплет
│   ├── include/        ← заголовочные файлы
│   ├── lib/            ← статические библиотеки / import-библиотеки
│   ├── bin/            ← .dll (для динамической линковки)
│   ├── debug/          ← debug-версии lib/bin
│   ├── share/          ← CMake-конфиги пакетов, метаданные
│   └── tools/          ← исполняемые утилиты, если порт их ставит
└── vcpkg/              ← служебная информация об установленном
```

Структура `include`/`lib`/`bin` — именно то, что `find_package` в CMake потом находит.

### `buildtrees/`

Временная рабочая область сборки. Для каждого собираемого порта здесь лежат распакованные исходники, конфигурация и логи компиляции.

```
buildtrees/
└── fmt/
    ├── src/                  ← распакованные исходники
    ├── x64-windows-rel/      ← release-сборка
    ├── x64-windows-dbg/      ← debug-сборка
    └── *.log                 ← логи (сюда смотреть при ошибках сборки!)
```

Когда установка падает — логи ошибок ищите именно тут. Каталог можно безопасно удалять для экономии места: vcpkg пересоздаст при необходимости.

### `downloads/`

Кэш скачанных исходников и инструментов (архивы релизов библиотек, скачанные CMake/Ninja и т. п.). Позволяет не качать одно и то же повторно.

```
downloads/
├── fmt-fmtlib-fmt-10.1.1.tar.gz
└── tools/        ← подтянутые инструменты (cmake, ninja, ...)
```

### `packages/`

Промежуточный «чистый» результат сборки порта перед тем, как он попадёт в `installed/`. Своего рода staging-область. Обычно туда заглядывать не нужно.

### `scripts/`

Внутренние скрипты vcpkg, включая самый важный для интеграции файл:

```
scripts/
└── buildsystems/
    └── vcpkg.cmake   ← тот самый CMAKE_TOOLCHAIN_FILE
```

Именно на `scripts/buildsystems/vcpkg.cmake` вы ссылаетесь в CMakePresets или через `-DCMAKE_TOOLCHAIN_FILE`.

### `versions/`

База данных версий портов — нужна для версионирования и baseline в manifest-режиме. Хранит, какие версии портов соответствуют каким git-коммитам.

### `docs/` (в репозитории) и `.git/`

Документация и git-метаданные репозитория.

## Сводная таблица

|Каталог|Что внутри|Трогать руками?|
|---|---|---|
|`ports/`|Рецепты сборки библиотек|Да, при создании/патче портов|
|`triplets/`|Целевые конфигурации|Да, для кастомных триплетов|
|`installed/`|Готовые libs и headers|Нет (управляется vcpkg)|
|`buildtrees/`|Временная сборка + **логи**|Смотреть логи; можно удалять|
|`downloads/`|Кэш скачанных исходников|Можно чистить|
|`packages/`|Staging перед installed|Нет|
|`scripts/`|Внутренние скрипты + **vcpkg.cmake**|Нет (но ссылаетесь на toolchain)|
|`versions/`|БД версий для baseline|Нет|

## Важное замечание про manifest-режим

В **classic-режиме** всё ставится глобально в `installed/` внутри самого vcpkg. В **manifest-режиме** (рекомендуемом) пакеты для конкретного проекта собираются в локальный каталог `vcpkg_installed/` **рядом с вашим проектом**, а не в корне vcpkg. Это изолирует зависимости одного проекта от другого:

```
my_project/
├── vcpkg.json
├── CMakeLists.txt
└── vcpkg_installed/      ← зависимости именно этого проекта
    └── x64-windows/
```

## Что стоит запомнить

Три каталога, к которым вы реально будете обращаться:

- **`ports/`** — когда работаете с рецептами библиотек,
- **`buildtrees/`** — когда что-то не собралось и нужны логи,
- **`scripts/buildsystems/vcpkg.cmake`** — путь, на который ссылается вся CMake-интеграция.

Остальное vcpkg обслуживает сам.
