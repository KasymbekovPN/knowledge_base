# Триплеты (triplets)

Триплет — одно из центральных понятий vcpkg. Если коротко: это описание целевой конфигурации, под которую собирается библиотека. Имя «триплет» исторически про три компонента (архитектура-платформа-...), но по сути это набор параметров сборки.

## Что задаёт триплет

Триплет определяет:

- **Архитектуру** — x64, x86, arm64 и т. д.
- **Целевую ОС/платформу** — windows, linux, osx, android, uwp...
- **Тип линковки** — статическая или динамическая.
- Дополнительно: тип линковки CRT (runtime), компилятор, флаги и прочее.

Имя триплета обычно читается как `<архитектура>-<платформа>[-модификатор]`:

```
x64-windows          ← x64, Windows, динамическая линковка (по умолчанию)
x64-windows-static    ← x64, Windows, статическая линковка
x86-windows
arm64-osx
x64-linux             ← на Linux линковка статическая по умолчанию для самих lib
arm64-android
```

## Зачем это нужно

Одна и та же библиотека может собираться по-разному в зависимости от того, куда вы её встраиваете. vcpkg позволяет держать рядом несколько вариантов одной библиотеки под разные триплеты — они не конфликтуют, потому что лежат в отдельных подкаталогах `installed/<триплет>/`.

```
installed/
├── x64-windows/         ← динамические версии
└── x64-windows-static/  ← статические версии
```

## Триплет по умолчанию

Для каждой платформы есть дефолтный триплет:

- Windows → `x64-windows`
- Linux → `x64-linux`
- macOS → `arm64-osx` или `x64-osx` (в зависимости от чипа)

Узнать и переопределить:

```bash
# посмотреть справку по триплетам
vcpkg help triplet

# установить под конкретный триплет (classic mode)
vcpkg install fmt:x64-windows-static

# задать дефолтный триплет переменной окружения
export VCPKG_DEFAULT_TRIPLET=x64-windows-static   # Linux/macOS
```

В CMake-интеграции триплет можно задать переменной `VCPKG_TARGET_TRIPLET`:

```bash
cmake -DVCPKG_TARGET_TRIPLET=x64-windows-static ...
```

## Статическая vs динамическая линковка

Это, пожалуй, самый практически важный аспект триплетов.

### Динамическая (dynamic) — `.dll` / `.so`

Библиотека компилируется в отдельный разделяемый файл, который подгружается во время выполнения.

- ✅ Меньше размер исполняемого файла.
- ✅ Можно обновить библиотеку без перекомпиляции программы.
- ✅ Несколько программ делят одну копию в памяти.
- ❌ Нужно распространять .dll/.so вместе с программой (проблема «забыли положить dll»).
- ❌ Возможен конфликт версий («DLL hell»).

### Статическая (static) — `.lib` / `.a`

Код библиотеки вшивается прямо в ваш исполняемый файл при сборке.

- ✅ Один самодостаточный исполняемый файл, ничего не нужно тащить рядом.
- ✅ Нет проблем с поиском/версиями библиотек во время запуска.
- ❌ Больше размер бинарника.
- ❌ Чтобы обновить библиотеку — нужно пересобрать программу.

### Нюанс Windows: линковка CRT

На Windows отдельно есть вопрос линковки **C runtime (CRT)** — динамически (`/MD`) или статически (`/MT`). По умолчанию:

- `x64-windows` → динамические библиотеки + динамический CRT.
- `x64-windows-static` → статические библиотеки + **статический** CRT.

Иногда нужен промежуточный вариант — статические библиотеки, но динамический CRT. Это решается кастомным триплетом (см. ниже) с `VCPKG_CRT_LINKAGE dynamic` и `VCPKG_LIBRARY_LINKAGE static`. Важно, чтобы линковка CRT совпадала с настройками вашего основного проекта, иначе будут ошибки линковки.

## Из чего состоит файл триплета

Триплеты — это `.cmake`-файлы в каталоге `triplets/`. Например, упрощённо `x64-windows`:

```cmake
set(VCPKG_TARGET_ARCHITECTURE x64)
set(VCPKG_CRT_LINKAGE dynamic)
set(VCPKG_LIBRARY_LINKAGE dynamic)
```

А `x64-windows-static`:

```cmake
set(VCPKG_TARGET_ARCHITECTURE x64)
set(VCPKG_CRT_LINKAGE static)
set(VCPKG_LIBRARY_LINKAGE static)
```

Ключевые переменные:

- `VCPKG_TARGET_ARCHITECTURE` — x86 / x64 / arm / arm64.
- `VCPKG_CRT_LINKAGE` — dynamic / static (Windows).
- `VCPKG_LIBRARY_LINKAGE` — dynamic / static.
- `VCPKG_CMAKE_SYSTEM_NAME` — целевая ОС (пусто для Windows, `Linux`, `Darwin`, `Android`...).
- `VCPKG_BUILD_TYPE` — можно ограничить сборку только release (`set(VCPKG_BUILD_TYPE release)`), чтобы не собирать debug и сэкономить время/место.

## Создание кастомного триплета

Делается, когда стандартные не подходят — например, нужны статические библиотеки с динамическим CRT, или только release-сборка, или специфические флаги компилятора.

Шаги:

1. Создайте отдельный каталог под overlay-триплеты (вне репозитория vcpkg, чтобы не терять при обновлениях):

```
my-project/
└── custom-triplets/
    └── x64-windows-static-md.cmake
```

2. Опишите конфигурацию, например «статические библиотеки + динамический CRT + только release»:

```cmake
set(VCPKG_TARGET_ARCHITECTURE x64)
set(VCPKG_CRT_LINKAGE dynamic)
set(VCPKG_LIBRARY_LINKAGE static)
set(VCPKG_BUILD_TYPE release)
```

3. Укажите путь к overlay-триплетам при установке/конфигурации:

```bash
# classic mode
vcpkg install fmt:x64-windows-static-md \
  --overlay-triplets=./custom-triplets

# или через переменную окружения
export VCPKG_OVERLAY_TRIPLETS=./custom-triplets
```

В CMake это можно задать через `VCPKG_OVERLAY_TRIPLETS` в пресете.

> Примечание: `x64-windows-static-md` — это распространённый кастомный триплет (static libs + dynamic CRT), которого нет в дефолтном наборе, отсюда и потребность создавать свой.

## Практические советы

- **Не правьте встроенные триплеты в `triplets/`** — изменения потеряются при `git pull`. Используйте overlay-триплеты в своём проекте.
- **Линковка должна быть согласованной** во всём проекте: и библиотеки, и ваш код, и CRT. Несовпадение → ошибки линковки на этапе сборки.
- **`VCPKG_BUILD_TYPE release`** заметно ускоряет установку и экономит место, если debug-версии библиотек вам не нужны.
- В manifest-режиме триплет обычно задаётся в `CMakePresets.json` через `VCPKG_TARGET_TRIPLET`, а overlay-триплеты — через `VCPKG_OVERLAY_TRIPLETS`, так конфигурация переносится вместе с проектом.

## Что запомнить

Триплет = «под что и как собрать библиотеку»: архитектура + платформа + тип линковки. Главный практический выбор — **static vs dynamic** (и на Windows ещё линковка CRT). Стандартных триплетов хватает в большинстве случаев; кастомные нужны для нестандартных комбинаций, и их правильно держать как overlay в своём проекте, а не править встроенные.
