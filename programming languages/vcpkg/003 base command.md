# Базовые команды vcpkg

Это набор команд, который покрывает повседневную работу: найти библиотеку, установить, посмотреть установленное, удалить, обновить. Большинство примеров — для classic-режима; в конце отмечу, как это меняется в manifest-режиме.

## `search` — найти библиотеку

Ищет порт по имени или ключевому слову в названии и описании.

```bash
vcpkg search fmt
vcpkg search json      # покажет все порты, где встречается "json"
vcpkg search           # без аргумента — весь список портов
```

Вывод содержит имя порта, доступную версию и краткое описание. Это первый шаг — убедиться, что нужная библиотека вообще есть в реестре, и узнать её точное имя.

Полезно знать про **features** (опциональные компоненты порта) — они показываются в выводе в квадратных скобках, например `boost[...]`.

## `install` — установить пакет

Скачивает исходники, собирает и кладёт результат в `installed/`.

```bash
vcpkg install fmt
vcpkg install fmt zlib curl           # сразу несколько
vcpkg install fmt:x64-windows         # под конкретный триплет
vcpkg install "curl[ssl]"             # с включённой feature
```

Указание триплета через двоеточие (`пакет:триплет`) переопределяет триплет по умолчанию. Без него используется дефолтный для вашей платформы (например, `x64-windows`, `x64-linux`).

Несколько важных моментов:

- Зависимости подтянутся и соберутся автоматически.
- Первая установка крупной библиотеки (вроде boost) может занять много времени — идёт сборка из исходников.
- При ошибке смотрите логи в `buildtrees/<порт>/`.

## `list` — что установлено

Показывает установленные пакеты и их версии.

```bash
vcpkg list
vcpkg list fmt          # отфильтровать по имени
```

В выводе видны имя, триплет, версия и установленные features. Удобно проверить, под какие триплеты что собрано.

## `remove` — удалить пакет

```bash
vcpkg remove fmt
vcpkg remove fmt:x64-windows          # конкретный триплет
vcpkg remove --recurse fmt            # вместе с зависимыми пакетами
```

Если пакет нужен другим установленным пакетам как зависимость, vcpkg предупредит и потребует `--recurse`, чтобы удалить всю связанную цепочку. Без флага он не даст сломать зависимости.

Полезный вариант — удалить «осиротевшие» пакеты, которые больше никому не нужны:

```bash
vcpkg remove --outdated      # см. ниже про update/upgrade
```

## `update` — проверить устаревшие пакеты

Показывает, какие из установленных пакетов отстают от версий в текущем реестре. Сама ничего не пересобирает — только сообщает.

```bash
vcpkg update
```

Вывод — список пакетов в формате «было → стало». Чтобы версии в реестре поменялись, нужно сначала обновить сам репозиторий vcpkg:

```bash
cd $VCPKG_ROOT
git pull
```

Реестр портов — это и есть git-репозиторий vcpkg, поэтому свежие версии библиотек приходят с `git pull`.

## `upgrade` — пересобрать устаревшие

Команда-компаньон к `update`: реально обновляет (пересобирает) устаревшие пакеты.

```bash
vcpkg upgrade            # показывает план (dry-run по умолчанию)
vcpkg upgrade --no-dry-run   # выполняет обновление
```

По умолчанию `upgrade` только показывает, что будет сделано. Флаг `--no-dry-run` запускает фактическую пересборку.

## Общий цикл обновления в classic-режиме

```bash
cd $VCPKG_ROOT
git pull                       # обновили реестр портов
vcpkg update                   # посмотрели, что устарело
vcpkg upgrade --no-dry-run     # пересобрали устаревшее
```

## Вспомогательные команды

Несколько команд, которые пригодятся:

- **`vcpkg version`** — версия самого vcpkg.
- **`vcpkg help`** / **`vcpkg help <команда>`** — встроенная справка по командам и темам (например, `vcpkg help triplet`).
- **`vcpkg integrate install`** — глобальная интеграция с Visual Studio/MSBuild (classic-режим).
- **`vcpkg integrate remove`** — убрать эту интеграцию.
- **`vcpkg export fmt zlib --zip`** — выгрузить установленные пакеты в переносимый архив (удобно для передачи на другую машину без пересборки).
- **`vcpkg depend-info <порт>`** — показать дерево зависимостей порта.

## Важно: как это меняется в manifest-режиме

В manifest-режиме (рекомендуемом) команды `install` / `remove` / `upgrade` для управления зависимостями вы **почти не используете напрямую**. Вместо этого:

- Зависимости описываются в файле `vcpkg.json` рядом с проектом.
- Установка происходит **автоматически при конфигурации CMake** — vcpkg читает манифест и ставит всё в локальный `vcpkg_installed/`.
- Чтобы добавить/убрать библиотеку, вы редактируете `vcpkg.json`, а не вызываете `install`.

Команда `vcpkg install` без аргументов в каталоге с манифестом установит всё, что в нём перечислено:

```bash
vcpkg install      # ставит зависимости из vcpkg.json в текущей папке
```

При этом `search`, `list`, `version`, `help`, `depend-info` остаются полезными в обоих режимах.

## Сводная таблица

|Команда|Назначение|
|---|---|
|`search`|Найти порт|
|`install`|Установить пакет(ы)|
|`list`|Показать установленное|
|`remove`|Удалить пакет|
|`update`|Показать устаревшие|
|`upgrade`|Пересобрать устаревшие|
|`export`|Выгрузить пакеты в архив|
|`depend-info`|Дерево зависимостей|
|`integrate`|Интеграция с MSBuild/VS|
|`version` / `help`|Версия и справка|

## Что запомнить

В classic-режиме вы управляете пакетами вручную через `install`/`remove`/`upgrade`. В manifest-режиме почти всё сводится к редактированию `vcpkg.json` и автоматической установке при сборке. `search` и `list` полезны всегда.
