# CRT (C Runtime) — подробный разбор

Тема линковки CRT — частый источник загадочных ошибок линковки в C++ на Windows, поэтому в неё стоит вникнуть. Сразу оговорюсь: **CRT в этом контексте — преимущественно тема Windows / MSVC**. На Linux и macOS вопрос линковки рантайма стоит иначе и обычно не доставляет проблем. Поэтому дальше речь в основном про Windows.

## Что такое CRT

**CRT (C Runtime Library)** — это стандартная библиотека времени выполнения, которая реализует базовые вещи, без которых не работает ни одна C/C++ программа:

- функции стандартной библиотеки C: `malloc`/`free`, `printf`, `memcpy`, `strlen`, математика и т. д.;
- запуск программы до `main`: инициализация, разбор аргументов, настройка окружения;
- поддержку C++ поверх этого: работа `new`/`delete`, раскрутку стека при исключениях, вызовы конструкторов глобальных объектов;
- завершение программы, вызов деструкторов, очистку.

То есть CRT — это «подложка», которую компилятор неявно подключает к любому вашему бинарнику. Вопрос лишь в том, **как** она подключается.

## Два способа линковки CRT (MSVC)

На Windows с компилятором MSVC есть выбор: вшить CRT в бинарник статически или подключать как DLL во время выполнения. Это управляется флагами компилятора `/MT` и `/MD`.

### Динамический CRT — `/MD` (и `/MDd` для debug)

CRT подключается как набор системных DLL (`vcruntime140.dll`, `msvcp140.dll`, `ucrtbase.dll` и др.). Эти библиотеки загружаются при запуске программы.

- ✅ Меньше размер исполняемого файла.
- ✅ Обновления/исправления CRT приходят с системой, без пересборки программы.
- ✅ Все модули процесса делят **одну** копию рантайма (это важно — см. ниже).
- ❌ Нужно, чтобы на машине пользователя был установлен соответствующий **Visual C++ Redistributable**, иначе программа не запустится («не найден vcruntime140.dll»).

Это вариант **по умолчанию** в Visual Studio и в триплете `x64-windows`.

### Статический CRT — `/MT` (и `/MTd` для debug)

Код CRT вшивается прямо в ваш исполняемый файл.

- ✅ Самодостаточный бинарник — не нужен установленный Redistributable.
- ✅ Проще распространять как один файл.
- ❌ Больше размер бинарника.
- ❌ Каждый модуль несёт свою копию рантайма (источник проблем при смешивании — см. ниже).
- ❌ Исправления CRT требуют пересборки программы.

Это вариант триплета `x64-windows-static`.

## Debug vs Release вариант CRT

К каждому варианту добавляется debug-версия:

|Флаг|Что значит|
|---|---|
|`/MD`|Динамический CRT, release|
|`/MDd`|Динамический CRT, debug|
|`/MT`|Статический CRT, release|
|`/MTd`|Статический CRT, debug|

Debug-CRT (`/MDd`, `/MTd`) содержит дополнительные проверки, отладочные «магические» значения в памяти, диагностику кучи. **Смешивать debug и release CRT в одном бинарнике нельзя** — отсюда и правило «debug-сборка проекта линкуется с debug-зависимостями, release — с release».

## Почему это вообще важно: главное правило

> **Линковка CRT должна быть одинаковой у всех частей, которые попадают в один исполняемый файл/процесс: у вашего кода и у всех библиотек, с которыми вы линкуетесь.**

Если ваш проект собран с `/MD`, а библиотека из vcpkg — с `/MT` (или наоборот), вы получите:

- ошибки линковки вида `LNK2038: mismatch detected for 'RuntimeLibrary'`;
- предупреждения о дублировании символов (`LNK4098: defaultlib 'MSVCRT' conflicts...`);
- либо, что хуже, программу, которая собирается, но падает в рантайме.

### Откуда берётся падение в рантайме

Самый коварный случай — когда **разные модули имеют каждый свою копию CRT** (например, при статическом CRT в нескольких DLL). Тогда каждая копия CRT держит **свою собственную кучу**. Если память выделена `malloc`/`new` в одном модуле, а освобождается `free`/`delete` в другом — освобождение идёт не в той куче, которая выделяла. Результат — повреждение кучи и краш.

То же касается передачи через границу модулей: указателей `FILE*`, локали, `errno`, C++ исключений, стандартных контейнеров. Всё это завязано на конкретный экземпляр CRT.

Вывод: смешивать линковки CRT нельзя не из формализма, а потому что это ломает управление памятью и состоянием.

## Как это связано с триплетами vcpkg

В файле триплета за CRT отвечает переменная `VCPKG_CRT_LINKAGE`, а за тип самой библиотеки — `VCPKG_LIBRARY_LINKAGE`. Это **две независимые оси**:

|Триплет|LIBRARY_LINKAGE|CRT_LINKAGE|Аналог флага|
|---|---|---|---|
|`x64-windows`|dynamic (.dll)|dynamic|`/MD`|
|`x64-windows-static`|static (.lib)|static|`/MT`|
|`x64-windows-static-md` (кастомный)|static (.lib)|dynamic|`/MD`|

Обратите внимание на третью строку: тип линковки библиотеки и тип линковки CRT **не обязаны совпадать**. Можно иметь статические библиотеки (`.lib`, всё вшито в exe, ничего не таскать рядом), но при этом динамический CRT (зависимость от Redistributable). Это очень популярная комбинация — отсюда и распространённый кастомный триплет `x64-windows-static-md`.

Файл такого кастомного триплета:

```cmake
set(VCPKG_TARGET_ARCHITECTURE x64)
set(VCPKG_CRT_LINKAGE dynamic)      # CRT как DLL → /MD
set(VCPKG_LIBRARY_LINKAGE static)   # сами библиотеки статические → .lib
```

## Как согласовать CRT между vcpkg и вашим проектом

Ключевой момент: триплет vcpkg должен соответствовать тому, как ваш собственный проект линкует CRT.

### Если используете static-триплет (`/MT`)

Ваш CMake-проект тоже должен собираться с `/MT`. В современном CMake это делается через свойство `MSVC_RUNTIME_LIBRARY`:

```cmake
cmake_minimum_required(VERSION 3.15)
set(CMAKE_MSVC_RUNTIME_LIBRARY "MultiThreaded$<$<CONFIG:Debug>:Debug>")
```

Значения свойства:

- `MultiThreadedDLL` → `/MD` (динамический CRT, release)
- `MultiThreaded` → `/MT` (статический CRT, release)
- с суффиксом `DLLDebug`/`Debug` — соответствующие debug-варианты, обычно через генераторное выражение `$<$<CONFIG:Debug>:...>`.

### Если используете дефолтный `x64-windows` (`/MD`)

Тогда обычно ничего специально настраивать не нужно — `/MD` и так стоит по умолчанию в MSVC-сборках.

## Практический чек-лист

- Решите заранее: динамический CRT (`/MD`, нужен Redistributable у пользователя) или статический (`/MT`, самодостаточный exe).
- Выберите соответствующий **триплет vcpkg** под это решение.
- Убедитесь, что **ваш проект** линкует CRT так же (`CMAKE_MSVC_RUNTIME_LIBRARY`).
- Debug-конфигурация проекта → debug-CRT; release → release-CRT. Не смешивать.
- Увидели `LNK2038 ... RuntimeLibrary` — это почти всегда именно рассинхрон CRT между вашим кодом и библиотекой.

## А что на Linux/macOS

Там нет деления `/MD` vs `/MT`. На Linux есть похожий по духу вопрос со статической/динамической линковкой `libstdc++`/`libc` (флаги вроде `-static-libstdc++`, `-static-libgcc`), но `glibc` статически линковать обычно не рекомендуют, и в повседневной работе с vcpkg это почти не доставляет хлопот. Поэтому переменная `VCPKG_CRT_LINKAGE` практически значима именно для Windows-триплетов.

## Что запомнить

CRT — обязательная подложка рантайма для любой C/C++ программы. На Windows её можно линковать динамически (`/MD`, зависимость от Redistributable, общая копия рантайма) или статически (`/MT`, самодостаточный бинарник, своя копия рантайма у каждого модуля). Главное правило — **линковка CRT должна совпадать у вашего кода и у всех библиотек vcpkg в одном бинарнике**, иначе ошибки линковки или повреждение кучи в рантайме. В vcpkg это управляется через `VCPKG_CRT_LINKAGE`, независимо от `VCPKG_LIBRARY_LINKAGE`, а ваш проект синхронизируется свойством `CMAKE_MSVC_RUNTIME_LIBRARY`.
