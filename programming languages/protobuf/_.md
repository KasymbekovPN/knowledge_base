# Protobuf

Protocol Buffers (protobuf) — это разработанный Google механизм сериализации структурированных данных: язык описания схемы плюс генератор кода для многих языков (C++, Java, Python, Go, C# и др.).

Работает так: вы описываете структуру данных в .proto-файле — сообщения (message) с типизированными полями, каждое поле пронумеровано. Из этого файла компилятор protoc генерирует код для нужного языка, который умеет сериализовать объекты в компактный бинарный формат и обратно.

Ключевые плюсы по сравнению с JSON/XML:

- бинарный формат намного компактнее и быстрее парсится;
- строгая типизация и явная схема — данные всегда валидны по контракту;
- обратная/прямая совместимость — можно добавлять новые поля, не ломая старых клиентов, благодаря нумерации полей;
- одна схема — код для многих языков, удобно для взаимодействия сервисов на разных стеках.

Чаще всего protobuf используют вместе с gRPC для описания API между микросервисами, а также для хранения конфигов, логов и любых межпроцессных данных, где важны скорость и компактность.

# Аналоги

**FlatBuffers** (тоже от Google) — похож на protobuf, но данные читаются без парсинга/десериализации, прямо из буфера. Быстрее для чтения, но многословнее в использовании и генерируемом коде.

**Cap'n Proto** — тоже с нулевым копированием при чтении (zero-copy), считается ещё быстрее FlatBuffers. Меньше распространён.

**Apache Thrift** — от Facebook, похож на protobuf + gRPC в одном: своя IDL, генерация кода и встроенный RPC-фреймворк. Исторически популярен в экосистеме Hadoop.

**Apache Avro** — популярен в Big Data (Kafka, Hadoop). Схема хранится вместе с данными или в отдельном реестре (schema registry), не встраивается в сгенерированный код так жёстко.

**MessagePack, CBOR, BSON** — бинарные форматы без строгой схемы, ближе к JSON по духу, но компактнее. Проще в использовании, но без строгой типизации и валидации на уровне схемы.

**JSON / XML** — текстовые форматы, не бинарные, но остаются дефолтным выбором там, где важна читаемость и простота отладки важнее производительности.

Protobuf при этом остаётся самым распространённым выбором для gRPC и микросервисов благодаря зрелой экосистеме и хорошей поддержке эволюции схемы.
