[[programming languages/protobuf/_|<=]]

Wire-формат — это конкретная бинарная кодировка, в которую protobuf превращает сообщение при сериализации. Это низкоуровневое представление байтов, которое передаётся по сети или пишется в файл.

**Структура: tag-length-value (TLV)**

Каждое непустое поле в сериализованном сообщении кодируется как:

```
[tag][value]  (для varint, fixed32, fixed64)
[tag][length][value]  (для length-delimited: string, bytes, вложенные сообщения)
```

Tag — это один varint, в котором закодированы сразу два числа: номер поля и wire type. Формула: `tag = (номер_поля << 3) | wire_type`.

**Wire types (всего 6, актуальны 5)**

|Код|Тип|Используется для|
|---|---|---|
|0|Varint|int32, int64, uint32, uint64, sint32, sint64, bool, enum|
|1|64-bit|fixed64, sfixed64, double|
|2|Length-delimited|string, bytes, вложенные message, repeated (packed)|
|5|32-bit|fixed32, sfixed32, float|

**Varint — ключевая идея кодирования чисел**

Числа кодируются переменным числом байт: в каждом байте 7 бит данных и 1 старший бит-флаг "есть продолжение". Маленькие числа (0-127) занимают 1 байт, большие — больше. Это и даёт компактность для типичных данных (id, счётчики, флаги — обычно небольшие числа).

**Пример разбора**

Сообщение `message User { int32 id = 1; string name = 2; }` с `id=1, name="Al"` сериализуется примерно так:

```
08 01          // tag=0x08 → номер поля 1, wire_type 0 (varint) → значение 1
12 02 41 6C    // tag=0x12 → номер поля 2, wire_type 2 (length-delimited) → длина 2, байты "Al"
```

`0x08 = (1 << 3) | 0`, `0x12 = (2 << 3) | 2` — отсюда видно, как номер поля и тип зашиты прямо в первый байт каждого поля.

**Почему это важно на практике**

- Если поле не установлено (значение по умолчанию в proto3), оно вообще не пишется в байты — экономия места.
- Парсер читает tag, по нему узнаёт номер поля и как его декодировать, независимо от порядка полей в файле.
- Неизвестные tag'и (поле, которого нет в текущей схеме) парсер просто пропускает по wire_type и length — отсюда прямая совместимость: старый код может прочитать сообщение, отправленное новой схемой с добавленными полями.
