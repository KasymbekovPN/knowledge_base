## Базовая иерархия классов

В основе всего лежит шаблон `basic_ios` и его специализации. Ключевые классы:

```
ios_base
   └── basic_ios<charT>
          ├── basic_istream<charT>   (ввод)
          ├── basic_ostream<charT>   (вывод)
          └── basic_iostream<charT>  (оба, через множественное наследование)
```

Для `char` существуют привычные typedef'ы: `istream`, `ostream`, `iostream`. Для `wchar_t` — `wistream`, `wostream` и т.д.

Принципиальный момент: сами потоки **не работают с устройством напрямую**. Они делегируют это объекту `streambuf` (буфер). Поток отвечает за форматирование (преобразование `int` в текст и обратно), а буфер — за фактическую передачу байтов к источнику/приёмнику. Это разделение и позволяет одним и тем же кодом работать с консолью, файлом или сокетом.

## Консоль

Глобальные объекты определены в `<iostream>`

`cout` и `cin` синхронизированы с C-потоками (`stdio`) по умолчанию. Если нужна производительность и вы не смешиваете `printf`/`cout`:

```cpp
std::ios_base::sync_with_stdio(false);
std::cin.tie(nullptr);  // отвязать cin от cout (убрать автосброс)
```

```cpp
#include <iostream>

int main() {
    int x{};
    std::cin >> x; // ввод с форматированием
    std::cout << "value: " << x << "\n"; // буферизованный вывод
    std::cerr << "Error!\n"; // небуферизованный (unitbuf)
    std::clog << "Log message\n"; // буферизованный вывод ошибок

    return 0;
}
```

```
1
value: 1
Error!
Log message
```

## Файлы

В `<fstream>` живут `ifstream`, `ofstream`, `fstream`. Они наследуют тот же интерфейс, но привязывают `filebuf` к файлу

Флаги открытия комбинируются через `|`: `ios::in`, `ios::out`, `ios::app` (дозапись), `ios::trunc`, `ios::binary`, `ios::ate` (позиция в конце при открытии).

```cpp
#include <iostream>
#include <format>
#include <fstream>

int main() {
    const std::string PATH{"data.txt"};
    std::ofstream out{PATH};
    if (out) {
        out << 42 << ' ' << 3.14 << '\n';
        out.close();

        int n;
        double d;
        std::ifstream in(PATH);
        in >> n >> d;
        std::cout << std::format("n = {}, d = {}", n, d);
    } else {
        std::cout << "Failure to attempt of file creation\n";
    };

    std::ofstream bin("data.bin", std::ios::binary);
    int value = 0xDEADBEEF;
    bin.write(reinterpret_cast<const char*>(&value), sizeof(value));

    return 0;
}
```

```
n = 42, d = 3.14
```

## Сокеты — здесь начинается самое интересное

Вот ключевой момент: **в стандартной библиотеке C++ нет потоковых классов для сокетов.** Сокет — это файловый дескриптор ОС, и стандарт его не абстрагирует. Поэтому есть несколько подходов:

**1. Свой `streambuf`.** Поскольку вся магия полиморфизма потоков заключена в `streambuf`, можно написать класс, наследующий `std::streambuf`, который в методах `overflow()` (вывод) и `underflow()` (ввод) вызывает `send()`/`recv()` на дескрипторе сокета. Затем подсунуть его в обычный `iostream`:

```cpp
class socketbuf : public std::streambuf {
    int fd_;
    char inbuf_[1024], outbuf_[1024];
protected:
    int_type underflow() override {
        ssize_t n = ::recv(fd_, inbuf_, sizeof(inbuf_), 0);
        if (n <= 0) return traits_type::eof();
        setg(inbuf_, inbuf_, inbuf_ + n);
        return traits_type::to_int_type(*inbuf_);
    }
    int_type overflow(int_type c) override {
        // накопить в outbuf_ и при заполнении вызвать send()
        // ...
        return c;
    }
    // нужен ещё sync() для flush
};

// Использование:
socketbuf buf(client_fd);
std::iostream sock(&buf);
sock << "GET / HTTP/1.1\r\n";
std::string line;
std::getline(sock, line);
```

Это «правильный» способ по духу стандартной библиотеки, но реализовать корректный `streambuf` с учётом putback, частичных записей и обработки ошибок неочевидно.

**2. GNU-специфичное расширение.** В libstdc++ есть `__gnu_cxx::stdio_filebuf`, позволяющий обернуть существующий дескриптор:

```cpp
#include <ext/stdio_filebuf.h>
__gnu_cxx::stdio_filebuf<char> sb(sockfd, std::ios::in | std::ios::out);
std::iostream stream(&sb);
```

Непортируемо, но быстро.

**3. Готовые библиотеки.** Boost.Asio — стандарт де-факто для сетевого I/O. Там есть `boost::asio::ip::tcp::iostream`, который даёт тот самый потоковый интерфейс над TCP-сокетом:

```cpp
boost::asio::ip::tcp::iostream stream("example.com", "80");
stream << "GET / HTTP/1.0\r\n\r\n";
```

## Что стоит изучить дальше

Чтобы понимать всё это глубоко, я бы выстроил такой порядок:

Сначала разберитесь с **состоянием потока** — флаги `goodbit`/`eofbit`/`failbit`/`badbit`, как их проверять (`if (stream)`, `.fail()`, `.clear()`), потому что без этого надёжный ввод не написать. Затем **манипуляторы и форматирование** (`std::setw`, `std::hex`, `std::setprecision` из `<iomanip>`, а в C++20+ — `std::format` как современная альтернатива). И в самом конце — **`streambuf`** как механизм, объясняющий, почему всё это работает единообразно: когда поймёте, что поток это лишь форматирующая обёртка над буфером, абстракция перестанет быть магией.

С какой стороны хотите зайти — со стороны практики (написать что-то рабочее, например, свой `socketbuf`) или со стороны теории (детально разобрать иерархию и состояние потоков)? Могу углубиться в любую часть.

Вот структурированный план изучения, выстроенный от фундамента к продвинутым темам.

## Этап 1. Состояние потока (фундамент надёжности)

Без этого любой ввод хрупок, поэтому начинать стоит отсюда.

Разберите четыре бита состояния: `goodbit`, `eofbit`, `failbit`, `badbit` — что каждый означает и при каких операциях выставляется. Научитесь их проверять: контекстное преобразование `if (stream)`, методы `.good()`, `.eof()`, `.fail()`, `.bad()`. Освойте сброс состояния через `.clear()` и понимание, зачем он нужен после неудачного чтения. Отдельно — типичный паттерн цикла чтения `while (stream >> x)` и почему он корректно завершается. Практика: написать функцию, которая читает числа до конца ввода и устойчиво обрабатывает мусор во входных данных (нечисловой символ → очистка `failbit` + `ignore`).

## Этап 2. Форматирование и манипуляторы

Здесь поток превращается из «трубы для байтов» в инструмент представления данных.

Изучите флаги форматирования через `ios_base` и удобные манипуляторы из `<iomanip>`: ширина поля `setw`, заполнитель `setfill`, выравнивание `left`/`right`/`internal`, системы счисления `hex`/`oct`/`dec`, `showbase`, точность вещественных `setprecision` в связке с `fixed`/`scientific`. Поймите разницу между «липкими» (sticky) флагами и одноразовым `setw`. Затем перейдите к современной альтернативе — `std::format` (C++20) и `std::print` (C++23): это будущее форматирования в C++, синтаксис в духе Python, типобезопасный и быстрый. Практика: вывести таблицу чисел с выровненными колонками сначала через манипуляторы, потом через `std::format` — сравнить читаемость.

## Этап 3. `streambuf` — механизм, объясняющий всё

Кульминация: здесь становится понятно, почему консоль, файл и сокет работают одним кодом.

Разберите разделение ответственности: поток форматирует, буфер передаёт байты. Изучите внутреннюю модель буфера — указатели области получения (`eback`, `gptr`, `egptr`) и области отправки (`pbase`, `pptr`, `epptr`). Освойте ключевые виртуальные методы для переопределения: `underflow()` (буфер ввода опустел — дочитать), `overflow()` (буфер вывода заполнен — сбросить), `sync()` (flush). Поймите механику putback (возврат символа во ввод). Полезные приёмы: перенаправление потока через `rdbuf()` (например, временно направить `cout` в файл), связывание потоков через `tie()`. Практика: реализовать минимальный `streambuf` — например, оборачивающий `std::vector<char>` в памяти, а затем (как развитие) тот самый `socketbuf` из прошлого ответа.

## Сквозные темы

Параллельно держите в голове два вопроса, которые связывают этапы: **производительность** (`sync_with_stdio`, буферизация, `endl` против `'\n'`) и **обработка ошибок** (когда поток бросает исключения — `exceptions()` — против тихого выставления битов).
