[[programming languages/cpp/coroutine/_|<=]]

**Кооперативная многозадачность** — это модель, в которой задачи переключаются только тогда, когда сами добровольно уступают управление. Никто не может прервать задачу принудительно — она работает, пока в явной точке не скажет «я подожду здесь, передаю управление дальше».

В корутинах такими точками являются `co_await`, `co_yield`, `co_return`. Между ними корутина выполняется монопольно.

## Вытеснение (preemption)

**Потоки — вытесняющая модель.** Операционная система через планировщик может прервать любой поток в _произвольный_ момент — хоть посреди арифметической операции — и отдать процессор другому потоку. Поток не контролирует, когда его прервут, и даже не знает об этом.

**Корутины — кооперативная модель.** Переключение происходит только в заранее известных точках приостановки. Это даёт важное следствие:

```cpp
// Между двумя co_await эта корутина выполняется атомарно
// относительно других корутин на том же потоке.
counter++;          // \
process(counter);    //  > никто не вклинится в эту секцию
log(counter);        // /
co_await something;  // <- только здесь возможно переключение
```

Поэтому общие данные между корутинами одного потока часто не требуют мьютексов — гонок не возникает, ведь две корутины не выполняются одновременно. У потоков же доступ к общим данным нужно защищать (`std::mutex`, атомики), иначе будут гонки данных.

Обратная сторона: если корутина не уступает управление (тяжёлый цикл без `co_await`), она **блокирует все остальные** корутины на этом потоке. В кооперативной модели одна «жадная» задача может заморозить всё. Вытесняющая ОС такого не допустит — она сама отберёт процессор.

## Параллелизм

Это разные оси, которые легко спутать:

- **Конкурентность (concurrency)** — несколько задач _в работе_ одновременно, но не обязательно исполняются в один и тот же момент (переключаются на одном ядре).
- **Параллелизм (parallelism)** — несколько задач _физически исполняются_ в один момент на разных ядрах.

**Потоки дают настоящий параллелизм** — ОС может разложить их по разным ядрам, и они побегут буквально одновременно.

**Корутины сами по себе параллелизма не дают.** На одном потоке в каждый момент времени активна ровно одна корутина — это чистая конкурентность. Чтобы получить параллелизм, корутины запускают на пуле потоков.

## Стоимость переключения

Здесь разница огромна и это главная практическая причина использовать корутины.

**Переключение потока (context switch)** проходит через ядро ОС:

- переход в режим ядра (системный вызов)
- сохранение/восстановление полного контекста регистров
- работа планировщика ОС
- сброс кешей процессора и TLB
- порядок сотен–тысяч наносекунд

**Переключение корутины** — это просто сохранение состояния в её фрейме и переход к другой:

- никакого участия ОС, всё в пользовательском пространстве
- сохраняются только нужные переменные, а не весь регистровый контекст
- порядок десятков наносекунд

Плюс память: поток требует отдельного стека (обычно 1–8 МБ), поэтому тысячи потоков — это уже гигабайты. Корутина в C++ stackless — её состояние это небольшая структура (часто десятки–сотни байт), поэтому миллионы корутин реальны.

## Сводка

| |Потоки|Корутины|
|---|---|---|
|Переключение|Принудительное, в любой момент (ОС)|Добровольное, в точках `co_await`/`co_yield`|
|Управляет|Планировщик ОС (режим ядра)|Сама программа (пользовательское пространство)|
|Параллелизм|Да, на разных ядрах|Нет (только конкурентность)|
|Защита данных|Нужны мьютексы/атомики|Часто не нужны (на одном потоке)|
|Стоимость переключения|Высокая (сотни нс+)|Низкая (десятки нс)|
|Память на задачу|Стек 1–8 МБ|Десятки–сотни байт|
|Жадная задача|ОС прервёт|Заблокирует остальных|

## Аналогия

**Вытесняющая модель (потоки)** — офис, где начальник (ОС) с таймером ходит между работниками и каждые несколько секунд командует «стоп, переключись на другое». Работники не договариваются — за них решает начальник.

**Кооперативная модель (корутины)** — работники без начальника, которые сами говорят: «я сейчас жду ответа по почте, пока займусь этим — коллега, поработай ты». Переключение дешёвое (не нужно звать начальника), но если один работник упрётся в задачу и забудет уступить — все остальные будут ждать его.
