**Различие в одном предложении:** stackful-корутина имеет собственный полноценный стек (как у потока), а stackless-корутина хранит своё состояние в небольшом объекте фиксированного размера и стек вызывающей стороны не сохраняет.

## Stackful корутины

У такой корутины есть выделенный стек — отдельный участок памяти под её кадры вызовов. Это значит, что приостановиться она может **из любого места своего дерева вызовов**, на любой глубине вложенности.

```cpp
// Псевдокод stackful-модели
void deep() {
    yield();          // приостановка прямо здесь — ОК
}
void middle() { deep(); }
void coroutine() { middle(); }   // yield сработает, хотя он
                                 // в функции на 2 уровня глубже
```

Когда такая корутина приостанавливается, сохраняется весь её стек целиком — со всеми промежуточными кадрами `coroutine → middle → deep`. При возобновлении стек восстанавливается, и выполнение продолжается ровно с того места.

Примеры: Boost.Coroutine, корутины в Go (горутины), ucontext/fibers.

**Плюс:** приостановка прозрачна — обычные функции, вызванные из корутины, могут её приостановить, ничего не зная о том, что они внутри корутины.

**Минус:** нужно заранее выделить стек под каждую корутину. Слишком большой — расход памяти (теряется преимущество над потоками), слишком маленький — риск переполнения. Переключение тяжелее, чем у stackless.

## Stackless корутины (выбор C++)

Состояние корутины — это **один объект (coroutine frame)** фиксированного размера, известного на этапе компиляции. В него компилятор кладёт только то, что нужно сохранить между точками приостановки: локальные переменные, аргументы, точку возобновления.

Ключевое ограничение: приостановиться можно **только из самой корутины**, а не из вложенных обычных функций.

```cpp
void deep() {
    co_await x;   // ОШИБКА: co_await нельзя из обычной функции
}

Task coroutine() {
    co_await x;   // ОК — только в теле самой корутины
}
```

Чтобы «приостановиться через вложенность», вложенная функция тоже должна быть корутиной, и её результат нужно явно ожидать: `co_await deep();`. Приостановка не прозрачна — она «заразна», она видна в сигнатуре и теле.

**Плюс:** очень дёшево. Размер фрейма точно подобран компилятором, нет избыточного стека, переключение — это смена нескольких указателей. Возможна даже оптимизация HALO, когда аллокация фрейма вообще убирается.

**Минус:** «функциональная окраска» — приостанавливающаяся функция и весь путь до неё должны быть корутинами; нельзя приостановиться из произвольной точки.

## Сравнение

| |Stackful|Stackless (C++)|
|---|---|---|
|Состояние|Полный отдельный стек|Один объект фикс. размера|
|Размер|Заранее заданный стек (КБ–МБ)|Минимальный, вычислен компилятором|
|Приостановка из вложенных функций|Да, прозрачно|Нет, только из самой корутины|
|«Заразность» (окраска функций)|Нет|Да|
|Стоимость переключения|Выше|Ниже|
|Аллокация|Стек на каждую корутину|Часто elided (HALO)|

## Почему C++ выбрал stackless

**1. Философия «не платишь за то, что не используешь».** Размер фрейма вычисляется компилятором ровно под нужды конкретной корутины. Не нужно угадывать размер стека и резервировать память «с запасом», как в stackful.

**2. Эффективность.** Stackless даёт минимальные накладные расходы по памяти и времени переключения — это критично для сценариев с миллионами одновременных корутин (сетевые серверы). Stackful с его стеком на каждую корутину масштабируется хуже.

**3. Оптимизируемость (HALO).** Поскольку размер фрейма известен компилятору, в ряде случаев аллокацию в куче можно полностью устранить — фрейм размещается в кадре вызывающей стороны. Со stackful такое невозможно: отдельный стек должен существовать всегда.

**4. Не требует ассемблера и переносимость.** Stackful-переключение стеков обычно реализуется платформенно-зависимым ассемблерным кодом (сохранение указателя стека и регистров). Stackless — это трансформация, которую делает компилятор в виде обычного кода, без платформенной магии. Это лучше переносится и дружелюбнее к оптимизатору.

**5. Интеграция с системой типов.** «Заразность» — обратная сторона того, что асинхронность видна в типах (`Task<T>`, `Generator<T>`). Компилятор знает о точках приостановки и может встраивать вокруг них логику (awaiter'ы, symmetric transfer).

**Компромисс, который приняли:** отказались от прозрачности и удобства (приостановка из любой глубины) в пользу производительности, контроля над памятью и оптимизируемости. Это согласуется с общим духом C++ — давать низкоуровневый, эффективный механизм, поверх которого библиотеки строят удобные абстракции.

Стоит отметить, что stackful-корутины в C++ доступны через библиотеки (Boost.Coroutine2, Boost.Fiber) — язык не запрещает их, но в _стандарт_ на уровне ключевых слов вошла именно stackless-модель.
