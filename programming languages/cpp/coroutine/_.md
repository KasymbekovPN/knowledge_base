[[_cpp|<=]]

Корутины в C++ (с C++20) — это функции, которые могут приостанавливать своё выполнение и возобновлять его позже, сохраняя состояние.

**Признак корутины** — наличие в теле функции одного из ключевых слов:

- `co_await` — приостановка до готовности значения
- `co_yield` — возврат значения с приостановкой (генераторы)
- `co_return` — завершение корутины с возвратом значения

**Ключевые механизмы:**

`promise_type` — обязательный тип, описывающий поведение корутины (что делать при старте, завершении, исключении, при `co_return`/`co_yield`). Компилятор ищет его через `std::coroutine_traits`.

`std::coroutine_handle<>` — дескриптор для управления корутиной (возобновление `.resume()`, проверка завершения `.done()`, уничтожение `.destroy()`).

**Awaitable / Awaiter** — объекты, с которыми работает `co_await`. Реализуют три метода:

- `await_ready()` — нужно ли приостанавливаться
- `await_suspend()` — что делать при приостановке
- `await_resume()` — результат при возобновлении

Готовые `std::suspend_always` и `std::suspend_never` — стандартные awaiter'ы.

**Особенности:**

- Стандарт даёт только низкоуровневую инфраструктуру — готовых типов (генераторов, задач) почти нет. `std::generator` появился только в C++23.
- Часто используют сторонние библиотеки: cppcoro, Boost.Asio, libunifex.
- Применение: асинхронный код (вместо колбэков), ленивые генераторы, конвейеры обработки данных.

Корутина и поток решают похожую задачу — выполнение нескольких «потоков логики» — но устроены принципиально по-разному.

**Главное отличие: вытесняющая vs кооперативная многозадачность**

Поток (thread) управляется операционной системой, которая может прервать его выполнение в любой момент (вытеснение). Корутина приостанавливается только сама, в явных точках (`co_await`, `co_yield`) — это кооперативная модель.

**Параллелизм vs конкурентность**

Потоки могут выполняться по-настоящему параллельно на разных ядрах процессора. Корутины сами по себе параллелизма не дают — это механизм конкурентности (переключение задач), а не параллельного исполнения. На одном потоке в любой момент времени активна ровно одна корутина.

**Стоимость и ресурсы**

|              | Корутина                               | Поток                        |
| ------------ | -------------------------------------- | ---------------------------- |
| Стек         | Нет отдельного стека (stackless в C++) | Свой стек, обычно 1–8 МБ     |
| Создание     | Дёшево (аллокация состояния)           | Дорого (системный вызов)     |
| Переключение | Дёшево (без участия ОС)                | Дорого (context switch ядра) |
| Количество   | Миллионы реальны                       | Тысячи — уже много           |

**Синхронизация**

Поскольку корутины на одном потоке не выполняются одновременно, между точками приостановки данные защищены автоматически — мьютексы часто не нужны. Потоки требуют синхронизации (`std::mutex`, атомики) для общих данных, иначе возникают гонки.

**Когда что использовать**

Потоки — для CPU-bound задач, где нужно загрузить несколько ядер (параллельные вычисления).

Корутины — для I/O-bound задач с большим числом одновременных операций (сетевые серверы, асинхронный ввод-вывод), где потоки простаивали бы в ожидании и тратили память.

**На практике их комбинируют:** пул из нескольких потоков (по числу ядер), и на каждом потоке крутятся тысячи корутин. Так работают современные асинхронные рантаймы — например, Boost.Asio.

Аналогия: поток — это отдельный работник, которого начальник (ОС) может в любой момент переключить на другую задачу. Корутина — один работник, который сам решает отложить дело, пока ждёт ответа, и взяться за следующее.
