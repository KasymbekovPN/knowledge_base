## Что такое coroutine_handle

`std::coroutine_handle` — это лёгкая обёртка (по сути типизированный указатель) на coroutine frame. Через неё внешний код управляет приостановленной корутиной: возобновляет, проверяет состояние, уничтожает, добирается до промиса.

Два варианта:

```cpp
std::coroutine_handle<promise_type>   // типизированный — есть доступ к промису
std::coroutine_handle<>               // стёртый тип (= coroutine_handle<void>)
                                      // умеет только resume/done/destroy
```

Типизированный неявно конвертируется в стёртый. Стёртый удобен там, где конкретный промис не важен — например, при хранении «кого возобновить» (continuation), как было в symmetric transfer.

Важно: handle **не владеет** frame. Это как сырой указатель — копирование handle не копирует корутину, а уничтожение handle не уничтожает frame. Владением (вызовом `destroy()`) управляешь ты вручную, обычно через RAII-обёртку (`Task`/`Generator`).

## Основные методы

## resume()

```cpp
h.resume();   // эквивалент: h()  — у handle есть operator()
```

Возобновляет приостановленную корутину — выполнение продолжается с точки последней приостановки до следующей (или до конца). **Синхронный** вызов: возвращается, только когда корутина снова приостановится или завершится. В выводе видно, как каждый `resume()` прогоняет тело от одного `co_yield` до следующего (`step A` → `step B` → `step C`).

Предусловие: вызывать `resume()` можно только на _приостановленной_ корутине. Вызов на завершённой (`done() == true`) или выполняющейся — UB.

## done()

```cpp
bool finished = h.done();
```

Возвращает `true`, если корутина приостановлена в **финальной точке** (`final_suspend`), то есть тело отработало полностью. До этого — `false`. В выводе: `false` пока идут `co_yield`, и `true` после третьего `resume`, когда тело дошло до конца.

Тонкость: `done()` корректно вызывать только на приостановленной корутине. Именно `done()` используют как условие цикла перебора (`while (!h.done())`), как делал `next()` в генераторе.

## promise()

```cpp
promise_type& p = h.promise();   // доступен только у типизированного handle
int v = p.value;
```

Даёт ссылку на промис внутри frame. Через него внешний код читает результаты, которые корутина положила в промис (`value`, `current`, сохранённое исключение). Доступен **только** у `coroutine_handle<promise_type>`, не у стёртого `coroutine_handle<>` — стёртый не знает тип промиса.

## destroy()

```cpp
h.destroy();   // освобождает coroutine frame
```

Уничтожает корутину: вызывает деструкторы её локальных переменных и освобождает память frame. После этого handle становится невалидным — любое обращение к нему UB. В примере я его не вызываю вручную: это делает `~Demo`. Двойной `destroy()` (или `destroy()` + повторный в деструкторе) — double-free, поэтому владение должно быть единственным (вспомни `std::exchange` в move-конструкторе).

## from_promise()

```cpp
auto h = std::coroutine_handle<promise_type>::from_promise(promise_ref);
```

Восстанавливает handle по ссылке на промис. Это «обратное направление»: промис лежит внутри frame, и по нему вычисляется адрес всего frame. Именно так `get_return_object` создаёт handle изнутри промиса — мы видели это в каждом примере.

## address() / from_address()

```cpp
void* addr = h.address();                          // handle -> сырой void*
auto h2 = coroutine_handle<P>::from_address(addr); // void* -> handle обратно
```

Превращает handle в сырой указатель и обратно. Нужно для хранения handle в C-style API, передачи через `void*`-контексты (часто в интеграции с C-библиотеками асинхронного I/O). В выводе `h2 == h` подтверждает, что round-trip даёт тот же frame. Сравнение handle (`==`) сравнивает именно адреса frame.

## Сводка

|Метод|Назначение|На каком handle|
|---|---|---|
|`resume()` / `operator()`|возобновить приостановленную корутину|любой|
|`done()`|завершена ли (в `final_suspend`)|любой|
|`destroy()`|уничтожить frame|любой|
|`promise()`|доступ к промису|только типизированный|
|`from_promise(p)`|handle из ссылки на промис|только типизированный|
|`address()`|handle → `void*`|любой|
|`from_address(p)`|`void*` → handle|любой|
|`std::noop_coroutine()`|handle-заглушка («ничего не делать»)|стёртый|

## Ключевые предостережения

**Handle не владеет frame.** Копия handle — это второй указатель на ту же корутину, а не вторая корутина. Уничтожать frame должен ровно один владелец.

**Состояния и UB.** На каждом методе есть предусловия: `resume()`/`done()`/`promise()` валидны на приостановленной корутине; после `destroy()` или для пустого handle обращения — UB. Поэтому handle оборачивают в RAII-тип, который следит за временем жизни.

**`std::noop_coroutine()`** — особый handle, возобновление которого ничего не делает. Мы использовали его в `final_suspend` композиции `Task` как «возобновить никого», когда continuation отсутствует.
