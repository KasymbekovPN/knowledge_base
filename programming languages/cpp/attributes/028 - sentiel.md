[[programming languages/cpp/attributes/_|<=]]

`__attribute__((sentinel))` — для variadic-функций (переменное число аргументов через `...`), требует, чтобы последним переданным аргументом в каждом вызове был `NULL` (используется как терминатор списка аргументов — типичный C-паттерн для функций вроде `execl`, `execlp` из POSIX API). Компилятор статически проверяет вызовы, где это видно (`-Wformat`-подобная диагностика), и предупреждает, если сентинел забыт.

```cpp
__attribute__((sentinel))
void processArgs(const char* first, ...);

int main() {
    processArgs("a", "b", "c", nullptr);  // ok — есть терминатор
    processArgs("a", "b", "c");           // warning: missing sentinel in function call
}
```

По умолчанию (`sentinel` без аргумента, эквивалент `sentinel(0)`) требуется, чтобы `NULL` был самым последним аргументом. Число в скобках задаёт, на какой позиции с конца должен быть терминатор, если после него по соглашению API идёт ещё что-то (редкий случай, но встречается):

```cpp
// sentinel(1) — NULL должен быть предпоследним, последний аргумент — что-то другое
__attribute__((sentinel(1)))
void processArgsWithFlag(const char* first, ...);

processArgsWithFlag("a", "b", nullptr, 42);  // ok
```

Реальный пример из стандартной библиотеки C — сигнатура `execl`:

```c
int execl(const char *path, const char *arg, ... /* NULL-terminated */);
```

glibc помечает такие функции `sentinel` во внутренних заголовках именно для этой цели — забытый `NULL` в конце списка аргументов `execl` (частая ошибка) без атрибута приводит к чтению мусора со стека как продолжения списка аргументов (реальный, часто встречающийся security-баг), а с атрибутом компилятор ловит это на этапе компиляции, если терминатор виден статически.

Нюансы:

- В C++ вместо этого паттерна обычно используют `std::initializer_list`, вариативные шаблоны (`template<typename... Args>`) или `std::span`/`std::vector` — они типобезопасны и не требуют ручного NULL-терминатора вообще, поэтому `sentinel` в современном C++ коде почти не встречается за пределами обёрток над C-API.
- Как и `format`/`nonnull`, это статическая проверка компилятора для вызовов, где терминатор виден на этапе компиляции — если `NULL` передаётся через переменную, значение которой неизвестно статически, атрибут ничего не гарантирует в рантайме, это не runtime-assert.
- Специфично для GCC/Clang, стандартного `[[...]]`-аналога и MSVC-эквивалента нет.
