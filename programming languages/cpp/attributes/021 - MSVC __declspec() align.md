[[programming languages/cpp/attributes/_|<=]]

`__declspec(align(N))` — MSVC-аналог `__attribute__((aligned(N)))`: задаёт выравнивание переменной, поля или типа по границе `N` байт (`N` — степень двойки, от 1 до 8192 в зависимости от версии MSVC). Как и с `dllexport`/`visibility`, с появлением C++11 в большинстве случаев его место занял стандартный `alignas(N)`, но у `__declspec(align)` были и остаются свои нюансы, специфичные именно для MSVC/Windows ABI.

```cpp
__declspec(align(16)) struct Vec4 {
    float x, y, z, w;
};

alignas(16) struct Vec4Standard {   // современный переносимый эквивалент
    float x, y, z, w;
};

__declspec(align(64)) int counter;   // выравнивание под cache line, избежать false sharing
```

Специфичные для MSVC нюансы:

- **Стек и `__declspec(align)` до x64.** На 32-битной цели (x86) старые версии MSVC гарантировали выравнивание стека только по 4/8 байт; `__declspec(align(16))` для локальной переменной на стеке мог не соблюдаться корректно в некоторых сценариях (в частности, при исключениях/`alloca`) — известная историческая проблема, из-за которой MSVC-код для SSE (16-байтовое выравнивание) иногда выносил такие переменные в кучу. На x64 ABI выравнивание стека по 16 байт гарантировано изначально, проблема практически не актуальна.
- **Динамическое выделение памяти не уважает `__declspec(align)` само по себе.** `new Vec4[]` или `malloc` не гарантируют выравнивание по `N`, если оно больше стандартного (`alignof(std::max_align_t)`, обычно 16). Раньше для этого использовали `_aligned_malloc`/`_aligned_free` (MSVC-специфичные), сейчас — стандартные `operator new` с выравниванием (C++17, `std::align_val_t`) или `std::aligned_alloc`, которые одинаково работают везде.
- **Максимальное значение ограничено** (историческое ограничение MSVC — раньше 8192 байт), тогда как `alignas`/GCC `aligned` в принципе позволяют указывать любые степени двойки, поддерживаемые платформой.
- **На указатель/ссылку `__declspec(align)` не применяется так, как ожидается** — влияет на выравнивание самого объекта, а не на то, куда он указывает; та же логика, что и у `alignas`, просто стоит явно упомянуть, так как путаница случается часто.

Практический вывод: в новом кроссплатформенном C++ коде `__declspec(align)` использовать почти никогда не нужно — `alignas(N)` из C++11 делает то же самое переносимо между MSVC, GCC и Clang. `__declspec(align)` актуален только для старого кода до C++11 или для MSVC-специфичных приёмов (например, некоторых внутренних выравниваний, которые до сих пор завязаны на конкретное поведение MSVC-линкера).
