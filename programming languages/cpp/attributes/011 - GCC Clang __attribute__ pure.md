[[programming languages/cpp/attributes/_|<=]]

`__attribute__((pure))` (`[[gnu::pure]]`) — помечает функцию как не имеющую побочных эффектов (не меняет глобальное/статическое состояние, не пишет в память через указатели), но при этом результат может зависеть от состояния памяти — то есть от аргументов и от того, что лежит в памяти, доступной через указатели/глобальные переменные. Компилятор использует это, чтобы объединять повторные вызовы с одинаковыми аргументами (CSE — common subexpression elimination) или выносить вызов из цикла, если аргументы не меняются, — но не может кэшировать результат "навечно", потому что глобальное состояние между вызовами может измениться.

```cpp
#include <iostream>  
  
namespace {  
  
    int counter{};  
  
    __attribute__((pure))  
    int badExample() {  
        // это pure — читает состояние, но не меняет его  
        return counter;  
    }  
    
    __attribute__((pure))  
    int stringLength(const char* s) {  
        int len{};  
        // читает из памяти по указателю — не "const", но "pure"  
        while (s[len]) ++len;  
  
        return len;  
    }  
    
    void loop(const char* s) {  
        for (int i{}; i < stringLength(s); ++i) {  
            // без pure компилятор обязан пересчитывать stringLength(s) каждую итерацию  
            // с pure — может вынести вызов за пределы цикла, если знает, что s не меняется            
            std::cout << s[i];  
        }        
        std::cout << std::endl;  
    }
}  
  
int main() {  
    constexpr auto line{"Hello"};  
    loop(line);  
  
    std::cout << badExample() << std::endl;  
  
    return 0;  
}
```

Ключевое отличие от `const`: `pure`-функция может читать память (глобальные переменные, данные по указателям), а `const`-функция — не может читать вообще ничего, кроме своих аргументов по значению. Если функция помечена `pure`, но на самом деле меняет глобальное состояние или пишет в память по указателю — это UB, компилятор может выкинуть "лишние", по его мнению, вызовы, что приведёт к неожиданному поведению программы.
