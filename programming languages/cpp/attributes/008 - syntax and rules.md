[[programming languages/cpp/attributes/_|<=]]

Атрибуты в C++ пишутся как `[[...]]` и могут стоять в разных позициях в зависимости от того, к чему они относятся (в стандарте это называется "appertain to"):

**Перед объявлением** — применяется к целой сущности (функции, переменной, классу):

```cpp
[[nodiscard]] int compute();
[[deprecated]] void oldFunc();
```

**После имени в объявлении переменной/параметра** — тоже допустимо и иногда обязательно для параметров:

```cpp
void f(int x [[maybe_unused]]);
int y [[maybe_unused]];
```

**Перед классом/структурой, после `struct`/`class`, до имени** — для атрибутов класса:

```cpp
struct [[nodiscard]] ErrorCode { int value; };
class [[deprecated]] OldWidget { };
```

**На типе** (после спецификатора типа, реже используется) — влияет на сам тип, а не на объявление:

```cpp
[[deprecated]] typedef int OldInt;
using NewInt [[deprecated]] = int;
```

**На statement** (как отдельный "оператор") — `[[fallthrough]]`, `[[likely]]`/`[[unlikely]]`, `[[assume]]` ставятся не на объявление, а на целый оператор или пустой statement:

```cpp
if (cond) [[likely]] { ... }
case 1: [[fallthrough]];
```

Важно: не любой атрибут можно ставить куда угодно — каждый атрибут стандарт жёстко привязывает к конкретным конструкциям (`[[noreturn]]` — только на функцию, `[[fallthrough]]` — только на пустой statement перед `case`/`default`, и т.п.), отсюда и ошибки вроде той, что была с `fallthrough` выше.

**Namespace-атрибуты (`vendor::attr`).** Компилятор-специфичные атрибуты, оформленные в стандартном синтаксисе `[[...]]`, но с префиксом-неймспейсом, чтобы не конфликтовать со стандартными и между собой:

```cpp
[[gnu::always_inline]] void f();          // GCC/Clang-аналог __attribute__((always_inline))
[[gnu::pure]] int g(int x);
[[msvc::no_unique_address]] Empty e;      // MSVC-специфичная версия no_unique_address
[[clang::annotate("custom_tag")]] void h();
```

Это позволяет писать компилятор-специфичные вещи в стандартном синтаксисе `[[]]`, а не через отдельные `__attribute__(())` / `__declspec()`, что удобнее для кроссплатформенного кода — синтаксический парсер один и тот же, различается только смысл конкретного атрибута.

**Игнорирование неизвестных атрибутов.** Ключевое свойство именно `[[...]]`-атрибутов (в отличие от `__attribute__` и `__declspec`): если компилятор не знает атрибут (или не знает vendor-неймспейс), он обязан молча его проигнорировать, а не выдать ошибку компиляции. Это гарантировано стандартом, поэтому такой код переносим:

```cpp
[[gnu::hot]] void hotPath();   // на MSVC просто игнорируется, компилируется без ошибки
```

На практике компиляторы могут выдать _предупреждение_ о неизвестном атрибуте (например, Clang с `-Wunknown-attributes`), но это не ошибка и не останавливает компиляцию — именно это отличает стандартные атрибуты от старых компилятор-специфичных расширений типа `__attribute__`, где неизвестный атрибут у другого компилятора — это synax error, и приходится оборачивать в `#ifdef`.
