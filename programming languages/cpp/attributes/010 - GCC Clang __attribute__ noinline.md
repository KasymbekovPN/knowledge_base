[[programming languages/cpp/attributes/_|<=]]

`__attribute__((noinline))` (эквивалент `[[gnu::noinline]]`) — запрещает компилятору инлайнить функцию, даже если обычная эвристика решила бы, что инлайнинг выгоден (например, маленькая функция, вызываемая один раз). Полезен в нескольких сценариях:

```cpp
#include <format>  
#include <format>  
#include <iostream>  
#include <format>  
  
namespace {  
    __attribute__((noinline))  
    void logError(const int code) {  
        std::cout << std::format("code: {}\n", code);  
    }
  
    __attribute__((noinline))  
    void handleError(const int code) {  
        // редкий "холодный" путь — не хотим раздувать icache горячего кода  
        logError(code);  
        std::abort();  
    }  

    [[gnu::noinline]]  
    void debugBreakpoint(const int value) {  
        // нужна отдельная функция для удобной постановки breakpoint / видимости в стеке  
        std::cout << std::format("bp: {}\n", value);  
    }
}  
  
int main() {  
    debugBreakpoint(42);  
    handleError(-42);  
  
    return 0;  
}
```

Основные причины использовать:

- **Разделение горячего и холодного пути.** Если обработка ошибок инлайнится в основную функцию, она раздувает код, который постоянно грузится в icache, даже если сама ветка обработки ошибки почти никогда не выполняется. `noinline` (часто вместе с `[[unlikely]]` или `__attribute__((cold))`) держит её отдельно.
- **Отладка и профилирование.** Заинлайненная функция не видна как отдельный кадр в стектрейсе/профайлере — `noinline` сохраняет её видимой для gdb/perf/valgrind.
- **Бенчмаркинг.** Чтобы измерить именно вызов функции, а не то, что компилятор её заинлайнил и оптимизировал целиком (частый паттерн вместе с `volatile`/`benchmark::DoNotOptimize`).
- **ABI-границы.** Функции, которые должны остаться реальными символами (например, для динамической линковки, интерпозиции, weak-символов), не должны исчезать через инлайнинг.

Есть родственный атрибут `__attribute__((cold))` — не запрещает инлайнинг напрямую, но подсказывает компилятору, что функция вызывается редко, и он может сам решить не инлайнить её и разместить в отдельной секции кода (аналог `[[unlikely]]`, но на уровне всей функции, а не одной ветки).
