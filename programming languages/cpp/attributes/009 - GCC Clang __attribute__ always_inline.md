[[programming languages/cpp/attributes/_|<=]]

`__attribute__((always_inline))` — GCC/Clang-специфичный атрибут (эквивалент `[[gnu::always_inline]]`), который заставляет компилятор инлайнить функцию практически всегда, даже если обычная эвристика инлайнинга (основанная на размере функции, флагах оптимизации и т.п.) решила бы этого не делать. В отличие от ключевого слова `inline` в C++, которое влияет в первую очередь на ODR (разрешает множественные определения в разных единицах трансляции) и лишь слабо подсказывает компилятору насчёт инлайнинга, `always_inline` — это жёсткое требование.

```cpp
#include <format>  
#include <iostream>  
#include <format>  
  
__attribute__((always_inline))  
inline int square(const int x) { return x * x; }  
  
// кроссплатформенный вариант, стандартный синтаксис  
[[gnu::always_inline]]  
inline int cube(const int x) { return x * square(x); }  
  
int main() {  
    std::cout << std::format("sqr: {}\n", square(42));  
    std::cout << std::format("cude: {}\n", cube(42));  
  
    return 0;  
}
```

Нюансы:

- Работает только при `-O1` и выше — на `-O0` GCC/Clang обычно всё равно не инлайнят (хотя формально пытаются, но с оговорками; на практике на `-O0` эффект может не проявиться в отладочной сборке).
- Функция всё равно должна быть технически инлайнируемой — например, нельзя заинлайнить рекурсивную функцию без ограничения глубины, или функцию с `va_list` в некоторых случаях; компилятор выдаст ошибку/warning, если инлайнинг невозможен, а не просто проигнорирует атрибут.
- Обратный атрибут — `__attribute__((noinline))` (`[[gnu::noinline]]`) — наоборот, запрещает инлайнинг; полезен для функций с обработкой редких ошибок ("холодный" путь), которые не должны раздувать icache горячего пути, или при отладке/профилировании, чтобы функция была видна как отдельный кадр стека.
- Злоупотребление `always_inline` может ухудшить производительность (раздувание кода, промахи icache) — используется точечно, обычно в низкоуровневых библиотеках (intrinsics-обёртки, hot-path в критичных по производительности местах), а не как общая практика.
