`__attribute__((packed))` (`[[gnu::packed]]`) — убирает выравнивание (padding) полей структуры/union, размещая их в памяти вплотную друг к другу, без обычных отступов, которые компилятор добавляет для соблюдения alignment-требований каждого типа. Экономит память, но за счёт возможного unaligned access, что на некоторых архитектурах медленнее (лишние инструкции для чтения) или вообще запрещено (падение с bus error на некоторых ARM/старых процессорах, если не сгенерирован специальный код).

```cpp
#include <format>  
#include <iostream>  
#include <format>  
  
namespace {  
  
    struct Normal {  
        // 1 байт + 3 padding  
        char a;  
        // 4 байта  
        int b;  
        // 1 байт + 3 padding  
        char c;  
    };  

    struct __attribute__((__packed__)) Packed {  
        // 1 байт  
        char a;  
        // 4 байта  
        int b;  
        // 1 байт  
        char c;  
    };  
}  
  
int main() {  
    std::cout << std::format("Normal: {}\n", sizeof(Normal));  
    std::cout << std::format("Packed: {}\n", sizeof(Packed));  
  
    return 0;  
}
```

Типичные случаи использования:

- **Бинарные протоколы / форматы файлов**, где нужен точный layout структуры "как на проводе" (сетевые пакеты, файловые заголовки), без лишних байт от компилятора.
- **Memory-mapped регистры устройств** во embedded, где важен точный офсет каждого поля.
- **Экономия памяти** при огромных массивах маленьких структур (жертвуя скоростью доступа).

Осторожности:

- Доступ к невыровненному полю (`b` в примере выше) может быть медленнее (на x86 обычно просто работает, но с накладными расходами) или требовать особой обработки на других архитектурах — компилятор обычно сам генерирует корректный, но менее эффективный код доступа.
- Взятие адреса невыровненного поля и передача его туда, где ожидается выровненный указатель (например, `reinterpret_cast<int*>(&packed.b)` и разыменование напрямую, а не через сам объект) — UB и может реально упасть на строгих архитектурах.
- Не путать с `#pragma pack(n)` (MSVC-стиль, тоже работает в GCC/Clang) — тот задаёт конкретное выравнивание в байтах, а не полностью убирает его; `packed` эквивалентен `pack(1)`.
- Стандартного `[[...]]`-аналога у `packed` нет — это полностью компилятор-специфичная вещь, критичная для layout'а данных, и для MSVC нужен отдельный путь через `#pragma pack`.
