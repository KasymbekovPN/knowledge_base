[[programming languages/cpp/idioms/_|<=]]

**RAII** (англ. *Resource Acquisition Is Initialization*, рус. **Получение ресурсов — это инициализация**) — это **фундаментальный принцип проектирования в C++**, согласно которому управление ресурсами (память, файлы, мьютексы, сокеты и т.д.) привязывается к **жизненному циклу объекта**.

> ✅ Суть:  
> - **Получение ресурса** происходит в **конструкторе**,  
> - **Освобождение ресурса** — в **деструкторе**.

Таким образом, ресурс автоматически освобождается, когда объект выходит из области видимости — даже при выбросе исключения.

| Проблема | Решение |
|--------|--------|
| Утечки памяти, файлов, дескрипторов | RAII гарантирует освобождение |
| Исключения могут нарушить логику `free()` / `close()` | Деструктор вызывается всегда |
| Сложный контроль за ресурсами в больших функциях | Код становится проще и безопаснее |

### Что считается "ресурсом"?

| Ресурс        | Пример RAII-обёртки                               |
| ------------- | ------------------------------------------------- |
| Память        | `std::unique_ptr`, `std::shared_ptr`              |
| Файлы         | `std::ifstream`, `std::ofstream`                  |
| Мьютексы      | `std::lock_guard`, `std::unique_lock`             |
| Сокеты        | Пользовательские классы (например, `SocketGuard`) |
| GUI-ресурсы   | Хэндлы окон, контексты рисования                  |
| БД-соединения |                                                   |

### Как работает RAII под капотом?

```cpp
{
    Resource res; // 1. Конструктор: захват ресурса
    // ... работа ...
}               // 2. Выход из области видимости → вызов деструктора → освобождение
```

> 💡 Это работает благодаря **гарантии вызова деструктора** для локальных объектов.


### Преимущества RAII

| Плюс                        | Объяснение                                                    |
| --------------------------- | ------------------------------------------------------------- |
| **Безопасность исключений** | Ресурсы освобождаются даже при `throw`                        |
| **Отсутствие утечек**       | Нет необходимости вручную вызывать `delete`, `close()` и т.д. |
| **Чистый код**              | Нет "шумных" строк вроде `if (error) { free(); return; }`     |
| **Идиоматичный C++**        | Так пишут профессионалы                                       |

### RAII vs try-finally (в других языках)

В **Java**/**Python**:

```python
f = open("file.txt")
try:
    f.write("data")
finally:
    f.close()  # Явное освобождение
```

В **C++** с RAII:

```cpp
std::ofstream f("file.txt");
f << "data"; // ← close() вызывается автоматически
```

> ✅ RAII делает код **короче и безопаснее**.

### Лучшая практика

| Совет                                                    | Почему                               |
| -------------------------------------------------------- | ------------------------------------ |
| Всегда используйте умные указатели вместо `new`/`delete` | Предотвращает утечки                 |
| Используйте `std::lock_guard` для мьютексов              | Безопасно и просто                   |
| Пишите свои RAII-обёртки для ресурсов                    | Например, `FileHandle`, `TimerGuard` |
| Избегайте `malloc`/`free` в современном C++              | Есть лучше альтернативы              |
| Комбинируйте RAII с move-семантикой                      | Эффективно и безопасно               |

| Функция | `lock_guard` | `unique_lock` | `shared_lock` |
|--------|--------------|---------------|----------------|
| Автоматическая блокировка | ✅ | ✅ | ✅ |
| Может быть разблокирована вручную | ❌ | ✅ | ✅ (`unlock()`) |
| Поддерживает `defer_lock` | ❌ | ✅ | ✅ |
| Поддерживает `try_lock` | ❌ | ✅ | ✅ |
| Можно передавать в функцию | ❌ | ✅ | ✅ |
| Поддерживает `std::condition_variable` | ❌ | ✅ | ❌ |
| Для `shared_mutex` (чтение) | ❌ | ✅ | ✅ |
| Производительность | ⚡ Самая высокая | Высокая | Высокая |
