[[programming languages/cpp/idioms/_|<=]]

**Named Constructor Idiom** — это паттерн проектирования на C++, который позволяет создавать **читаемые, безопасные и понятные альтернативы конструкторам**.

> ✅ Особенно полезно, когда:
> - Конструкторы с одинаковыми типами параметров неоднозначны,
> - Нужно выбрать логику создания по смыслу (например, "из радиуса" или "из диаметра"),
> - Вы хотите скрыть сложную инициализацию.

### Преимущества идиомы

| Плюс                          | Объяснение                                             |
| ----------------------------- | ------------------------------------------------------ |
| 🔹 **Читаемость**             | `Point::FromRadius(...)` понятнее, чем `Point(5.0)`    |
| 🔹 **Типовая безопасность**   | Исключает путаницу между `Point(1, 2)` и `Point(2, 1)` |
| 🔹 **Гибкость**               | Можно выполнять проверки, нормализацию, кэширование    |
| 🔹 **Контроль над созданием** | Например, объекты могут браться из пула                |

### Важные моменты

| Особенность                                        | Объяснение                                                       |
| -------------------------------------------------- | ---------------------------------------------------------------- |
| Конструкторы должны быть `private` или `protected` | Чтобы нельзя было создать напрямую                               |
| Методы `static` — точка входа                      | Часто возвращают `T`, `std::unique_ptr<T>`, `std::shared_ptr<T>` |
| Поддерживает move-семантику                        | Современные компиляторы оптимизируют `return`                    |
| Может использоваться с `friend`, если нужно        | Для тестов или расширений                                        |

### Альтернативы

| Подход                                    | Когда использовать                                  |
| ----------------------------------------- | --------------------------------------------------- |
| Перегрузка конструкторов                  | Если параметры отличаются по типу (`int`, `double`) |
| Шаблоны + теги (`struct cartesian_tag{}`) | Более продвинутый способ                            |
| Named Constructor Idiom                   | Когда важна **ясность кода** и **удобство API**     |

### Лучшая практика

| Совет                                                              | Почему                                |
| ------------------------------------------------------------------ | ------------------------------------- |
| Используйте `static` фабричные методы для сложных случаев          | Улучшает читаемость                   |
| Называйте методы понятно: `FromDegrees`, `WithTimeout`, `FromJSON` | Код сам документирует себя            |
| Возвращайте `T`, `std::unique_ptr<T>` или `std::optional<T>`       | По ситуации                           |
| Документируйте каждый "именованный конструктор"                    | Особенно если поведение нетривиальное |

```cpp
#include <iostream>
#include <cmath>

class Point {

private:
    double x, y;

    Point(double _x, double _y):
        x{_x},
        y{_y} {}

public:
    static Point Cartesian(double _x, double _y) {
        return Point(_x, _y);
    }

    static Point Polar(double _r, double _theta) {
        return Point(_r * cos(_theta), _r * sin(_theta));
    }

    void print() const {
        std::cout
            << "Point{"
            << x << ", "
            << y << "}"
            << std::endl;
    }
};

int main() {
    auto p0 = Point::Cartesian(3, 4);
    auto p1 = Point::Polar(5, 3.12159 / 4);

    p0.print();
    p1.print();

    return 0;
}
```
