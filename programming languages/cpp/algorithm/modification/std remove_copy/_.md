Функция `std::remove_copy` из заголовочного файла `<algorithm>` используется для **копирования элементов из одного диапазона в другой, исключая элементы, равные заданному значению**.

> ✅ В отличие от `std::remove`, которая модифицирует исходный контейнер,  
> `std::remove_copy` **создаёт новый контейнер с фильтрованными данными**, не изменяя оригинал.

## 🔍 Синтаксис

```cpp
#include <algorithm>

template<class InputIterator, class OutputIterator, class T>
OutputIterator remove_copy(InputIterator first, InputIterator last,
                           OutputIterator result,
                           const T& value);
```

- `first`, `last` — итераторы, задающие исходный диапазон `[first, last)`
- `result` — итератор на начало целевого контейнера
- `value` — значение, которое нужно исключить
- Возвращает: итератор на конец скопированной последовательности

## ⚠️ Важные моменты

| Особенность | Объяснение |
|-------------|------------|
| Не изменяет исходный диапазон | Создаёт новый |
| Работает за O(n) | Проверяет каждый элемент один раз |
| Требуется перегрузка `operator==` для пользовательских типов | Чтобы можно было сравнить элементы |
| Нужно использовать `std::back_inserter`, если цель пустая | Иначе может быть выход за границы |
| Подходит для работы с любыми итерируемыми структурами | Например, `std::vector`, `std::list`, `std::string` |

## ✅ Лучшая практика

| Совет | Почему |
|-------|--------|
| Используйте `std::remove_copy`, если нужно сохранить оригинал | Без лишних циклов |
| Используйте лямбду или функтор для гибкости | Особенно полезно с `std::remove_copy_if` |
| Комбинируйте с `std::back_inserter`, если цель пустая | Чтобы автоматически расширять контейнер |
| Избегайте `std::remove_copy` в больших циклах без оптимизации | Это O(n), может быть медленным |
| Проверяйте размер целевого буфера, если не используете `std::back_inserter` | Чтобы избежать выхода за границы |
