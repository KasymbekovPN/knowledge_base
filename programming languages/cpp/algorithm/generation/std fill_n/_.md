Функция `std::fill_n` из заголовочного файла `<algorithm>` используется для **записи одного и того же значения `n` раз, начиная с заданного итератора**.

> ✅ Это "ограниченная" версия `std::fill`, где вы указываете **не диапазон**, а **количество элементов**.

### Синтаксис

```cpp
#include <algorithm>

template<class OutputIterator, class Size, class T>
OutputIterator fill_n(OutputIterator first, Size count, const T& value);
```

- `first` — итератор, с которого начинается запись
- `count` — количество элементов для заполнения
- `value` — значение, которым заполняем
- Возвращает: `first + count`
- Подходит для любых `OutputIterator` — включая `std::back_inserter`

### Важные моменты

| Особенность                            | Объяснение                                              |
| -------------------------------------- | ------------------------------------------------------- |
| Не изменяет размер контейнера напрямую | Но `std::back_inserter` делает `push_back()`            |
| Работает за O(n)                       | Очень эффективно                                        |
| Может заполнять любые типы             | `int`, `double`, `std::string`, пользовательские классы |
| Подходит для любых `OutputIterator`    | Включая `std::ostream_iterator`, `std::front_inserter`  |
| Если `count < 0`, ничего не делает     | Безопасно                                               |

### Лучшая практика

| Совет                                                         | Почему                        |
| ------------------------------------------------------------- | ----------------------------- |
| Используйте `std::fill_n` с `std::back_inserter` для векторов | Удобно и безопасно            |
| Убедитесь, что `count >= 0`                                   | Хотя функция это проверяет    |
| Комбинируйте с `reserve()` при использовании `back_inserter`  | Эффективнее                   |
| Используйте `std::ostream_iterator` для вывода                | Красиво и компактно           |
| Избегайте `std::fill_n` в больших циклах без оптимизации      | Это O(n), может быть медленно |
