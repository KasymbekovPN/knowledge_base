# Модули C++: первые шаги

## Терминология

Прежде чем писать код, договоримся о словах — они будут встречаться постоянно.

**Модуль (module)** — это именованная единица кода со своим интерфейсом. Имя модуля (`math`, `app.utils`) — глобально уникальный идентификатор в программе. Точки в имени (`app.utils`) — просто часть имени для удобной группировки, никакой вложенности или иерархии они技нически не создают.

**Единица модуля (module unit)** — единица трансляции, которая принадлежит модулю. Их несколько видов, но сейчас нам важен главный:

**Интерфейсная единица модуля (module interface unit)** — файл, который объявляет модуль через `export module` и описывает его публичный интерфейс. Именно её «видят» те, кто делает `import`.

**BMI (Built Module Interface)** — бинарный скомпилированный интерфейс модуля. Когда вы компилируете интерфейсную единицу, компилятор создаёт этот файл. При `import` подключается именно он — уже разобранный, без текстовой подстановки. Это та самая «магия», ради которой всё затевалось.

## Три ключевых слова

Весь базовый синтаксис строится на трёх конструкциях:

- **`export module имя;`** — объявляет, что данный файл является интерфейсом модуля `имя`. Должна быть (почти) первой строкой файла.
- **`export`** — помечает сущность как часть публичного интерфейса: её будет видно снаружи.
- **`import имя;`** — подключает модуль, делая доступными все его экспортированные сущности.

## Hello, Module

Соберём минимальный рабочий пример из двух файлов.

**Файл `math.cppm`** (интерфейс модуля; расширение зависит от компилятора — об этом ниже):

```cpp
export module math;

int sum(int _a, int _b) {
    return _a + _b;
}

export int add(int _a, int _b) {
    return sum(_a, _b);
}
```

**Файл `main.cpp`** (потребитель модуля):

```cpp
// clang++ -std=c++23 --precompile math.cppm -o math.pcm
// clang++ -std=c++23 -x c++-system-header --precompile iostream -o iostream.pcm
// clang++ -std=c++23 -x c++-system-header --precompile format -o format.pcm
// clang++ -std=c++23 "-fmodule-file=math=math.pcm" "-fmodule-file=iostream=iostream.pcm" "-fmodule-file=format=format.pcm" demo.cpp math.pcm iostream.pcm format.pcm -o demo.exe

import math;

#include <iostream>
#include <format>

int main() {
    std::cout << std::format("result: {}\n", add(2, 3));

    return 0;
}
```

```
result: 5
```

Вот и всё — это полноценный модуль. Обратите внимание на три вещи, которые прямо отвечают на боли из прошлых тем:

**Видимость по умолчанию закрыта.** Функция `sum` без `export` невидима снаружи — это естественная инкапсуляция, без `static`-трюков и анонимных пространств имён. Сравните с заголовками, где наружу утекало всё.

**Никаких include guards.** Файл `math.cppm` можно «импортировать» из десяти разных мест — повторной вставки не происходит в принципе, потому что подключается готовый BMI, а не текст. Проблема двойного включения и ODR-часть-1 просто не существует.

**Определение прямо в интерфейсе.** Здесь `add` и объявлена, и определена в одном месте — не нужно дублировать сигнатуру между `.h` и `.cpp`.

## Как это компилируется

Важный момент, который отличает модули от заголовков: **порядок сборки теперь имеет значение**. Интерфейс модуля нужно скомпилировать **раньше**, чем файлы, которые его импортируют, — ведь `import math;` ищет готовый BMI.

Концептуально процесс такой:

```
math.ixx  ──компиляция──►  math BMI  +  math.o
                                │
main.cpp  ──компиляция──► (читает BMI) ──►  main.o
                                                │
                              math.o + main.o ──►  program
```

Команды зависят от компилятора. Для примера, на Clang это выглядит примерно так:

```bash
# 1. компилируем интерфейс модуля — получаем BMI и объектный файл
clang++ -std=c++20 --precompile math.ixx -o math.pcm
clang++ -std=c++20 -c math.ixx -o math.o

# 2. компилируем main, указывая, где искать BMI модуля
clang++ -std=c++20 -fmodule-file=math=math.pcm -c main.cpp -o main.o

# 3. линкуем
clang++ math.o main.o -o program
```

## Про расширения файлов

Единого стандарта на расширение интерфейсной единицы **нет** — стандарт C++ его не фиксирует. Сложились такие соглашения:

|Компилятор|Типичное расширение интерфейса|
|---|---|
|MSVC|`.ixx`|
|Clang|`.cppm`|
|GCC|обычный `.cpp` (вид определяется по содержимому)|

Многие проекты и CMake тяготеют к `.ixx` или `.cppm` как к наиболее явным. Файлы реализации и потребители (`main.cpp`) остаются с обычным `.cpp`.

## Глобальный фрагмент модуля

Один нюанс вы встретите почти сразу. Если внутри интерфейса модуля нужно подключить _старый_ заголовок через `#include`, его нельзя писать просто так — препроцессорные включения должны идти в **глобальном фрагменте модуля**, до объявления `export module`:

```cpp
module;                    // начало глобального фрагмента модуля

#include <cmath>           // старый заголовок — только здесь

export module math;        // дальше — собственно модуль

export double area(double r) {
    return 3.14159 * r * r;
}
```

Строка `module;` (без имени) открывает зону, куда складывают legacy-`#include`.

## Что вы освоили на этом этапе

Вы знаете терминологию (модуль, единица модуля, интерфейс, BMI), три ключевых слова (`export module`, `export`, `import`), умеете прочитать минимальный модуль и понимаете, почему порядок компиляции теперь важен. Главное — вы видите, как `export`-по-умолчанию-закрыто, отсутствие guards и единое место определения напрямую закрывают проблемы заголовков из подготовительного этапа.
