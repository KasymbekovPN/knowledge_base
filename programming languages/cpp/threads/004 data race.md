**Гонка данных (data race)** — это ситуация, когда два или более потока одновременно обращаются к одной и той же области памяти, при этом хотя бы один поток выполняет запись, и между этими обращениями нет синхронизации.

В C++ гонка данных приводит к **неопределённому поведению (Undefined Behavior)**.

```cpp
#include <iostream>
#include <thread>

struct Worker {
    static const size_t SIZE{100000};
    int value{};

    void run() {
        for (size_t i{}; i < SIZE; i++) {
            ++value;
        }
    }
};

int main() {
    Worker w;
    std::thread t0 {&Worker::run, std::ref(w)};
    std::thread t1 {&Worker::run, std::ref(w)};

    t0.join();
    t1.join();

    std::cout << "w.value: " << w.value << std::endl;

    return 0;
}
```

```
w.value: 100005
```

## Почему так происходит

Операция:

```cpp
++value;
```

не является атомарной.

Упрощённо она состоит из трёх шагов:

```text
1. Прочитать value
2. Увеличить значение
3. Записать обратно
```

# Формальное определение

Гонка данных возникает, если:
1. Есть два или более обращения к одной памяти.
2. Хотя бы одно обращение — запись.
3. Обращения происходят из разных потоков.
4. Между ними нет отношения **happens-before** (синхронизации).

# Признаки гонки

Если видишь общий объект:

```cpp
global
static
shared_ptr
this
reference
pointer
```

и несколько потоков его изменяют:

```cpp
=
++
push_back()
insert()
erase()
```

то почти наверняка нужна синхронизация:

```cpp
std::mutex
std::atomic
std::shared_mutex
condition_variable
```

## Практическое правило

Для каждого объекта, используемого несколькими потоками, спроси:

> Может ли два потока одновременно изменить этот объект или читать его во время изменения?

Если ответ "да", то без синхронизации в программе присутствует гонка данных и поведение становится неопределённым.
