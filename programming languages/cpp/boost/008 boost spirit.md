# Boost.Spirit

Boost.Spirit — библиотека для построения парсеров и генераторов прямо на C++ через выражения, напоминающие EBNF-грамматику. Header-only, но **тяжёлая для компилятора** и с самой крутой кривой обучения в Boost. Один из самых сложных модулей.

> Важно: у Spirit есть **три поколения**. Для нового кода рекомендуется **Spirit X3** (современный, требует C++14+). Classic и Qi/Karma/Lex (V2) встречаются в существующих проектах. Я разберу в основном X3, с пометками про Qi.

```cpp
#include <boost/spirit/home/x3.hpp>
namespace x3 = boost::spirit::x3;
```

## Три поколения (чтобы не путаться)

|Версия|Заголовок|Статус|
|---|---|---|
|Spirit Classic|`boost/spirit/include/classic.hpp`|Устаревшая|
|Spirit V2 (Qi/Karma/Lex)|`boost/spirit/include/qi.hpp` и др.|Зрелая, широко используется|
|Spirit X3|`boost/spirit/home/x3.hpp`|Современная, рекомендуемая|

Подмодули V2:

- **Qi** — парсинг (текст → данные)
- **Karma** — генерация (данные → текст)
- **Lex** — лексический анализатор (токенизация)

X3 — это переосмысленный Qi (только парсинг), быстрее компилируется.

## 1. Базовые парсеры X3

Готовые «кирпичики» из `x3::`:

|Парсер|Что разбирает|
|---|---|
|`x3::int_`, `x3::uint_`, `x3::long_`|Целые числа|
|`x3::double_`, `x3::float_`|Числа с плавающей точкой|
|`x3::char_`|Один символ|
|`x3::char_('a')`|Конкретный символ|
|`x3::char_('a','z')`|Символ из диапазона|
|`x3::lit("text")`|Литеральная строка (без атрибута)|
|`x3::string("text")`|Строка (с атрибутом)|
|`x3::alpha`, `x3::digit`, `x3::alnum`|Классы символов|
|`x3::space`, `x3::blank`|Пробельные символы|
|`x3::eol`, `x3::eoi`|Конец строки / конец ввода|
|`x3::bool_`|Булево значение|

## 2. Операторы построения грамматики

Spirit перегружает операторы C++ для записи грамматических правил:

|Оператор|Значение|Пример|
|---|---|---|
|`a >> b`|Последовательность (a, затем b)|`int_ >> ',' >> int_`|
|`a \| b`|Альтернатива (a или b)|`int_ \| double_`|
|`*a`|Ноль или больше (как `*` в regex)|`*char_`|
|`+a`|Один или больше|`+digit`|
|`-a`|Опционально (ноль или один)|`-lit('-')`|
|`a % b`|Список a, разделённых b|`int_ % ','`|
|`a - b`|Разность (a, но не b)|`char_ - '"'`|
|`&a`|And-предикат (проверка без потребления)|`&digit`|
|`!a`|Not-предикат|`!lit(';')`|
|`a >> b` против `a > b`|`>` — «ожидание» (ошибка, если b не совпал)||
|`(...)`|Группировка||

```cpp
// Список целых чисел через запятую: "1, 2, 3"
auto numbers = x3::int_ % ',';

// Пара "ключ=значение"
auto pair = +x3::alpha >> '=' >> +x3::alnum;
```

## 3. Точки входа: `parse` и `phrase_parse`

|Функция|Описание|
|---|---|
|`x3::parse(begin, end, grammar)`|Парсинг без пропуска пробелов|
|`x3::parse(begin, end, grammar, attr)`|С извлечением атрибута (результата)|
|`x3::phrase_parse(begin, end, grammar, skipper)`|С автоматическим пропуском (обычно `x3::space`)|
|`x3::phrase_parse(begin, end, grammar, skipper, attr)`|То же с атрибутом|

Возвращают `bool` (успех/неудача). **Важно:** итератор `begin` передаётся по ссылке и сдвигается — проверяй `begin == end`, чтобы убедиться, что разобран весь ввод.

```cpp
std::string input = "1, 2, 3, 42";
std::vector<int> result;
auto it = input.begin();

bool ok = x3::phrase_parse(
    it, input.end(),
    x3::int_ % ',',   // грамматика
    x3::space,        // skipper — пропускать пробелы
    result);          // атрибут-приёмник

if (ok && it == input.end())
    for (int n : result) std::cout << n << " "; // 1 2 3 42
```

## 4. Атрибуты (attributes)

Каждый парсер имеет **тип атрибута** — то, что он «возвращает» при разборе. Spirit автоматически синтезирует составные атрибуты:

|Грамматика|Тип атрибута|
|---|---|
|`x3::int_`|`int`|
|`x3::int_ >> x3::int_`|`boost::fusion::vector<int,int>` (или подходящий tuple)|
|`x3::int_ % ','`|`std::vector<int>`|
|`*x3::char_`|`std::string`|
|`x3::int_ \| x3::double_`|`boost::variant<int,double>`|
|`-x3::int_`|`boost::optional<int>`|

Правила согласования атрибутов с пользовательскими структурами — самая тонкая часть Spirit. Структуры адаптируются через `BOOST_FUSION_ADAPT_STRUCT`:

```cpp
struct Point { int x, y; };
BOOST_FUSION_ADAPT_STRUCT(Point, x, y) // теперь Point — приёмник атрибута

auto point = x3::int_ >> ',' >> x3::int_;
Point p;
x3::parse(it, end, point, p); // разберётся прямо в p.x, p.y
```

## 5. Правила (`rule`) и рекурсивные грамматики

Для сложных/рекурсивных грамматик используются именованные правила:

```cpp
// Объявление правила: имя, тип атрибута
x3::rule<class expr_id, int> const expr = "expr";

// Определение тела правила
auto const expr_def = x3::int_ >> *('+' >> x3::int_);

// Связывание имени и тела
BOOST_SPIRIT_DEFINE(expr)
```

|Элемент|Назначение|
|---|---|
|`x3::rule<ID, Attr>`|Объявление правила с тегом-идентификатором и типом атрибута|
|`BOOST_SPIRIT_DEFINE(rule)`|Макрос, связывающий правило с его `_def`|
|Теги-классы (`class expr_id`)|Уникально идентифицируют правило (нужны для рекурсии)|

Правила позволяют рекурсию (например, разбор вложенных выражений со скобками).

## 6. Семантические действия

Код, выполняемый при срабатывании парсера. В X3 — через лямбды, получающие контекст:

```cpp
auto print = [](auto& ctx){ std::cout << "matched: " << _attr(ctx) << "\n"; };
auto p = x3::int_[print]; // действие в []
```

|Функция контекста|Описание|
|---|---|
|`x3::_attr(ctx)`|Атрибут текущего парсера|
|`x3::_val(ctx)`|Атрибут охватывающего правила (результат)|
|`x3::_where(ctx)`|Диапазон совпавшего ввода|

> В Qi (V2) семантические действия писались через Boost.Phoenix (`_1`, `_val`, `phoenix::ref`) — другой синтаксис.

## 7. Директивы

Модификаторы поведения парсеров:

|Директива|Эффект|
|---|---|
|`x3::lexeme[...]`|Отключить пропуск пробелов внутри (разбор «вплотную»)|
|`x3::skip(s)[...]`|Задать конкретный skipper для участка|
|`x3::no_skip[...]`|Полностью отключить пропуск|
|`x3::raw[...]`|Вернуть сырой диапазон ввода вместо синтезированного атрибута|
|`x3::omit[...]`|Разобрать, но отбросить атрибут|
|`x3::repeat(n)[...]`|Повторить ровно n раз|
|`x3::repeat(min, max)[...]`|Повторить от min до max раз|
|`x3::seek[...]`|Искать совпадение, пропуская несовпадающее|

```cpp
// Разбор слова целиком, без разрыва пробелами
auto word = x3::lexeme[+x3::alpha];
```

## 8. Karma (генерация — только в V2)

Зеркало Qi для вывода данных в текст. Те же операторы, но направление обратное:

```cpp
#include <boost/spirit/include/karma.hpp>
namespace karma = boost::spirit::karma;

std::vector<int> v{1, 2, 3};
std::string out;
karma::generate_delimited(
    std::back_inserter(out),
    karma::int_ % ',',   // генератор
    karma::space, v);
// out == "1 , 2 , 3 "
```

## Сводка ключевых концепций

| Концепция                      | Суть                                                  |
| ------------------------------ | ----------------------------------------------------- |
| Базовые парсеры                | `int_`, `double_`, `char_`, `lit`, классы символов    |
| Операторы                      | `>>` `\|` `*` `+` `-` `%` `>` — строят грамматику     |
| Точки входа                    | `parse` / `phrase_parse` (со skipper'ом)              |
| Атрибуты                       | Тип «результата» парсера, синтезируется автоматически |
| `rule` + `BOOST_SPIRIT_DEFINE` | Именованные и рекурсивные грамматики                  |
| Семантические действия         | Код при срабатывании (лямбды с `_attr`)               |
| Директивы                      | `lexeme`, `raw`, `omit`, `repeat` и др.               |
| Адаптация структур             | `BOOST_FUSION_ADAPT_STRUCT`                           |

## Практические советы

- **Начинай с X3**, если нет причин использовать Qi (например, поддержки старого компилятора C++03). Qi тянет за собой Boost.Phoenix и компилируется ещё дольше.
- **Время компиляции** растёт нелинейно со сложностью грамматики — разбивай большие грамматики на отдельные единицы трансляции (через `rule` + `BOOST_SPIRIT_DEFINE` в .cpp).
- **Сообщения об ошибках** компилятора при несовпадении типов атрибутов могут быть огромными — изучай атрибутную модель внимательно, это главный источник трудностей.
- Для **простых задач** (разбить строку, извлечь числа) Spirit избыточен — хватит `boost::regex` или ручного парсинга. Spirit оправдан для настоящих грамматик: конфигурационные форматы, DSL, выражения, мини-языки.

## Отличия от стандарта и альтернатив

- В стандартной библиотеке **аналога нет** — Spirit уникален.
- Альтернативы вне Boost: PEGTL (header-only, многим кажется проще), ANTLR (внешний генератор), Lex/Yacc (классика, отдельный шаг сборки), написание парсера вручную (recursive descent).
- Сила Spirit — грамматика прямо в C++ без отдельного шага кодогенерации; цена — время компиляции и сложность диагностики.

### include/test_spirit.h
```cpp
#pragma once  
  
namespace test_spirit {  
    void test();  
}
```

### src/test_spirit.cpp
```cpp
#include "test_spirit.h"  
  
#include <boost/spirit/home/x3.hpp>  
#include <boost/fusion/adapted/std_pair.hpp>  
#include <iostream>  
#include <format>  
#include <map>  
  
namespace x3 = boost::spirit::x3;  
  
namespace test_spirit {  
  
void test() {  
    auto const pair_rule =  
        x3::rule<struct pair_id, std::pair<std::string, std::string>>{}  
        = x3::lexeme[+x3::alnum] >> '=' >> x3::lexeme[+(x3::char_ - ';')];  
    auto grammar = pair_rule % ';';  
  
    std::string input{"name=Alice; age=30; city=NYC"};  
    std::map<std::string, std::string> result;  
    auto it = input.begin();  
    bool ok = x3::phrase_parse(  
        it,  
        input.end(),  
        grammar,  
        x3::space,  
        result  
    );  
  
    if (ok && it == input.end()) {  
        for (auto& [key, value]: result) {  
            std::cout << std::format("{} -> {}\n", key, value);  
        }    } else {  
        std::cout << "Parser error\n";  
    }}  
  
}
```
