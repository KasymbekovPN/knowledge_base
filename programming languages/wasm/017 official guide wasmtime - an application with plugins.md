# [Калькулятор с WASM плагинами](https://docs.wasmtime.dev/wasip2-plugins.html#calculator-with-webassembly-plugins)

В этом примере показано, как встроить Wasmtime для создания приложения, использующего плагины. Плагины представляют собой компоненты WebAssembly.

Вы можете [посмотреть исходный код онлайн](https://github.com/bytecodealliance/wasmtime/blob/main/examples/wasip2-plugins) и клонировать репозиторий wasmtime, чтобы запустить этот пример локально.

Данное приложение — упрощенная версия программы, описанной в статье Сая Брэнда (Sy Brand) «Создание систем нативных плагинов с использованием компонентов WebAssembly» (["Building Native Plugin Systems with WebAssembly Components"](https://tartanllama.xyz/posts/wasm-plugins/)). Обратитесь к этой статье, если вас интересует более сложный пример встраивания Wasmtime и использования плагинов.

## [Калькулятор](https://docs.wasmtime.dev/wasip2-plugins.html#the-calculator)

Реализуемый калькулятор очень прост: он принимает выражение, записанное в префиксной форме (без скобок), в качестве аргумента командной строки. Например:

`target/release/calculator --plugins plugins/ add 1 2`

or

`target/release/calculator --plugins plugins/ subtract -1 -2`

Набор доступных операций определяется списком плагинов, находящихся в каталоге `plugins/`.

Каждый плагин представляет собой компонент, поддерживающий две операции:

- `get_plugin_name`: возвращает название арифметической операции, которую реализует данный плагин.
- `evaluate`: принимает два аргумента (целые числа со знаком) и возвращает результат выполнения операции над ними.

В комплект включены два примера плагинов: `add` (реализован на C) и `subtract` (реализован на JavaScript). Команда `cargo build --release` создает файлы плагинов: `c-plugin/add.wasm` и `js-plugin/subtract.wasm`. Для запуска кода необходимо скопировать оба этих файла в каталог `plugins/`, путь к которому указывается с помощью опции `--plugins`.

> Для сборки плагинов необходимо установить `wit-bindgen`, WASI SDK (для сборки плагина на C) и `jco` (для сборки плагина на JavaScript). Инструкции можно найти в разделах [C/C++](https://component-model.bytecodealliance.org/language-support/c.html) и [JavaScript](https://component-model.bytecodealliance.org/language-support/javascript.html) документации по [Component Model](https://component-model.bytecodealliance.org/).

Вложенные выражения отсутствуют.

## [WIT привязки](https://docs.wasmtime.dev/wasip2-plugins.html#wit-bindings)

Чтобы определить интерфейс для плагинов, необходимо создать файл `.wit`. Содержимое этого файла:

```
package docs:calculator;

interface host {}

world plugin {
	import host;
	export get-plugin-name: func() -> string;
	export evaluate: func(x: s32, y: s32) -> s32;
}
```


Файл WIT определяет «мир» (world), который должен реализовать плагин, а также все импортируемые элементы, предоставляемые хостом. В данном случае интерфейс `host` пуст, что означает отсутствие какой-либо функциональности на стороне хоста, которую мог бы вызвать плагин.

У этого мира есть два экспортируемых элемента; это означает, что плагин должен реализовать две функции: `get-plugin-name` (возвращает название операции, выполняемой плагином) и `evaluate` (выполняет вычисления, специфичные для данного плагина).

В коде калькулятора мы пишем:

`bindgen!("plugin");`

в котором используется макрос, предоставляемый Wasmtime и автоматически запускающий инструмент `wit-bindgen` для генерации привязок для «мира» (world).

## [`CalculatorState`](https://docs.wasmtime.dev/wasip2-plugins.html#calculatorstate)

Для представления глобального состояния программы мы используем тип `CalculatorState`, который в данном случае представляет собой просто отображение строк (имен операций) на объекты `PluginDesc`. Объект `PluginDesc` содержит информацию, необходимую для выполнения плагина с заданными аргументами.

## [Загрузка плагин](https://docs.wasmtime.dev/wasip2-plugins.html#loading-plugins)

Приложение принимает в качестве аргумента командной строки путь к директории, в которой должны находиться плагины (в виде файлов .wasm). Все плагины из этой директории загружаются сразу (eagerly).

Функция `load_plugins()` начинает с вызова функции `Engine::default()` из библиотеки Wasmtime для создания объекта `Engine`:

`let engine = Engine::default();`

`Engine` — это среда выполнения программ WebAssembly. Для работы любого количества плагинов достаточно одного экземпляра `Engine`. Подробности можно найти в [документации к крейту Wasmtime](https://docs.rs/wasmtime/latest/wasmtime/#core-concepts).

Затем этот экземпляр `Engine` передается в функцию `Linker::new()` библиотеки Wasmtime для создания объекта `Linker`. Тип `Linker` параметризуется типом состояния. В данном приложении нам не требуется состояние, специфичное для каждого плагина (так как плагины реализуют чистые функции), поэтому в качестве типа состояния используется `()` (тип unit).

`let linker: Linker<()> = Linker::new(&engine);`

Как и в случае с `Engine`, для всего приложения требуется лишь один экземпляр `Linker`. `Linker` позволяет определять в хост-приложении (в данном случае — в приложении-калькуляторе) функции, которые могут вызываться «гостевыми» модулями (плагинами, загружаемыми калькулятором). Поскольку мы не определяем подобных функций в хост-приложении, `Linker` используется здесь лишь как аргумент для функции `instantiate()` (о которой речь пойдет чуть позже).

Оставшаяся часть кода проверяет, существует ли указанный путь к директории с плагинами и является ли он действительно директорией; если это так, для каждого файла с расширением `.wasm` в этой директории вызывается функция `load_plugin()`:

```
    if !plugins_dir.is_dir() {
        anyhow::bail!("plugins directory does not exist");
    }

    for entry in fs::read_dir(plugins_dir)? {
        let path = entry?.path();
        if path.is_file() && path.extension().and_then(OsStr::to_str) == Some("wasm") {
            load_plugin(state, &engine, &linker, path)?;
        }
    }

```

Теперь рассмотрим функцию `load_plugin()`, которая загружает отдельный плагин. Работа функции начинается с вызова функции `Component::from_file()` из библиотеки Wasmtime; она принимает объект `Engine` и имя бинарного файла WebAssembly.

`let component = Component::from_file(engine, &path)?;`

`from_file()` загружает и компилирует код WebAssembly, а также создает представление компонента в памяти, которое мы присваиваем переменной `component`.

Следующий блок кода создает динамическое представление компонента, обладающее всеми необходимыми ресурсами и позволяющее вызывать его функции:

```
    let (plugin_name, plugin, store) = {
        let mut store = Store::new(engine, ());
        let plugin = Plugin::instantiate(&mut store, &component, linker)?;
        (plugin.call_get_plugin_name(&mut store)?, plugin, store)
    };

```

Сначала вызывается функция `Store::new` из библиотеки Wasmtime для создания `Store`. Объект [`Store`](https://docs.rs/wasmtime/latest/wasmtime/#core-concepts) представляет собой состояние конкретного компонента. В отличие от `Engine`, он привязан к конкретной единице кода, поэтому его нельзя повторно использовать для разных плагинов. Тип `Store` параметризован типом состояния `T`, и третий аргумент функции `Store::new` должен иметь тип `T`. Поскольку в данном примере мы не используем состояние хоста, мы передаем `()` (значение типа `()`); в результате получаем `Store<()>`.

Затем вызывается функция `Plugin::instantiate()`, которая была автоматически сгенерирована макросом `bindgen!("plugin")`. Эта функция принимает созданный нами `Store`, `Component` (представляющий код плагина) и `Linker`, переданный ранее в `load_plugin()`. Метод `instantiate()` возвращает объект `Plugin`. Тип `Plugin` соответствует миру `plugin` из нашего файла `.wit` и также был автоматически сгенерирован макросом `bindgen!`.

Теперь, когда плагин полностью инициализирован, мы можем вызвать его функцию `get-plugin-name`. Метод `call_get_plugin_name` был сгенерирован макросом `bindgen!`; обратите внимание, что имя `call_get_plugin_name` совпадает с `get-plugin-name` из файла `.wit`, но дефисы в нем заменены на символы подчеркивания, а также добавлен префикс `call_`. Этот метод принимает `Store`, что в общем случае позволяет реализации метода внутри плагина использовать состояние хоста (хотя в данном конкретном случае это не используется, так как у нас `Store<()>`).

Наконец, мы обновляем состояние калькулятора, связывая имя плагина со структурой, содержащей сам плагин и `Store`:

```
    state
        .plugin_descs
        .insert(plugin_name, PluginDesc { plugin, store });

```

## [Запуск](https://docs.wasmtime.dev/wasip2-plugins.html#running-the-code)

Наконец, эта строка кода отвечает за непосредственное вычисление выражения, переданного в командной строке:

`args.op.run(&mut state)`

У структуры `BinaryOperation` есть метод `run`, который выглядит следующим образом:

```
    fn run(self, state: &mut CalculatorState) -> anyhow::Result<()> {
        let desc = lookup_plugin(state, self.op.as_ref())?;
        let result = desc.plugin.call_evaluate(&mut desc.store, self.x, self.y)?;
        println!("{}({}, {}) = {}", self.op, self.x, self.y, result);
        Ok(())
    }

```

Сначала вызывается `lookup_plugin`, которая просто ищет имя операции (`self.op` — это имя, переданное в командной строке) в хеш-таблице, созданной функцией `load_plugins()`. В результате возвращается объект `PluginDesc`, определение которого выглядит следующим образом:

```
pub struct PluginDesc {
    pub plugin: Plugin,
    pub store: wasmtime::Store<()>,
}

```

Помните, что тип `Plugin` соответствует миру `plugin` и был сгенерирован автоматически макросом `bindgen!`.

Следующая строка кода:

`let result = desc.plugin.call_evaluate(&mut desc.store, self.x, self.y)?;`

именно она вызывает плагин для выполнения вычислений. Генератор привязок гарантирует наличие у `Plugin` метода `evaluate`, который мы вызываем с помощью `call_evaluate` (имя, присвоенное ему генератором привязок). Как и `call_get_plugin_name`, этот метод принимает `Store` в качестве первого аргумента. Два других аргумента — это значения, переданные через командную строку. Переменная `result` представляет собой 32-битное целое число (`i32`), поскольку именно такой тип данных возвращает `call_evaluate()`.

Наконец, мы выводим результат в `stdout`.

## [Написание плагин](https://docs.wasmtime.dev/wasip2-plugins.html#writing-the-plugins)

До сих пор мы исходили из того, что в каталоге `plugins` уже находятся плагины для всех необходимых нам арифметических операций. Но как именно создаются такие плагины? В [документации по компонентной модели](https://component-model.bytecodealliance.org) описано, как генерировать компоненты WebAssembly с использованием различных языков программирования.

В данном примере приложения представлены два плагина: один в каталоге `c-plugin/` (реализующий операцию сложения — `add`), а другой в `js-plugin/` (реализующий операцию вычитания — `subtract`). Процесс сборки кода показан в скрипте `build.rs`.

Можно добавить любое количество плагинов, реализующих другие арифметические операции и написанных на любом языке, для которого существует инструментарий с поддержкой WebAssembly.

## [Итоги](https://docs.wasmtime.dev/wasip2-plugins.html#wrapping-up)

Это минимальный пример, демонстрирующий, как встроить Wasmtime для создания приложения с динамически загружаемыми плагинами. Функциональность приложения можно расширить различными способами:

- добавить поддержку вложенных выражений (например, `add(subtract(1, 2), 3)`);
- добавить операции с числами с плавающей запятой;
- добавить унарные выражения (например, `sqrt(2)`).

При этом базовый механизм загрузки плагинов останется прежним — изменится лишь логика, специфичная для конкретного приложения.
