[[programming languages/wasm/_|<=]]


**1. Сам модуль** (`add.wat`) — текстовый формат WASM в S-выражениях:

```wat
(module
  (func $add (export "add") (param $a i32) (param $b i32) (result i32)
    local.get $a
    local.get $b
    i32.add)
)
```

Это стек-машина: `local.get $a` кладёт значение параметра `a` на стек, `local.get $b` — значение `b`, `i32.add` снимает два верхних значения со стека, складывает и кладёт результат обратно. `(export "add" ...)` делает функцию видимой снаружи модуля — именно так хост потом находит и вызывает функции.

**2. Компиляция в бинарный `.wasm`:**

```
wat2wasm add.wat -o add.wasm
```

Получившийся файл — 41 байт. Можно убедиться, что он компактный и корректный, разобрав его обратно в текст (`wasm2wat add.wasm`) — вышло ровно то же самое, только без имён локальных переменных (они не сохраняются в бинарном формате, это просто метки для читаемости в `.wat`).

`wasm-objdump -x add.wasm` показывает секции бинарника — ровно та структура модуля, о которой я писал в первый день плана: секция типов (сигнатура функции), секция функций, секция экспортов, секция кода. Такие модули на практике почти всегда собираются компилятором (в вашем случае — из C++), а не пишутся руками, но полезно один раз увидеть эту структуру в чистом виде.

**3. Запуск:**

```
wasmtime run --invoke add add.wasm 2 3
```

Результат — `5`. Флаг `--invoke` говорит wasmtime вызвать конкретную экспортированную функцию с аргументами из командной строки (сам wasmtime предупреждает, что эта возможность экспериментальная — в будущем синтаксис может немного измениться, но для локальных экспериментов это самый быстрый способ проверить модуль).
