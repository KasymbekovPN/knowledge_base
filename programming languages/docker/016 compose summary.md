## Проблема, которую решает Compose

Ты это уже прожил на практике: чтобы поднять наши `consumer` и `producer` вместе, пришлось выполнить 5 отдельных команд в правильном порядке, не перепутав флаги (`--network`, `--name`), и помнить, что `consumer` нужно запустить раньше, чем `producer`. На двух контейнерах это терпимо, но представь то же самое с 5-6 сервисами (база данных, кэш, несколько микросервисов) — риск ошибки и объём ручной работы растёт линейно.

**Docker Compose** — это инструмент для **декларативного** описания многоконтейнерного приложения одним YAML-файлом, вместо императивной последовательности команд.

## Ключевая идея — декларативность

Вместо того чтобы говорить Docker'у **как** что-то сделать (пошагово: создай сеть, потом собери первый образ, потом второй, потом запусти в правильном порядке) — ты описываешь **что** в итоге должно получиться, а Compose сам разбирается, в каком порядке и как это создать.

## Пример для нашего producer/consumer

```yaml
services:
  consumer:
    build: ./consumer
    networks:
      - mynet

  producer:
    build: ./producer
    depends_on:
      - consumer
    networks:
      - mynet

networks:
  mynet:
```

Одна команда:

```powershell
docker compose up
```

— и Compose сам: создаст сеть `mynet` (даже без явного `docker network create`), соберёт оба образа, запустит `consumer`, дождётся его старта (`depends_on`), запустит `producer`, подключит оба к общей сети с DNS-резолвингом по имени сервиса — всё то, что мы делали руками.

## Что именно Compose даёт по сравнению с ручными командами

- **Идемпотентность** — повторный `docker compose up` не создаст дубликаты, а просто убедится, что всё в нужном состоянии (пересоздаст только то, что изменилось)
- **`docker compose down`** — одна команда останавливает и удаляет **всё**: контейнеры, сеть, при необходимости volumes — не нужно помнить и перечислять каждый ресурс вручную
- **Версионируемая конфигурация** — `docker-compose.yml` лежит в репозитории рядом с кодом, вся команда работает с одинаковым окружением, а не полагается на то, что каждый разработчик правильно помнит все флаги
- **Масштабирование одной командой** — `docker compose up --scale producer=3` поднимет три экземпляра `producer` без переписывания команд запуска

## Важное уточнение — не путать с Kubernetes

Compose — это инструмент для **одного хоста** (по сути, обёртка над обычными Docker-командами и user-defined bridge сетью, которую мы уже разобрали). Он не даёт отказоустойчивости, автоматического восстановления при падении хоста, распределения по нескольким машинам — для этого уже нужен Kubernetes или Docker Swarm.
