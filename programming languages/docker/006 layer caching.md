## Как работает кэш слоёв

Docker кэширует **каждый слой** (каждую инструкцию Dockerfile) отдельно. При повторной сборке он проверяет по порядку сверху вниз: если инструкция и её входные данные не изменились — использует готовый слой из кэша, не выполняя её заново. Но как только находится **первая** инструкция, которая изменилась — кэш ломается для неё и **для всех инструкций после неё**, даже если они сами не менялись. Это и видно на схеме: как только `COPY` изменился, все нижестоящие слои красные — Docker не может знать, что находится в изменившихся файлах, поэтому обязан пересобрать всё дальше.

## Почему левый вариант плохой

```dockerfile
FROM node:20
COPY . .              # ← любое изменение ЛЮБОГО файла ломает кэш здесь
RUN npm install        # ← из-за этого пересобирается КАЖДЫЙ раз
CMD ["node", "app.js"]
```

Если ты меняешь одну строчку в `app.js` — Docker увидит, что `COPY . .` изменился (потому что скопировал другой набор файлов), и `npm install` пересобирается заново каждый раз, даже если `package.json` не менялся вообще. На реальных проектах это может быть минуты ожидания на каждую пересборку.

## Почему правый вариант эффективный

```dockerfile
FROM node:20
COPY package.json .    # меняется редко
RUN npm install         # тяжёлая операция — теперь кэшируется!
COPY . .                # меняется часто — но это лёгкая операция
CMD ["node", "app.js"]
```

Идея простая: **сначала копируй то, что меняется редко, потом то, что меняется часто**. `package.json` меняется, только когда ты добавляешь зависимость — а значит, `npm install` пересобирается только в этом случае. Копия исходного кода — дешёвая операция, её пересборка почти не стоит времени.

## Общее правило для эффективного Dockerfile

1. **Стабильные слои — в начало**: базовый образ, системные пакеты, зависимости
2. **Часто меняющееся — в конец**: исходный код приложения
3. **Объединяй связанные `RUN`** через `&&`, чтобы не плодить лишние слои и не оставлять мусор в промежуточных слоях (это уже разбирали)
4. **`.dockerignore`** — исключай из контекста сборки то, что не нужно (`.git`, `node_modules`, логи) — это и ускоряет отправку контекста демону, и не даёт этим файлам случайно инвалидировать кэш через `COPY . .`

## Пример

### app/main.cpp
```cpp
#include <iostream>  
  
int main() {  
    std::cout << "Hello world!" << std::endl;  
}
```

### CMakeLists.txt
```cmake
cmake_minimum_required(VERSION 3.5.0)  
project(LayerCacheDemo LANGUAGES CXX)  
  
add_executable(app main.cpp)  
target_compile_features(app PUBLIC cxx_std_17)
```

### Dockerfile
```Dockerfile
#FROM ubuntu:22.04  
FROM cr.yandex/mirror/ubuntu:22.04  
# редко меняется  
RUN apt-get update && apt-get install -y cmake build-essential  
COPY CMakeLists.txt .  
# часто меняется  
COPY app/ app/  
# конфигурация тоже относительно стабильна  
RUN cmake -B build -S .  
RUN cmake --build build
```
