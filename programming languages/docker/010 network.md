## Bridge — режим по умолчанию

Если не указывать сеть явно, Docker подключает контейнер к виртуальному мосту **docker0**. Контейнер получает свой собственный внутренний IP (например `172.17.0.2`), изолированный от сети хоста.

```powershell
docker run -d -p 8080:80 nginx
```

Чтобы достучаться до контейнера снаружи, нужен явный **проброс порта** (`-p host:container`) — Docker настраивает NAT-правило, которое перенаправляет трафик с порта хоста на порт внутри моста. Без `-p` контейнер доступен только другим контейнерам в той же bridge-сети, но не снаружи.

**Когда использовать:** практически всегда по умолчанию — это самый безопасный и предсказуемый вариант, обеспечивает изоляцию.

## Host — контейнер использует сеть хоста напрямую

```powershell
docker run -d --network host nginx
```

Контейнер вообще не получает отдельного сетевого namespace — он видит и использует сетевой стек хоста как есть. Порт 80 внутри контейнера — это **буквально** порт 80 на хосте, никакого NAT и проброса не требуется и не поддерживается.

**Плюс:** максимальная производительность (нет накладных расходов NAT), не нужно думать про `-p`. **Минус:** нет изоляции — если два контейнера в host-режиме попробуют занять один и тот же порт, будет конфликт, как если бы это были два обычных процесса на хосте. Также контейнер получает доступ ко всем сетевым интерфейсам хоста.

⚠️ Важный нюанс на Windows/Mac: `--network host` там работает **не так, как на Linux** — Docker Desktop на Windows/macOS всегда крутит демон внутри Linux-VM (через WSL 2), поэтому "хост" в этом режиме — это сеть VM, а не сеть твоего Windows напрямую. На Linux-серверах это работает буквально, там `--network host` даёт настоящий прямой доступ.

## None — полная сетевая изоляция

```powershell
docker run -d --network none alpine
```

У контейнера нет ни моста, ни какого-либо внешнего интерфейса — только `loopback` (`127.0.0.1`), который виден только внутри самого контейнера. Он не может обратиться ни наружу, ни к другим контейнерам, и снаружи к нему тоже не достучаться.

**Когда использовать:** для задач, где сеть в принципе не нужна и нежелательна из соображений безопасности — например, batch-обработка файлов, где контейнер только читает/пишет через volume, а сетевой доступ был бы лишней поверхностью атаки.

## Практическая проверка разницы

```powershell
docker run -d --name test-bridge nginx
docker inspect test-bridge --format "{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}"
```

Увидишь IP вида `172.17.0.x`.

```powershell
docker run -d --name test-none --network none alpine sleep 300
docker exec test-none ip addr
```

Увидишь только `lo` (loopback), никакого `eth0`.
