## Виртуальная машина

VM эмулирует полноценный компьютер: у каждой ВМ своя **гостевая ОС** (со своим ядром), которая работает поверх **гипервизора** — программы, которая делит физическое железо между несколькими ВМ. Из-за этого:

- Каждая VM весит гигабайты (полная копия ОС)
- Запуск занимает минуты (нужно загрузить всю ОС)
- Изоляция максимальная — вплоть до уровня ядра

## Контейнер

Контейнер не тащит с собой отдельную ОС. Все контейнеры на машине **используют одно и то же ядро хост-ОС**, а Docker Engine изолирует их друг от друга через механизмы ядра Linux (namespaces, cgroups). Из-за этого:

- Контейнер весит мегабайты (только приложение + зависимости)
- Запуск занимает секунды (ядро уже работает)
- Изоляция на уровне процессов, а не полной ОС

## Ключевой вывод

Главное отличие — на схеме это видно по среднему слою: у VM есть лишняя "гостевая ОС" под каждым приложением, а у контейнеров этого слоя просто нет — они делят одно ядро через Docker Engine. Отсюда и вся разница в скорости и весе.

## Этап 1. Основы контейнеризации

**Темы:**
- 
- Установка Docker (Docker Desktop / Docker Engine)
- Образы (images) vs контейнеры (containers)
- Docker Hub — публичный registry

**Практика:**

- Установить Docker
- Запустить `hello-world`, `ubuntu`, `alpine` в интерактивном режиме
- Разобраться с `docker ps`, `docker images`, `docker logs`, `docker exec`

**Цель:** понимать жизненный цикл контейнера и базовые команды CLI.

## Этап 2. Dockerfile и сборка образов

**Темы:**

- Синтаксис Dockerfile: `FROM`, `RUN`, `COPY`, `ADD`, `WORKDIR`, `CMD`, `ENTRYPOINT`
- Разница между `CMD` и `ENTRYPOINT`
- Кэширование слоёв (layer caching) и как писать Dockerfile эффективно
- `.dockerignore`
- Сборка образа: `docker build`, теги (`-t`)

**Практика:**

- Написать Dockerfile для простого C++ проекта, собираемого через CMake
- Оптимизировать порядок инструкций для использования кэша слоёв

**Цель:** уметь самостоятельно писать рабочий Dockerfile для своих проектов.

---

## Этап 3. Volumes и работа с данными

**Темы:**

- Файловая система контейнера (эфемерность)
- Bind mounts vs named volumes
- `docker volume create`, `docker volume ls`
- Монтирование через `-v` и `--mount`

**Практика:**

- Запустить контейнер с базой данных (например, PostgreSQL) и сохранить данные в volume
- Смонтировать локальную папку с исходниками внутрь контейнера для разработки

**Цель:** понимать, как данные переживают перезапуск контейнера.

## Этап 4. Сети (networking)

**Темы:**

- Типы сетей: bridge, host, none
- Проброс портов (`-p`)
- Связь между контейнерами по имени (user-defined bridge network)
- `docker network create/ls/inspect`

**Практика:**

- Поднять два контейнера (например, приложение + база данных) и связать их через общую сеть

**Цель:** уметь настраивать взаимодействие между несколькими контейнерами.

---

## Этап 5. Многоэтапная сборка (multi-stage builds)

**Темы:**

- Проблема больших образов
- Multi-stage build: сборка в одном образе, запуск в другом
- Актуально для C++/CMake — компилятор и зависимости не должны попадать в финальный образ

**Практика:**

- Переписать Dockerfile из Этапа 2 в multi-stage вариант: этап сборки (с CMake, компилятором) → этап запуска (минимальный образ только с бинарником)
- Сравнить размер образов до/после

**Цель:** уметь собирать компактные production-образы.

---

## Этап 6. Docker Compose

**Темы:**

- Зачем нужен Compose (оркестрация нескольких контейнеров)
- Синтаксис `docker-compose.yml`: `services`, `volumes`, `networks`, `depends_on`
- Команды: `up`, `down`, `logs`, `build`

**Практика:**

- Собрать `docker-compose.yml` для связки: C++ приложение + PostgreSQL + (опционально) сервис кэша
- Поднять весь стек одной командой

**Цель:** уметь описывать и запускать многосервисные приложения декларативно.

## Этап 7. Оптимизация образов и лучшие практики

**Темы:**

**Практика:**

- Проаудировать и уменьшить размер одного из ранее написанных образов
- Настроить запуск контейнера от непривилегированного пользователя

**Цель:** писать production-ready Dockerfile.

## Как двигаться по плану

- Каждый этап — сначала теория (коротко), потом обязательно практика на реальном примере
- Рекомендую использовать один и тот же C++/CMake-проект как сквозной пример через все этапы — так виден прогресс
- После каждого этапа можно возвращаться сюда за следующей темой
