## Три компонента

**Docker Client** — это то, с чем ты взаимодействуешь напрямую. Когда пишешь `docker run`, `docker build` и так далее — это клиент. Сам он ничего не делает, только формирует запрос и отправляет его демону.

**Docker Daemon (dockerd)** — фоновый процесс на хост-машине, который делает всю реальную работу:

- собирает образы
- запускает, останавливает, удаляет контейнеры
- управляет сетями и volume'ами
- следит за состоянием всего этого хозяйства

Клиент и демон общаются через **REST API** — это может быть Unix-сокет (`/var/run/docker.sock`) на локальной машине, либо TCP, если демон удалённый. Из этого следует важный момент: **клиент и демон не обязаны быть на одной машине**. Можно с ноутбука управлять демоном, запущенным на удалённом сервере.

**Registry** — хранилище образов. Когда демону нужен образ, которого нет локально (`docker run nginx`, а `nginx` ещё не скачан), он делает `pull` из registry. Когда ты собрал свой образ и хочешь им поделиться — делаешь `push`. По умолчанию используется Docker Hub, но registry может быть и приватным (например, GitHub Container Registry, или свой self-hosted).

## Практический вывод

Когда ты пишешь `docker run nginx`:

1. Клиент отправляет запрос демону
2. Демон проверяет, есть ли образ `nginx` локально (в разделе "Образы" на схеме)
3. Если нет — идёт в registry за образом (`pull`)
4. Запускает из образа контейнер (раздел "Контейнеры")
