# 📅 План по изучению CMake

> 🎯 Цель: Научиться создавать надёжные, кроссплатформенные сборки для C/C++ проектов.

---

## 🔹 Неделя 1: Основы CMake

**Цель:** Научиться собирать простые проекты.

### Темы:
- Что такое CMake и зачем он нужен
- Разница между `CMakeLists.txt`, Makefile и IDE-проектами
- Установка CMake (Linux/macOS/Windows)
- Простой `CMakeLists.txt`: `cmake_minimum_required`, `project`, `add_executable`
- Генерация проекта: `cmake .` → `make`
- Каталог `build` — best practice (out-of-source build)

### Практика:
```bash
# Создать проект с одним .cpp файлом, собрать через CMake
```

📚 Документация: [https://cmake.org/cmake/help/latest/guide/tutorial/index.html](https://cmake.org/cmake/help/latest/guide/tutorial/index.html)

---

## 🔹 Неделя 2: Работа с несколькими файлами и библиотеками

**Цель:** Собирать проекты с несколькими исходниками и библиотеками.

### Темы:
- `add_library()` — статические и динамические библиотеки (`STATIC`, `SHARED`)
- Связывание: `target_link_libraries()`
- Включение заголовков: `target_include_directories()`
- Организация структуры проекта: `src/`, `include/`, `lib/`
- Переменные в CMake: `set(VAR value)`
- Условия: `if(WIN32)`, `if(CMAKE_CXX_COMPILER_ID STREQUAL "GNU")`

### Практика:
```cmake
# Проект: main.cpp + math.cpp + math.h → libmath.a → executable
```

---

## 🔹 Неделя 3: Современный CMake (целевой подход)

**Цель:** Использовать современные практики (CMake ≥ 3.1+).

### Темы:
- **Target-based подход** вместо глобальных команд (`target_compile_features`, `target_compile_options`)
- Совместимость с C++17/20: `target_compile_features(target PRIVATE cxx_std_17)`
- Управление зависимостями через цели
- Использование `find_package()` — например, `Boost`, `OpenCV`, `PkgConfig`
- Обработка ошибок: `find_package(Required)`, `message(FATAL_ERROR)`

### Практика:
```cmake
# Подключить Boost через find_package и использовать в проекте
```

## 🔹 Неделя 4: Управление зависимостями и внешними проектами

**Цель:** Работать с внешними библиотеками и подмодулями.

### Темы:
- `FetchContent` — загрузка зависимостей на лету (например, `nlohmann/json`)
- `ExternalProject_Add` — альтернатива (для сложных случаев)
- Работа с Git Submodules + CMake
- Установка проекта: `install(TARGETS ...)`, `cpack`
- Генерация `.deb`, `.rpm`, `.exe` установщиков

### Практика:
```cmake
# Добавить JSON через FetchContent и использовать в коде
```

## 🔹 Неделя 5: Модульность и реальные проекты

**Цель:** Создавать многомодульные проекты.

### Темы:
- `add_subdirectory()` — вложенные `CMakeLists.txt`
- Экспорт целей: `install(EXPORT ...)`, `CMakePackageConfigHelpers`
- Создание собственного `FindXXX.cmake` модуля
- Работа с разными конфигурациями: `Debug`, `Release`, `RelWithDebInfo`
- Кастомные команды и цели: `add_custom_command`, `add_custom_target`

### Практика:
```cmake
# Проект: app/ + lib/ + tests/ → каждый в своём подкаталоге
```

## 🔹 Неделя 6: Профессиональные практики

**Цель:** Писать production-ready CMake.

### Темы:
- Поддержка разных компиляторов (GCC, Clang, MSVC)
- Работа с sanitizers: `-fsanitize=address`, `-fsanitize=thread`
- Интеграция сCTest и CPack
- Генерация coverage отчётов
- CI/CD: GitHub Actions, GitLab CI с CMake
- Использование `vcpkg` / `conan` / `hunter` (менеджеры пакетов)

### Практика:
```yaml
# Настроить GitHub Actions для сборки проекта на Linux, Windows, macOS
```

## ✅ Советы по обучению

| Совет | Почему |
|------|--------|
| Всегда используйте `out-of-source build` | Не засоряйте исходники |
| Используйте `target_*` команды, а не глобальные | Современный стиль |
| Тестируйте на разных платформах | Проверьте Windows, Linux, macOS |
| Начинайте с простого `CMakeLists.txt` | Постепенно усложняйте |
| Используйте `FetchContent` для зависимостей | Упрощает развёртывание |
