[[programming languages/cmake/_|<=]]

Out-of-source build — это подход, при котором все артефакты сборки (объектные файлы, исполняемые файлы, кэш CMake, сгенерированные Makefile'ы) размещаются в отдельном каталоге, физически отделённом от исходного кода.

Противоположность — in-source build, когда сборка происходит прямо в каталоге с исходниками, и сгенерированные файлы перемешиваются с вашим кодом.

**Как это выглядит**

```
myproject/
├── CMakeLists.txt      ← исходники
├── src/
├── include/
└── build/              ← всё сгенерированное здесь
    ├── CMakeCache.txt
    ├── Makefile
    └── ...
```

Команда:

```
cmake -B build      # конфигурация: build/ — каталог сборки
cmake --build build # сборка
```

**Почему это правильный подход**

Чистота репозитория — исходный каталог не засоряется временными файлами, и в `.gitignore` достаточно добавить одну строку `build/`.

Простая очистка — чтобы полностью пересобрать проект с нуля, достаточно удалить каталог `build/`, не рискуя задеть исходники.

Несколько конфигураций параллельно — можно держать разные каталоги сборки для разных вариантов:

```
cmake -B build-debug   -DCMAKE_BUILD_TYPE=Debug
cmake -B build-release -DCMAKE_BUILD_TYPE=Release
```

Они не конфликтуют друг с другом.

Безопасность — современный CMake по умолчанию предупреждает или блокирует in-source сборку, чтобы случайно не испортить дерево исходников.

Это считается стандартной практикой в современном CMake, и почти все проекты собираются именно так.
