# Stack vs Heap и время жизни объектов

## Stack (стек)

Автоматическая память. Каждый вызов функции создаёт **stack frame**, который хранит локальные переменные, аргументы, адрес возврата.

```cpp
void foo() {
    int x = 42;        // на стеке
    std::string s;     // сам объект на стеке (буфер может быть на heap)
}                      // при выходе — автоматическое разрушение в обратном порядке
```

Характеристики:

- Выделение/освобождение — просто сдвиг указателя стека (очень быстро)
- Размер ограничен (обычно 1–8 МБ) → глубокая рекурсия/большие массивы = **stack overflow**
- Размер должен быть известен на этапе компиляции
- Разрушение автоматическое, в порядке LIFO (обратном порядку создания)

## Heap (куча)

Динамическая память. Управляется вручную (или через smart pointers).

```cpp
int* p = new int(42);   // объект на heap, указатель p — на стеке
delete p;               // освобождать нужно явно

auto up = std::make_unique<int>(42);  // heap + автоматический delete
```

Характеристики:

- Выделение медленнее (поиск блока, синхронизация, фрагментация)
- Размер ограничен доступной памятью
- Время жизни контролирует программист → утечки, use-after-free, double-free
- Размер может определяться в рантайме

## Ключевое различие для собеседования

Указатель может лежать на стеке, а объект — на куче. Это два независимых вопроса: _где живёт переменная-указатель_ и _где живёт то, на что она указывает_.

```cpp
void f() {
    std::vector<int> v(1000);  // объект vector — на стеке (~24 байта)
                               // но 1000 int'ов — в heap-буфере
}                              // деструктор vector освобождает heap-буфер (RAII)
```

## Время жизни (storage duration)

Четыре вида:

**Automatic** — локальные переменные. Живут от объявления до конца области видимости (`{}`).

**Static** — глобальные, `static` локальные, `static` члены. Живут всю программу. Локальные static инициализируются при первом проходе (thread-safe с C++11).

```cpp
void counter() {
    static int n = 0;   // инициализируется один раз, живёт до конца программы
    ++n;
}
```

**Dynamic** — `new`/`delete`, аллокаторы. Живёт до явного освобождения.

**Thread** — `thread_local`. Своя копия на каждый поток.

## Типичные ловушки на собеседовании

**Возврат ссылки/указателя на локальную переменную** — dangling reference, UB:

```cpp
int& bad() {
    int x = 42;
    return x;   // x умирает при выходе → висячая ссылка
}
```

**Порядок разрушения** — обратный порядку создания:

```cpp
void f() {
    A a;
    B b;
}   // сначала ~B(), потом ~A()
```

**Static init order fiasco** — порядок инициализации static-объектов из разных единиц трансляции не определён.

**Lifetime extension** — const-ссылка (или rvalue-ссылка) продлевает жизнь временного объекта до конца своей области видимости:

```cpp
const std::string& s = std::string("temp");  // временный живёт, пока живёт s
```


# Корректный возврат ссылок и указателей

Ключевой принцип: возвращать ссылку/указатель можно только на объект, который **переживёт** возврат из функции.

## 1. Возврат ссылки на член объекта (переживает вызов)

```cpp
class Buffer {
    std::vector<int> data_;
public:
    int& at(size_t i) { return data_[i]; }              // объект живёт, пока живёт Buffer
    const int& at(size_t i) const { return data_[i]; }  // const-перегрузка
};

Buffer b;
b.at(0) = 42;  // можно писать — ссылка валидна
```

Так работают `operator[]`, `at()`, `front()`, `back()` в STL-контейнерах.

## 2. Возврат `*this` (для method chaining)

```cpp
class Stream {
public:
    Stream& operator<<(int x) { /*...*/ return *this; }
};

Stream s;
s << 1 << 2 << 3;  // цепочка возможна благодаря возврату ссылки на себя
```

## 3. Возврат ссылки на параметр-ссылку

```cpp
int& max(int& a, int& b) {
    return a > b ? a : b;   // возвращаем то, что пришло снаружи — живёт у вызывающего
}

int x = 1, y = 2;
max(x, y) = 100;   // y стало 100
```

## 4. Возврат ссылки на static/глобальный объект

```cpp
Logger& instance() {
    static Logger log;   // живёт всю программу
    return log;          // классический Meyers singleton
}
```

## 5. Возврат указателя на heap-объект (владение переходит вызывающему)

```cpp
Widget* create() {
    return new Widget();   // валидно, но вызывающий обязан сделать delete
}
```

Работает, но это плохой стиль — неясно, кто владеет. Правильнее:

```cpp
std::unique_ptr<Widget> create() {
    return std::make_unique<Widget>();   // владение явно передаётся move'ом
}
```

## 6. Возврат указателя на элемент контейнера

```cpp
class Registry {
    std::unordered_map<int, Widget> items_;
public:
    Widget* find(int id) {
        auto it = items_.find(id);
        return it != items_.end() ? &it->second : nullptr;  // nullptr если не найдено
    }
};
```

Указатель как «optional-ссылка»: валидный объект или `nullptr`.

## Чего делать нельзя (для контраста)

```cpp
int& bad1() {
    int x = 42;
    return x;              // ссылка на локальную — dangling
}

const std::string& bad2() {
    return "hello";        // ссылка на временный std::string — dangling
}

int& bad3() {
    std::vector<int> v{1,2,3};
    return v[0];           // ссылка на элемент локального вектора — dangling
}

std::string& bad4() {
    static std::string s = "ok";
    return s;              // это ОК
}
```

## Тонкая ловушка — lifetime extension **не** спасает через функцию

```cpp
const int& identity(const int& r) { return r; }

const int& x = identity(42);  // временный 42 НЕ продлевается — dangling!
// продление работает только при ПРЯМОЙ привязке временного к ссылке:
const int& y = 42;            // вот тут временный живёт, пока живёт y
```

Это любимый каверзный вопрос: продление жизни временного действует только при непосредственной инициализации ссылки временным, но не проходит «сквозь» возврат из функции.

Итоговое правило, которое стоит проговорить на собеседовании: возвращай по ссылке только то, чьё время жизни не привязано к телу функции — член объекта, параметр, static, `*this`. Всё, что создано локально (automatic storage), — возвращай **по значению** (move/RVO сделают это дёшево).

# Возврат ссылки/указателя из функции без аргументов

Если параметров нет, источник «долгоживущего» объекта может быть только один из этих:

## 1. Static локальная переменная

```cpp
Config& config() {
    static Config c;   // живёт до конца программы, инициализируется один раз
    return c;
}

config().timeout = 30;  // валидно
```

Это основа паттерна Meyers singleton — thread-safe инициализация с C++11.

## 2. Глобальный / namespace-scope объект

```cpp
namespace {
    Registry g_registry;
}

Registry& registry() {
    return g_registry;   // живёт всю программу
}
```

## 3. Член класса (метод без аргументов)

Формально аргумент есть — это неявный `this`. Объект переживает вызов, пока жив сам экземпляр.

```cpp
class Server {
    Logger logger_;
    std::vector<int> conns_;
public:
    Logger& logger() { return logger_; }        // ссылка на член
    int* firstConn() {                            // указатель на элемент
        return conns_.empty() ? nullptr : &conns_[0];
    }
};
```

## 4. Указатель на heap-объект (передача владения)

```cpp
Widget* make() {
    return new Widget();   // валидно, но кто делает delete?
}

// правильнее — явное владение:
std::unique_ptr<Widget> make() {
    return std::make_unique<Widget>();
}
```

## 5. Возврат через объект, полученный «извне» без параметров

Например, из другого long-lived источника:

```cpp
Widget& current() {
    return Registry::instance().active();   // ссылка тянется из singleton
}
```

## Чего нельзя (напоминание)

```cpp
int& bad() {
    int x = 42;
    return x;              // локальная — dangling
}

std::vector<int>& bad2() {
    std::vector<int> v{1,2,3};
    return v;              // локальная — dangling
}
```

## Практический вывод

Функция **без аргументов**, возвращающая ссылку/указатель, почти всегда сводится к одному из трёх легитимных случаев: **static локальная**, **глобальная**, или **член класса** (через неявный `this`). Если ни одного из этих источников нет — значит объект локальный, и его нужно возвращать **по значению**, а не по ссылке.

Частая формулировка на собеседовании: «Откуда берётся объект, на который вы возвращаете ссылку?» Правильный ответ всегда указывает на storage duration, переживающий вызов — static, dynamic (heap с передачей владения), или время жизни объемлющего объекта.
