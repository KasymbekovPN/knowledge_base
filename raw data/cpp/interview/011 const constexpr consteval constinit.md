# `const` / `constexpr` / `consteval` / `constinit`

Четыре ключевых слова, которые легко путают. Различаются по двум осям: **что гарантируют** (неизменяемость vs время вычисления) и **когда** это происходит (компиляция vs рантайм).

## Сводная таблица (главное)

| |Что гарантирует|Когда вычисляется|
|---|---|---|
|`const`|**неизменяемость** после инициализации|может быть в рантайме|
|`constexpr`|**может** быть вычислено на этапе компиляции (+ const для переменных)|компиляция **или** рантайм|
|`consteval`|**обязано** быть вычислено на этапе компиляции|только компиляция|
|`constinit`|**инициализация** на этапе компиляции (но не const!)|инициализация — компиляция|

---

## `const` — неизменяемость

Самое старое и простое: «после инициализации не менять».

```cpp
const int x = 5;           // известно на этапе компиляции
const int y = getValue();  // ✅ ОК! инициализируется в РАНТАЙМЕ, дальше не меняется
```

Ключевое: `const` **не означает** «известно на этапе компиляции». Это про запрет модификации, а не про время вычисления.

```cpp
int arr[y];   // ❌ ошибка: y не compile-time константа (нужно constexpr)
int arr[x];   // ✅ ОК: x — integral constant expression (частный случай, работает и для const int)
```

`const int` с compile-time инициализатором — исторический особый случай, который может использоваться как константное выражение. Для остальных типов это не так:

```cpp
const double d = 3.14;
constexpr double d2 = d;   // ✅ работает (C++11+, d — константное выражение)

const std::string s = "hi";
constexpr auto s2 = s;     // ❌ string не литеральный тип
```

---

## `constexpr` — «возможно на этапе компиляции»

### Для переменных

`constexpr` переменная **обязана** быть инициализирована константным выражением. Подразумевает `const`.

```cpp
constexpr int a = 5;            // ✅
constexpr int b = a * 2;        // ✅
constexpr int c = getValue();   // ❌ ОШИБКА, если getValue не constexpr

const int d = getValue();       // ✅ обычный const — можно в рантайме
```

```cpp
int arr[a];   // ✅ constexpr → можно как размер массива
```

### Для функций — **может**, но не обязано

Тут главное непонимание. `constexpr` функция вычисляется на этапе компиляции **только если это возможно** — т.е. если аргументы известны в compile-time и результат нужен в constexpr-контексте. Иначе она работает как обычная рантайм-функция.

```cpp
constexpr int square(int n) { return n * n; }

constexpr int a = square(5);   // ✅ вычислено при КОМПИЛЯЦИИ (нужно в constexpr-контексте)
int x = readInt();
int b = square(x);             // ✅ вычислено в РАНТАЙМЕ — та же функция!
```

То есть `constexpr` на функции — это **разрешение**, а не требование. Одна функция обслуживает оба случая.

Даже с константным аргументом компилятор **не обязан** считать на этапе компиляции, если результат не требуется в constexpr-контексте:

```cpp
int c = square(5);   // может быть вычислено в compile-time (оптимизация), но не гарантировано
```

### Ограничения на constexpr-функции

Смягчались с каждым стандартом:

- **C++11**: только `return` одного выражения (очень строго)
- **C++14**: циклы, локальные переменные, ветвления, множественные `return`
- **C++20**: `try/catch`, `virtual` функции, аллокации (если освобождены в том же compile-time вычислении), `constexpr` деструкторы
- **C++23**: ещё мягче (`static` в constexpr-функциях, `goto`, non-literal переменные)

Чего нельзя даже в C++23: `goto` в некоторых формах, статические переменные с нетривиальной инициализацией, работа с указателями на объекты вне выражения.

```cpp
// C++14 и позже:
constexpr int factorial(int n) {
    int result = 1;
    for (int i = 2; i <= n; ++i) result *= i;   // цикл — OK с C++14
    return result;
}
constexpr int f = factorial(5);   // 120, вычислено при компиляции
```

### `constexpr` для классов

Класс может иметь `constexpr` конструктор → объекты можно создавать в compile-time:

```cpp
struct Point {
    int x_, y_;
    constexpr Point(int x, int y) : x_(x), y_(y) { }
    constexpr int x() const { return x_; }
};

constexpr Point p(1, 2);          // объект создан при КОМПИЛЯЦИИ
constexpr int px = p.x();         // ✅
static_assert(p.x() == 1);        // ✅ проверка на этапе компиляции
```

### `if constexpr` (C++17) — другое применение

Компилируется только выбранная ветка (не путать с constexpr-функциями):

```cpp
template<class T>
void print(T t) {
    if constexpr (std::is_pointer_v<T>)
        std::cout << *t;    // компилируется ТОЛЬКО для указателей
    else
        std::cout << t;     // else-ветка для указателей даже не проверяется
}
```

Мощная замена SFINAE — отбрасывает ветку **до** инстанциации, поэтому в ней может быть код, невалидный для других типов.

## `consteval` (C++20) — «обязательно на этапе компиляции»

**Immediate function**: вызов **обязан** быть вычислен в compile-time. Если не может — **ошибка компиляции**.

```cpp
consteval int square(int n) { return n * n; }

constexpr int a = square(5);   // ✅ compile-time
int b = square(5);             // ✅ ОК — аргумент известен, вычислено при компиляции

int x = readInt();
int c = square(x);             // ❌ ОШИБКА КОМПИЛЯЦИИ! x не известен в compile-time
```

Сравни с `constexpr`, где последняя строка просто ушла бы в рантайм.

**Зачем:** гарантировать, что дорогое вычисление / генерация точно не попадёт в рантайм. Или что функция используется только для compile-time метапрограммирования.

```cpp
consteval size_t compileTimeHash(const char* s) { /* ... */ }
// гарантия: хеш посчитан при компиляции, в бинарнике только результат
```

Классическое применение — `std::source_location::current()` (объявлена `consteval`, потому что должна захватывать место вызова на этапе компиляции).

**Ограничение:** consteval-функцию нельзя вызвать из обычной (не-constexpr) функции с рантайм-аргументами, и нельзя взять её адрес как обычной функции.

## `constinit` (C++20) — статическая инициализация

Решает **static initialization order fiasco** — проблему, когда порядок инициализации глобальных объектов из разных единиц трансляции не определён.

`constinit` **гарантирует**, что переменная со static/thread storage duration инициализируется **на этапе компиляции** (constant initialization), а не в рантайме перед `main()`.

```cpp
constinit int x = 42;              // ✅ инициализация при компиляции
constinit int y = getValue();      // ❌ ОШИБКА, если getValue не constexpr
```

**Ключевое отличие от `constexpr`: НЕ подразумевает `const`.** Переменную можно менять!

```cpp
constexpr int a = 5;
// a = 10;   // ❌ ошибка — constexpr означает const

constinit int b = 5;
b = 10;      // ✅ ОК! constinit — только про ИНИЦИАЛИЗАЦИЮ, не про изменяемость
```

Это и есть смысл: нужна изменяемая глобальная переменная, но с гарантией, что она не будет инициализироваться динамически (значит, порядок инициализации не важен, fiasco невозможна).

```cpp
// a.cpp
constinit Config g_config{defaults};   // гарантированно готов до любого динамического кода

// b.cpp — глобальный объект, чей конструктор читает g_config
struct Init { Init() { use(g_config); } };   // ✅ безопасно: g_config уже инициализирован
Init g_init;
```

Без `constinit` компилятор мог бы (незаметно) выбрать динамическую инициализацию → порядок не гарантирован → UB.

## Сравнение на одном примере

```cpp
int getRuntime();
constexpr int getCE(int n) { return n * 2; }
consteval int getMustCE(int n) { return n * 2; }

// --- const ---
const int c1 = 5;              // ✅ неизменяем, compile-time значение
const int c2 = getRuntime();   // ✅ неизменяем, РАНТАЙМ инициализация

// --- constexpr ---
constexpr int e1 = 5;              // ✅ compile-time, неизменяем
constexpr int e2 = getCE(5);       // ✅ compile-time
// constexpr int e3 = getRuntime(); // ❌ ошибка: не константное выражение

int r1 = getCE(5);                 // ✅ constexpr-функция МОЖЕТ работать в рантайме
int r2 = getCE(getRuntime());      // ✅ рантайм

// --- consteval ---
int m1 = getMustCE(5);             // ✅ вычислено при компиляции
// int m2 = getMustCE(getRuntime()); // ❌ ОШИБКА: consteval требует compile-time

// --- constinit (только для static/thread storage) ---
constinit int g1 = 5;              // ✅ статическая инициализация, ИЗМЕНЯЕМА
// g1 = 10;                        // ✅ OK
// constinit int g2 = getRuntime(); // ❌ ошибка: нужна constant initialization
```

## Частые ловушки

**1. `constexpr` на функции ≠ гарантия compile-time.**

```cpp
constexpr int f(int n) { return n * 2; }
int x = readInt();
int y = f(x);   // рантайм — и это нормально, не ошибка
```

Нужна гарантия → `consteval`.

**2. `constexpr` в объявлении указателя — про сам указатель.**

```cpp
constexpr int* p = &globalInt;   // p — константный указатель (int* const),
                                 // указуемое значение МОЖНО менять: *p = 5; ✅
const int* q;                    // указуемое const, сам указатель менять можно
```

`constexpr` всегда применяется к **самому объекту** (top-level const), как `const` справа: `int* const`.

**3. `constexpr` переменная в функции — неявно `static`? Нет.**

```cpp
constexpr int f() {
    constexpr int arr[] = {1,2,3};   // локальная, может пересоздаваться (обычно оптимизируется)
    return arr[0];
}
```

С C++23 можно писать `static constexpr` внутри constexpr-функций.

**4. `constinit` не даёт const.** Частая путаница — думают, что это «constexpr для глобалов». Нет: `constexpr` = const + compile-time; `constinit` = только compile-time **инициализация**, изменяемость сохраняется.

## Практические рекомендации

- **`const`** — по умолчанию для всего, что не меняется (const correctness). Не про производительность, а про корректность и читаемость.
- **`constexpr`** — на функциях/переменных, которые _могут_ понадобиться в compile-time. Стоит дёшево, расширяет применимость. Много где в STL (`std::array`, `std::optional` и др. constexpr-friendly).
- **`consteval`** — редко; когда рантайм-вычисление недопустимо (генерация таблиц, source_location, гарантия отсутствия рантайм-стоимости).
- **`constinit`** — для изменяемых глобалов/static, чтобы исключить static init order fiasco.

---

## Формулировки на собеседовании

**«Разница `const` и `constexpr`?»** — `const` = неизменяемость (инициализация может быть в рантайме). `constexpr` = может быть вычислено на этапе компиляции; для переменных дополнительно подразумевает `const` и требует константного инициализатора.

**«Гарантирует ли `constexpr`-функция compile-time вычисление?»** — Нет. Она **может** быть вычислена в compile-time (если аргументы константны и контекст требует), но с рантайм-аргументами работает как обычная функция. Гарантию даёт только `consteval`.

**«Зачем `constinit`, если есть `constexpr`?»** — `constexpr` делает переменную неизменяемой. `constinit` гарантирует **статическую инициализацию** (решая static init order fiasco), но оставляет переменную **изменяемой**.

**«Что такое static initialization order fiasco?»** — порядок динамической инициализации глобальных объектов из **разных TU** не определён; если конструктор одного глобала обращается к другому, тот может быть ещё не инициализирован → UB. Решения: `constinit`, Meyers singleton (function-local static — инициализируется при первом обращении, потокобезопасно с C++11), или явная фаза инициализации.

---

Отличие от Java: там `final` — примерно `const` (неизменяемость ссылки/значения), а compile-time вычисления ограничены **constant expressions** для примитивов и строк (`static final int X = 5;` инлайнится компилятором). Полноценного аналога `constexpr` — произвольных функций, выполняемых компилятором, — нет. Compile-time метапрограммирование в Java делается через аннотации/кодогенерацию/рефлексию в рантайме, а не встроено в язык. Это ещё один пример философии C++: перенести максимум работы на этап компиляции, чтобы в рантайме платить ноль.
