## 0/1 Knapsack

**Условие:** дано `n` предметов, каждый с весом `weight[i]` и ценностью `value[i]`, и рюкзак вместимостью `capacity`. Каждый предмет можно взять **не более одного раза** (0/1 — либо берём целиком, либо не берём вовсе, в отличие от дробного рюкзака). Максимизировать суммарную ценность так, чтобы суммарный вес не превышал `capacity`.

### Идея

Определим `dp[i][w]` — максимальная ценность, достижимая, используя только первые `i` предметов, при ограничении веса `w`. Для каждого предмета `i` есть ровно два варианта:

- **не брать** предмет `i` — тогда `dp[i][w] = dp[i-1][w]` (результат без изменений, как будто предмета нет);
- **взять** предмет `i` (только если `weight[i-1] <= w`) — тогда `dp[i][w] = dp[i-1][w - weight[i-1]] + value[i-1]` (освобождаем место под этот предмет из решения для `i-1` предметов и добавляем его ценность).

Берём максимум из двух вариантов:

`dp[i][w] = max(dp[i-1][w], dp[i-1][w - weight[i-1]] + value[i-1])` — второй вариант применим только при `weight[i-1] <= w`.

База: `dp[0][w] = 0` для любого `w` (нет предметов — ценность 0).

```cpp
#include "knapsack01.h"  
  
#include <vector>  
#include <algorithm>  
#include <iostream>  
#include <format>  
  
namespace knapsack01 {  
  
int knapsack(const int capacity, const std::vector<int>& weights, const std::vector<int>& values) {  
    const int N{static_cast<int>(weights.size())};  
    std::vector<std::vector<int>> dp(N+1, std::vector<int>(capacity+1, 0));  
    const auto print = [&dp](const int i, const int j) {  
        std::cout << std::format("{} {}\n", i, j);
        for (const auto& vec: dp) {  
            for (const auto& item: vec) {  
                std::cout << std::format("{} ", item);            
            }            
        std::cout << '\n';        
	    }        
		std::cout << "\n\n";    
	};  
  
    for (int i{1}; i<=N; ++i) {  
        for (int w{0}; w<=capacity; ++w) {  
            // вариант "не берём предмет i"  
            dp[i][w] = dp[i-1][w];  
  
            if (weights[i-1] <= w) {  
                dp[i][w] = std::max(  
                    dp[i][w],  
                    dp[i-1][w - weights[i-1]] + values[i-1]);  
            }            
            // print(i, w);  
        }  
    }  
    return dp[N][capacity];  
}  
  
int knapsack_1d(const int capacity, const std::vector<int>& weights, const std::vector<int>& values) {  
    const int N{static_cast<int>(weights.size())};  
    std::vector<int> dp(capacity+1, 0);  
  
    for (int i{}; i < N; ++i) {  
        for (int w{capacity}; w >= weights[i]; --w) {  
            dp[w] = std::max(dp[w], dp[w - weights[i]] + values[i]);  
        }    
    }  
    return dp[capacity];  
}  
  
void demo() {  
    constexpr int CAPACITY{7};  
    const std::vector<int> WEIGHTS{1, 3, 4, 5};  
    const std::vector<int> VALUES{1, 4, 5, 7};  
  
    std::cout << std::format("knapsack: {}\n", knapsack(CAPACITY, WEIGHTS, VALUES));  
    std::cout << std::format("knapsack_1d: {}\n", knapsack_1d(CAPACITY, WEIGHTS, VALUES));  
}  
  
}
```

### Решение (2D DP)

### Разбор

- Индексация `weight[i-1]`, `value[i-1]` — та же техника сдвига на 1, что и в LCS/Edit Distance: `dp[i][*]` соответствует **первым `i`** предметам, а сами массивы `weight`/`value` индексируются от 0.
- `dp[i][w] = dp[i-1][w]` — стартовое присваивание "не берём", затем условно улучшаем его вариантом "берём", если предмет вообще влезает по весу (`weight[i-1] <= w`).
- Ответ — `dp[n][capacity]`: максимальная ценность с использованием всех `n` предметов (по факту — любого их подмножества) при полной вместимости `capacity`.

### Пример

```
weight = [1, 3, 4, 5], value = [1, 4, 5, 7], capacity = 7

      w=0 1  2  3  4  5  6  7
i=0    0  0  0  0  0  0  0  0
i=1    0  1  1  1  1  1  1  1   (предмет: w=1,v=1)
i=2    0  1  1  4  5  5  5  5   (предмет: w=3,v=4)
i=3    0  1  1  4  5  6  6  9   (предмет: w=4,v=5)
i=4    0  1  1  4  5  7  8  9   (предмет: w=5,v=7)

dp[2][4]: не брать=dp[1][4]=1; брать (w=3<=4): dp[1][1]+4=1+4=5 -> max=5
dp[3][7]: не брать=dp[2][7]=5; брать (w=4<=7): dp[2][3]+5=4+5=9 -> max=9
dp[4][7]: не брать=dp[3][7]=9; брать (w=5<=7): dp[3][2]+7=1+7=8 -> max=9

Результат: dp[4][7] = 9  (предметы с весами 3 и 4: ценность 4+5=9)
```

### Сложность

- Время: **O(n · capacity)**.
- Память: **O(n · capacity)**.

### Оптимизация памяти до O(capacity): 1D DP с обратным проходом по весу

Каждая строка `dp[i][*]` зависит только от предыдущей строки `dp[i-1][*]`, причём только от позиций **левее или равных текущей** (`w - weight[i-1] <= w`). Это позволяет использовать один массив, но **обходить веса в убывающем порядке** — критичный момент, отличающий 0/1 рюкзак от неограниченного (Unbounded Knapsack).

### Разбор оптимизации

- Один массив `dp[w]` теперь представляет "текущую" строку, которая на каждой итерации `i` обновляется **на месте**, отражая переход от `dp[i-1][*]` к `dp[i][*]`.
- Обход `w` **от `capacity` вниз к `weight[i]`** — обязателен. Если идти по возрастанию `w` (как обычно), то `dp[w - weight[i]]` могло бы быть уже **обновлено на этой же итерации** `i` (то есть уже учитывать предмет `i` повторно) — это превратило бы задачу в Unbounded Knapsack (неограниченное количество копий предмета), что неверно для 0/1 версии.
- При обходе по убыванию `w`, когда мы обновляем `dp[w]`, значение `dp[w - weight[i]]` гарантированно ещё **не обновлено** на этой итерации (так как `w - weight[i] < w`, а мы идём сверху вниз) — то есть оно всё ещё представляет `dp[i-1][w - weight[i]]`, что и требуется по формуле.

Время: O(n · capacity) без изменений, память: **O(capacity)** вместо O(n · capacity).

### Частые вариации

- **Unbounded Knapsack** — каждый предмет можно брать неограниченное число раз → в 1D-версии веса обходятся **по возрастанию**, а не по убыванию (именно потому, что повторное использование обновлённого `dp[w - weight[i]]` в рамках той же итерации `i` теперь и есть желаемое поведение).
- **Partition Equal Subset Sum** — частный случай 0/1 Knapsack: можно ли разбить массив на два подмножества с равной суммой → рюкзак с `value[i] = weight[i] = nums[i]`, `capacity = sum/2`, проверяем достижимость (булев DP вместо максимизации).
- **Target Sum** — присвоить каждому числу знак `+`/`-`, чтобы получить целевую сумму → сводится к 0/1 Knapsack через алгебраическое преобразование (сумма положительных элементов = `(totalSum + target) / 2`).
- **Coin Change** (уже разобрана) — по структуре ближе к Unbounded Knapsack (монеты берутся многократно), а не к 0/1.

### Частый доп. вопрос: "почему в 0/1 рюкзаке обход по убыванию, а в Coin Change (Unbounded) — по возрастанию?"

Это один из самых частых concept-check вопросов на эту тему: направление обхода веса в 1D-оптимизации напрямую определяет, учитывается ли предмет в решении **один раз** (0/1, обход сверху вниз — не даёт "увидеть" уже обновлённое в этой же итерации значение) или **многократно** (Unbounded, обход снизу вверх — специально позволяет использовать только что обновлённое значение, что эквивалентно повторному использованию того же предмета).
