## Container With Most Water

**Условие:** дан массив `height`, где `height[i]` — высота вертикальной линии в точке `i`. Найти две линии, которые вместе с осью X образуют контейнер, вмещающий максимум воды. Вернуть максимальный объём (площадь).

Площадь между линиями `i` и `j` = `min(height[i], height[j]) * (j - i)` — ограничивает более низкая из двух линий, ширина — расстояние между ними.

### Идея

Наивно — перебор всех пар `(i, j)`: O(n²). Оптимально — **два указателя**, начинающиеся с краёв массива (`left = 0`, `right = n-1`). Это даёт максимально возможную ширину сразу. На каждом шаге считаем площадь и сдвигаем указатель, стоящий на **более низкой** линии, внутрь.

Почему можно сдвигать именно более низкую границу: площадь ограничена меньшей из двух высот. Если сдвинуть более высокую границу, ширина уменьшится, а ограничивающая высота останется той же или станет ещё меньше (поскольку min всё ещё зависит от более низкой) — то есть результат заведомо не может улучшиться. А сдвиг более низкой границы — единственный шанс найти линию повыше и потенциально увеличить `min(...)`, компенсируя уменьшение ширины.

### Решение

```cpp
#include "container_most_water.h"  
  
#include <algorithm>  
#include <iostream>  
#include <format>  
  
namespace container_most_water {  
  
int max_area(const std::vector<int>& heights) {  
    int left{};  
    int right{static_cast<int>(heights.size()) - 1};  
    int best{};  
  
    while (left < right) {  
        int width = right - left;  
        int area{std::min(heights[left], heights[right]) * width};  
        best = std::max(best, area);  
  
        if (heights[left] < heights[right]) {  
            ++left;  
        } else {  
            --right;  
        }
	}  

    return best;  
}  
  
void demo() {  
    const std::vector<int> heights = {1,8,6,2,5,4,8,3,7};  
    std::cout << std::format("max area {}\n", max_area(heights));  
}  
  
}
```

### Разбор

- `width = right - left` — расстояние между указателями (ширина контейнера).
- `area = min(height[left], height[right]) * width` — площадь, ограниченная более низкой линией.
- Сдвигаем `left` вперёд, если `height[left] < height[right]` (левая линия ниже — она "узкое место"), иначе сдвигаем `right` назад. При равенстве высот можно двигать любой указатель — результат не зависит от выбора.
- Цикл идёт, пока `left < right`, суммарно указатели проходят весь массив — O(n).

### Пример


### Сложность

- Время: **O(n)** — каждый указатель проходит массив не более одного раза суммарно.
- Память: **O(1)**.

### Почему наивный O(n²) неверно "чувствуется" быстрее

Интуитивно кажется, что надо проверять больше пар, но доказательство корректности жадного сдвига (выше) строго обосновывает, что O(n) достаточно — это частый вопрос на собеседовании: "докажите, почему можно отбросить остальные пары при сдвиге низкой границы".

### Частые вариации

- **Trapping Rain Water** — похожая задача, но считает воду **над** каждым столбцом (сумма по всем позициям, а не одна пара) — тоже решается двумя указателями или через префиксные максимумы слева/справа.
