## Combination Sum

**Условие:** дан массив уникальных положительных чисел `candidates` и целевая сумма `target`. Найти все уникальные комбинации чисел из `candidates`, дающие в сумме `target`. Одно и то же число можно использовать в комбинации **многократно** (неограниченное количество раз). Комбинации, отличающиеся только порядком элементов, считаются одинаковыми.

### Идея

Backtracking, похожий на Subsets, но с двумя ключевыми отличиями:

1. Один и тот же элемент можно брать повторно — значит рекурсивный вызов продолжает **с того же индекса `i`**, а не с `i+1` (в отличие от Subsets/Permutations, где элемент использовался ровно один раз).
2. Есть числовое ограничение (`target`) — это даёт естественную точку **отсечения (pruning)**: если текущая частичная сумма превысила `target`, дальше в этой ветке смысла нет, откатываемся немедленно.

Как и в Subsets, параметр `start` (не брать элементы левее текущего) исключает подсчёт одной и той же комбинации в разном порядке — например, `[2,2,3]` и `[2,3,2]` не должны попасть в ответ как разные комбинации.

### Решение

```cpp
#include "combination_sum.h"  
  
#include <vector>  
#include <algorithm>  
#include <iostream>  
#include <format>  
  
namespace combination_sum {  
  
void backtrace(const std::vector<int>& candidates,  
               const int target,  
               const int start,  
               std::vector<int>& path,  
               std::vector<std::vector<int>>& result) {  
    if (target == 0) {  
        // сумма точно набрана -> сохраняем комбинацию  
        result.push_back(path);  
        return;  
    }  
    for (int i{start}; i < static_cast<int>(candidates.size()); ++i) {  
        if (candidates[i] > target) {  
            // массив отсортирован -> все дальнейшие элементы тоже слишком большие  
            break;  
        }  
        path.push_back(candidates[i]);  
        // i, не i+1 — повтор разрешён  
        backtrace(candidates, target - candidates[i], i, path, result);  
        // откат  
        path.pop_back();  
    }}  
  
std::vector<std::vector<int>> combination_sum(const std::vector<int>& candidates, const int target) {  
    std::vector<std::vector<int>> result;  
    std::vector<int> path;  
    backtrace(candidates, target, 0, path, result);  
  
    return result;  
}  
  
void demo() {  
    const std::vector<int> SORTED_CANDIDATES{2,3,6,7};  
    constexpr  int TARGET{7};  
  
    for (const auto& result = combination_sum(SORTED_CANDIDATES, TARGET);  
        const auto& vec: result) {  
        for (const auto& item: vec) {  
            std::cout << std::format("{} ", item);  
        }        std::cout << '\n';  
    }  
}  
}
```

### Разбор

- Сортировка `candidates` в начале — необходима для оптимизации `break` в цикле: если текущий кандидат уже больше оставшегося `target`, все последующие (они ещё больше, так как массив отсортирован) точно не подойдут — можно прервать цикл целиком, а не просто пропустить (`continue`) этот один элемент.
- База рекурсии: `target == 0` — сумма набрана ровно, сохраняем `path`. Если бы `target` стал отрицательным, это означало бы "перебор" — но такая ветка вообще не создаётся благодаря проверке `candidates[i] > target` перед рекурсивным вызовом (значит `target - candidates[i]` в рекурсии всегда `>= 0`).
- Рекурсивный вызов передаёт **тот же индекс `i`** (не `i+1`) — это единственное структурное отличие от Subsets/Combinations без повторов. Значит на следующем уровне рекурсии снова можно выбрать `candidates[i]`, то есть один элемент допустимо использовать сколько угодно раз подряд.
- `start` (не `i`) в цикле `for` — гарантирует, что новые элементы выбираются только из `candidates[start..]`, исключая перестановки одной и той же комбинации (не даёт получить, скажем, и `[2,3]`, и `[3,2]` как разные записи).

### Пример

  i=0 (2<=7): path=[2]

      i=0 (2<=5): path=[2,2]
        backtrack(target=3, start=0, path=[2,2])
          i=0 (2<=3): path=[2,2,2]
            backtrack(target=1, start=0, path=[2,2,2])
              i=0 (2<=1? нет) -> break, ничего не добавлено
            откат: path=[2,2]
          i=1 (3<=3): path=[2,2,3]

            откат: path=[2,2]
          i=2 (6<=3? нет) -> break
        откат: path=[2]
      i=1 (3<=5): path=[2,3]
        backtrack(target=2, start=1, path=[2,3])
          i=1 (3<=2? нет) -> break
        откат: path=[2]
      i=2 (6<=5? нет) -> break
    откат: path=[]
  i=1 (3<=7): path=[3]
    backtrack(target=4, start=1, path=[3])
      i=1 (3<=4): path=[3,3]
        backtrack(target=1, start=1, path=[3,3])
          i=1 (3<=1? нет) -> break
        откат: path=[3]
      i=2 (6<=4? нет) -> break
    откат: path=[]
  i=2 (6<=7): path=[6]
    backtrack(target=1, start=2, path=[6])
      i=2 (6<=1? нет) -> break

### Сложность

- Время: **O(2^target)** в худшем случае (грубая верхняя оценка через дерево решений "брать/не брать" повторно) — точная оценка сложна и зависит от `candidates`, но экспоненциальна по своей природе, так как перечисляются все допустимые комбинации.
- Память: **O(target / min(candidates))** — максимальная глубина рекурсии (сколько раз можно вложить самый маленький элемент, не превысив target).

### Частые вариации

- **Combination Sum II** — каждый элемент можно использовать **не более одного раза**, при этом входной массив может содержать **дубликаты**, и результат не должен содержать одинаковых комбинаций → рекурсивный вызов идёт с `i+1` (не `i`, как здесь), плюс пропуск дубликатов на одном уровне рекурсии (`if (i > start && candidates[i] == candidates[i-1]) continue;`).
- **Combination Sum III** — нужно использовать ровно `k` чисел из диапазона `1..9` (без повторов), дающих в сумме `target` → комбинация ограничений: `i+1` (без повторов) + доп. условие на количество выбранных элементов.
- **Combination Sum IV** — на самом деле не про комбинации, а про **количество способов** с учётом порядка (по сути ближе к Coin Change II/Unbounded Knapsack) → решается DP, а не backtracking, несмотря на похожее название.
- **Subsets** (разобрана ранее) — тот же паттерн `start`, но без ограничения по сумме и без повторного использования элементов (`i+1` вместо `i`).

### Частый доп. вопрос: "почему `i`, а не `i+1`, ведёт к разрешённому повтору?"

Передавая в рекурсию тот же `i`, мы говорим: "на следующем шаге можно снова рассмотреть `candidates[i]` (и последующие)". Поскольку сам элемент `candidates[i]` остаётся в допустимом диапазоне `[i, end)` для следующего вызова, он может быть выбран повторно неограниченное число раз, пока позволяет `target`. Если бы передавали `i+1`, `candidates[i]` навсегда исключался бы из рассмотрения после первого использования — это и есть Combination Sum II / Subsets поведение.
