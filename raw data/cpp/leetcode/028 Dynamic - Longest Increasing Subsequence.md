## Longest Increasing Subsequence

**Условие:** дан массив целых чисел `nums`. Найти длину наибольшей строго возрастающей подпоследовательности (элементы не обязательно идут подряд, но должны сохранять относительный порядок и строго возрастать).

### Решение 1: DP за O(n²)

**Идея:** определим `dp[i]` — длину наибольшей возрастающей подпоследовательности, **заканчивающейся именно на элементе `nums[i]`**. Для каждого `i` перебираем все предыдущие `j < i`: если `nums[j] < nums[i]`, то к подпоследовательности, заканчивающейся на `j`, можно "приклеить" `nums[i]`, получив длину `dp[j] + 1`. Берём максимум по всем подходящим `j`.

```cpp
#include "longest_increasing_subsequence.h"  
  
#include <vector>  
#include <algorithm>  
#include <iostream>  
#include <format>  
  
namespace longest_increasing_subsequence {  
  
int len_of_lis(const std::vector<int>& nums) {  
    std::cout << "len_of_lis\n";  
    const int N{static_cast<int>(nums.size())};  
    if (N == 0) return 0;  
  
    // каждый элемент сам по себе -> подпоследовательность длины 1  
    std::vector<int> dp(N, 1);  
    int best{1};  
  
    const auto print = [&nums, &dp, &best](const int i, const int j) {  
        std::cout << "###\nnums: ";        
        for (const auto& item : nums) std::cout << std::format("{} ", item);  
        std::cout << "\ndp: ";        
        for (const auto& item : dp) std::cout << std::format("{} ", item);  
        std::cout << std::format("best: {}, i: {}, j: {}\n", best, i, j);    
    };  
  
    for (int i{1}; i < N; ++i) {  
        for (int j{0}; j < i; ++j) {  
            if (nums[j] > nums[i]) {  
                dp[i] = std::max(dp[i], dp[j] + 1);  
            }            
            // print(i, j);  
        }  
        best = std::max(best, dp[i]);  
    }  
    return best;  
}  
  
int len_of_lis_fast(const std::vector<int>& nums) {  
    std::cout << "len_of_lis_fast\n";  
    std::vector<int> tails;  
  
    const auto print = [&tails]() {  
        for (const auto& item: tails) std::cout << std::format("{} ", item);  
        std::cout << "\n";    
    };  
  
    for (const auto& item: nums) {  
        if (auto it{std::ranges::lower_bound(tails, item)};  
            it == tails.end()) {  
  
            tails.push_back(item);  
        } else {  
            *it = item;  
        }        
        // print();  
    }  
  
    return static_cast<int>(tails.size());  
}  
  
void demo() {  
    const std::vector<int> NUMS{10, 9, 2, 5, 3, 7, 101, 18};  
    std::cout << std::format("len_of_lis: {}\n", len_of_lis(NUMS));  
    std::cout << std::format("len_of_lis_fast: {}\n", len_of_lis_fast(NUMS));  
}  
  
}
```

**Разбор:** `dp[i]` инициализируется 1, потому что сам по себе элемент `nums[i]` — подпоследовательность длины 1. Внутренний цикл перебирает всех "потенциальных предшественников" `j` и берёт лучший из тех, кто меньше `nums[i]` — тогда `nums[i]` продолжает эту подпоследовательность. Ответ — не обязательно `dp[n-1]` (LIS может заканчиваться где угодно), поэтому `best` отслеживается отдельно как максимум по всему массиву `dp`.

**Пример:**

```
nums = [10, 9, 2, 5, 3, 7, 101, 18]

dp[0]=1 (10)
dp[1]=1 (9) — 10 не < 9
dp[2]=1 (2) — ничего не меньше 2
dp[3]=2 (5) — 2<5 -> dp[2]+1=2
dp[4]=2 (3) — 2<3 -> dp[2]+1=2
dp[5]=3 (7) — 2<7(dp=1->2), 5<7(dp=2->3), 3<7(dp=2->3) -> max=3
dp[6]=4 (101) — все меньше -> max(dp[0..5])+1 = dp[5]+1=4
dp[7]=4 (18) — 10,9,2,5,3,7 < 18 -> max(dp[0..5])+1=4 (7 даёт dp=3->4)

dp = [1,1,1,2,2,3,4,4]
best = 4  ([2,3,7,101] или [2,5,7,101] и т.п.)
```

Сложность: время **O(n²)**, память **O(n)**.

### Решение 2: O(n log n) через бинарный поиск

**Идея:** поддерживаем массив `tails`, где `tails[k]` — минимально возможное значение последнего элемента возрастающей подпоследовательности длины `k+1` среди всех уже обработанных элементов. Для каждого нового числа `x`:

- если `x` больше всех элементов в `tails` — оно продолжает самую длинную подпоследовательность, добавляем в конец;
- иначе находим первую позицию в `tails`, где элемент `>= x` (через `std::lower_bound`, бинарный поиск), и заменяем её на `x`.

Замена (а не просто игнорирование) критична: заменяя `tails[pos]` на меньшее `x`, мы **не уменьшаем** длину подпоследовательности, но делаем её потенциально более "продолжаемой" в будущем (меньший хвост даёт больше шансов на присоединение следующих элементов). Важно: сам массив `tails` **не является** реальной LIS — это вспомогательная структура, только его длина в конце равна длине LIS.

**Разбор:** `std::lower_bound` находит первую позицию, где `tails[pos] >= x` — именно эту позицию нужно "улучшить" (заменить на меньшее значение `x`, сохраняя ту же длину подпоследовательности `pos+1`, но с более выгодным хвостом). Массив `tails` всегда остаётся отсортированным по построению — это гарантирует корректность бинарного поиска на каждом шаге.

**Пример:**

```
nums = [10, 9, 2, 5, 3, 7, 101, 18]

x=10:  tails=[]        -> lower_bound не находит -> push_back -> tails=[10]
x=9:   tails=[10]      -> lower_bound(9) -> позиция 0 (10>=9) -> заменить -> tails=[9]
x=2:   tails=[9]       -> lower_bound(2) -> позиция 0 -> заменить -> tails=[2]
x=5:   tails=[2]       -> lower_bound(5) не найден -> push_back -> tails=[2,5]
x=3:   tails=[2,5]     -> lower_bound(3) -> позиция 1 (5>=3) -> заменить -> tails=[2,3]
x=7:   tails=[2,3]     -> lower_bound(7) не найден -> push_back -> tails=[2,3,7]
x=101: tails=[2,3,7]   -> push_back -> tails=[2,3,7,101]
x=18:  tails=[2,3,7,101] -> lower_bound(18) -> позиция 3 (101>=18) -> заменить -> tails=[2,3,7,18]

Итог: tails.size() = 4
```

(Обратите внимание: `[2,3,7,18]` — не обязательно реальная LIS в массиве, но её **длина** корректна.)

Сложность: время **O(n log n)** — `n` элементов, каждый требует бинарный поиск за `O(log n)`. Память: **O(n)** под `tails`.

### Частые вариации

- **Number of Longest Increasing Subsequences** — посчитать не длину, а количество различных LIS — требует доп. массива `count[i]` рядом с `dp[i]`.
- **Russian Doll Envelopes** — 2D-обобщение: сортировка по одному измерению + LIS по-другому с трюком (реверс сортировки при равных значениях, чтобы избежать ложных цепочек).
- **Longest Increasing Subsequence восстановление самой подпоследовательности** — для O(n²) решения хранится массив `parent[i]` — предшественник в оптимальной цепочке; для O(n log n) решения восстановление сложнее и требует дополнительного отслеживания индексов.
- **Maximum Length of Pair Chain** — похожая идея, но чаще решается жадным алгоритмом (сортировка по концу интервала), а не DP.
