## Climbing Stairs

**Условие:** дана лестница из `n` ступеней. За один шаг можно подняться на 1 или 2 ступени. Сколько существует различных способов подняться на самый верх?

### Идея

Чтобы оказаться на ступени `n`, последний шаг был либо с ступени `n-1` (шаг на 1), либо с ступени `n-2` (шаг на 2). Значит количество способов добраться до `n` — это сумма способов добраться до `n-1` и до `n-2`:

`ways(n) = ways(n-1) + ways(n-2)`

Это в точности рекуррентное соотношение **чисел Фибоначчи** (с базовыми случаями `ways(1) = 1`, `ways(2) = 2`). Классический пример, показывающий, что не всякая DP-задача выглядит как DP на первый взгляд — но перекрывающиеся подзадачи (`ways(n-1)` пересчитывается многократно при наивной рекурсии) выдают её сразу.

### Наивная рекурсия (для сравнения — экспоненциальная)

```cpp
int climbStairsNaive(int n) {
    if (n <= 2) return n;
    return climbStairsNaive(n - 1) + climbStairsNaive(n - 2);
}
```

Время: **O(2ⁿ)** — каждый вызов порождает два новых, множество поддеревьев рекурсии пересчитывают одно и то же (например, `ways(5)` вычисляется многократно на разных ветках).

### Решение: DP с O(1) памяти

Поскольку для вычисления `ways(n)` нужны только два предыдущих значения, не нужен весь массив — достаточно хранить последние два числа.

```cpp
int climbStairs(int n) {
    if (n <= 2) return n;

    int prev2 = 1; // ways(1)
    int prev1 = 2; // ways(2)

    for (int i = 3; i <= n; ++i) {
        int cur = prev1 + prev2;
        prev2 = prev1;
        prev1 = cur;
    }

    return prev1;
}
```

### Разбор

- База: `ways(1) = 1` (единственный способ — один шаг на 1 ступень), `ways(2) = 2` (либо 1+1, либо сразу 2).
- `prev2` и `prev1` — это "скользящее окно" из двух последних значений последовательности, аналогично итеративному вычислению Фибоначчи.
- На каждой итерации: `cur = prev1 + prev2` — новое значение по рекуррентной формуле; затем "сдвигаем окно" — `prev2` становится тем, что было `prev1`, а `prev1` становится только что вычисленным `cur`.
- Никакой массив `dp[]` не нужен — только 3 переменные, что даёт O(1) память вместо O(n).

### Пример

```
n=5

i=1: ways=1
i=2: ways=2
i=3: prev2=1,prev1=2 -> cur=3; prev2=2,prev1=3
i=4: prev2=2,prev1=3 -> cur=5; prev2=3,prev1=5
i=5: prev2=3,prev1=5 -> cur=8; prev2=5,prev1=8

Результат: 8
```

(Проверка: способы для n=5: 1+1+1+1+1, 1+1+1+2 (в разных порядках — 4 варианта), 1+2+2 (в разных порядках — 3 варианта) → 1+4+3=8 ✓)

### Сложность

- Время: **O(n)** — один линейный проход.
- Память: **O(1)** — три переменные.

### Вариант с явным массивом DP (менее оптимален по памяти, но нагляднее)

```cpp
#include <vector>

int climbStairsDP(int n) {
    if (n <= 2) return n;

    std::vector<int> dp(n + 1);
    dp[1] = 1;
    dp[2] = 2;

    for (int i = 3; i <= n; ++i) {
        dp[i] = dp[i - 1] + dp[i - 2];
    }

    return dp[n];
}
```

Полезно показать на собеседовании сначала этот вариант (нагляднее демонстрирует DP-переходы), а затем оптимизировать до O(1) памяти, объяснив, что `dp[i]` зависит только от двух предыдущих значений.

```cpp
#include "climbing_stairs.h"  
  
#include <vector>  
#include <iostream>  
#include <format>  
  
namespace climbing_stairs {  
  
int climb_stairs_naive(const int n) {  
    if (n <= 2) return n;  
    return climb_stairs_naive(n - 1) + climb_stairs_naive(n - 2);  
}  
  
int climb_stairs(const int n) {  
    if (n <= 2) return n;  
  
    int prev2{1};  
    int prev1{2};  
  
    for (int i{3}; i <= n; ++i) {  
        const int current{prev1 + prev2};  
        prev2 = prev1;  
        prev1 = current;  
    }  
    return prev1;  
}  
  
int climb_stairs_dp(const int n) {  
    if (n <= 2) return n;  
  
    std::vector<int> dp(n + 1);  
    dp[1] = 1;  
    dp[2] = 2;  
  
    for (int i{3}; i <= n; ++i) {  
        dp[i] = dp[i - 1] + dp[i - 2];  
    }  
    return dp[n];  
}  
  
void demo() {  
    std::cout << std::format("climb_stairs_naive: {}\n", climb_stairs_naive(7));  
    std::cout << std::format("climb_stairs: {}\n", climb_stairs(7));  
    std::cout << std::format("climb_stairs_dp: {}\n", climb_stairs_dp(7));  
}  
  
}
```

### Частые вариации

- **Min Cost Climbing Stairs** — не считаем количество способов, а минимизируем суммарную стоимость подъёма с весами на ступенях — тот же паттерн DP, но с `min` вместо суммы.
- **Climbing Stairs с шагом до k** — обобщение: за раз можно подняться на 1..k ступеней → `ways(n) = sum(ways(n-1), ..., ways(n-k))`, скользящее окно уже из `k` последних значений.
- **House Robber** — структурно похожая рекуррентность (`dp[i] = max(dp[i-1], dp[i-2] + nums[i])`), но с максимизацией вместо суммирования.
- **Fibonacci Number** — сама задача, из которой Climbing Stairs выводится напрямую — часто задают как разминочный вопрос перед этой.
