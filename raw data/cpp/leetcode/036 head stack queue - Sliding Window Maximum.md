## Sliding Window Maximum

**Условие:** дан массив `nums` и размер окна `k`. Окно скользит слева направо по одному элементу за раз. Для каждой позиции окна найти максимальный элемент внутри него. Вернуть массив всех этих максимумов.

### Идея

Наивно — для каждого положения окна искать максимум линейным проходом: O(n·k). Оптимально — **монотонная дек (deque) с убывающими значениями**, дающая амортизированное O(1) на каждый элемент.

Идея дека: хранить в нём **индексы** элементов (не сами значения), поддерживая инвариант — значения по этим индексам идут строго убывающе от начала дека к концу. Тогда голова дека всегда содержит индекс максимума текущего окна.

На каждом шаге, добавляя новый элемент `nums[i]`:

1. Удаляем с **конца** дека все индексы, значения которых **меньше или равны** `nums[i]` — они больше никогда не смогут быть максимумом, пока в окне присутствует более свежий и не меньший элемент `nums[i]`.
2. Добавляем индекс `i` в конец дека.
3. Удаляем с **начала** дека индексы, которые вышли за левую границу текущего окна (устарели).
4. Если окно уже достигло размера `k` — значение на **голове** дека (наибольший ещё актуальный элемент) — это максимум текущего окна.

### Решение

```cpp
#include "sliding_window_max.h"  
  
#include <iostream>  
#include <ostream>  
#include <vector>  
#include <queue>  
  
namespace sliding_window_max {  
  
std::vector<int> max_sliding_window(const std::vector<int>& nums, const int k) {  
    // хранит индексы, значения по ним убывают от начала к концу  
    std::deque<int> dq;  
    std::vector<int> result;  
  
    const int N{static_cast<int>(nums.size())};  
    result.reserve(N - k + 1);  
  
    for (int i{}; i < N; ++i) {  
        // убираем с конца все индексы с меньшим или равным значением — они бесполезны  
        while (!dq.empty() && nums[dq.back()] <= nums[i]) dq.pop_back();  
        dq.push_back(i);  
  
        // убираем с начала индексы, вышедшие из текущего окна [i-k+1, i]  
        if (dq.front() <= i - k) dq.pop_front();  
  
        // окно ещё не набрало полный размер k — максимум пока не фиксируем  
        if (i >= k - 1) result.push_back(nums[dq.front()]);  
    }    return result;  
}  
  
void demo() {  
    constexpr int K{3};  
    const std::vector<int> NUMS{1,3,-1,-3,5,3,6,7};  
  
    for (const auto& num : max_sliding_window(NUMS, K)) {  
        std::cout << num << std::endl;  
    }}  
  
}
```

### Разбор

- Дек хранит **индексы**, а не значения — это важно, чтобы на шаге 3 можно было проверить, не устарел ли индекс относительно текущей позиции окна (`dq.front() <= i - k` означает, что этот индекс уже вышел за левую границу).
- Шаг 1 (`while (!dq.empty() && nums[dq.back()] <= nums[i])`) — ключевая идея: если новый элемент `nums[i]` больше или равен значению на конце дека, то это старое значение никогда не станет максимумом ни для одного будущего окна (пока `nums[i]` ещё в окне, оно всегда будет "перекрывать" собой более старый и не больший элемент). Поэтому его можно безопасно выбросить.
- За счёт шага 1 дек всегда остаётся отсортированным по убыванию значений (от головы к хвосту) — голова автоматически содержит индекс текущего максимума.
- Каждый индекс добавляется в дек **ровно один раз** и удаляется **не более одного раза** (либо с конца на шаге 1, либо с начала на шаге 3) — отсюда амортизированная линейная сложность, несмотря на вложенный `while`.
- Результат начинает собираться только когда `i >= k - 1` — то есть когда окно впервые достигло полного размера `k`.

### Сложность

- Время: **O(n)** амортизированно — каждый индекс добавляется в дек ровно один раз и удаляется не более одного раза суммарно за весь проход.
- Память: **O(k)** — дек хранит не более `k` индексов одновременно (устаревшие индексы удаляются).

### Частые вариации

- **Sliding Window Median** — вместо максимума нужна медиана окна — решается через две кучи (или `multiset`/`multimap` с балансировкой) вместо монотонного дека, так как медиана требует поддержки порядка всех элементов, а не только текущего максимума.
- **Shortest Subarray with Sum at Least K** — тоже использует монотонный дек, но по префиксным суммам, а не по скользящему окну фиксированного размера.
- **Constrained Subsequence Sum** — DP + монотонный дек для быстрого нахождения максимума `dp[]` в скользящем окне размера `k`, чтобы избежать O(n·k).
- **First Negative Number in Every Window of Size K** — похожая структура (окно + дек), но дек хранит индексы отрицательных чисел вместо монотонной последовательности.

### Частый доп. вопрос: "почему `<=`, а не строгое `<` на шаге 1?"

Если использовать строгое `<` вместо `<=`, дубликаты значений будут накапливаться в деке (равные элементы не будут вытеснять друг друга), что не ломает корректность результата, но может ухудшить асимптотику в вырожденных случаях (например, массив из одинаковых чисел) — деку придётся хранить больше индексов, чем нужно. `<=` гарантирует, что дек содержит не более одного индекса на каждое различное значение в текущем "убывающем хвосте", что чуть эффективнее по константе.
