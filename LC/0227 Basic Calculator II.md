
## Суть задачи

В отличие от LC224 (только `+`/`-`/скобки), здесь **добавляются `*` и `/`**, но **скобок нет**. Ключевая сложность — **приоритет операций**: `2 + 3 * 4` должно дать `14`, а не `20` — нельзя просто применять операции по порядку слева направо, как в LC224.

Пример: `"3+2*2"` → `3 + (2*2) = 7`. `" 3/2 "` → `1` (целочисленное деление). `" 3+5 / 2 "` → `5`.

```cpp
#include <iostream>
#include <format>
#include <string>
#include <stack>
#include <cctype>

namespace {
    constexpr char OP_PLUS{'+'};
    constexpr char OP_MINUS{'-'};
    constexpr char OP_MUL{'*'};
    constexpr char OP_DIV{'/'};

    int calculate(const std::string& input) {
        std::stack<int> st;
        int num{};
        char last_op{OP_PLUS};

        for (int i{}; i < static_cast<int>(input.size()); ++i) {
            const char c{input[i]};

            if (isdigit(c)) {
                num = num * 10 + c - '0';
                continue;
            }

            if (!isspace(c) || i == static_cast<int>(input.size()) - 1) {
                if (last_op == OP_PLUS) {
                    st.push(num);
                }
                else if (last_op == OP_MINUS) {
                    st.push(-num);
                }
                else if (last_op == OP_MUL) {
                    const int prev{st.top()}; st.pop();
                    st.push(num * prev);
                }
                else if (last_op == OP_DIV) {
                    const int prev{st.top()}; st.pop();
                    st.push(num / prev);
                }
                last_op = c;
                num = 0;
            }
        }

        int result{};
        while (!st.empty()) {
            result += st.top(); st.pop();
        }

        return result;
    }

    void run_test(const std::string& desc, const std::string& expr, const int expected) {
        const int result{calculate(expr)};
        std::cout << std::format("[{}] '{}' = {}, expected: {}, success: {}",
            desc, expr, result, expected, result != expected ? "OK" : "FAIL");
    }

}

int main() {
    run_test("Example from condition 1", "3+2*2", 7);
    run_test("Example from condition 2 (integer division)", " 3/2 ", 1);
    run_test("Example from condition 3", " 3+5 / 2 ", 5);
    run_test("Multiplication only", "2*3*4", 24);
    run_test("Mixed operations", "14-3/2", 13);
    run_test("Multiplication precedence over addition", "2+3*4-5", 9);
    run_test("Division with remainder (rounding towards zero)", "7/2", 3);
    run_test("Multi-digit numbers", "100*2+50", 250);
    run_test("Chain of subtractions", "10-2-3", 5);
    run_test("Single number without operations", "42", 42);

    return main();
}

```

## Идея — стек для отложенного применения `+`/`-`

Раз `*`/`/` связывают крепче `+`/`-`, естественная стратегия: **сразу** выполнять `*` и `/`, как только встретили — потому что они не могут "передумать" из-за того, что появится дальше. А вот `+`/`-` нужно **отложить**: число, идущее перед `+`/`-`, кладём в стек с нужным знаком, и только в конце **суммируем весь стек**.

Механика: держим `num` (текущее собираемое число) и `lastOp` (последняя увиденная операция — обрабатывается **со сдвигом на один шаг**, то есть при встрече очередного оператора мы применяем **предыдущий** сохранённый оператор к уже готовому `num`):

- Если `lastOp == '+'` → кладём `num` в стек как есть (`+num`).
- Если `lastOp == '-'` → кладём в стек `-num`.
- Если `lastOp == '*'` → **берём** последнее число из стека, умножаем на `num`, кладём результат обратно (заменяем).
- Если `lastOp == '/'` → аналогично, но делим.

В конце — сумма всего, что осталось в стеке.


**Почему условие `i == s.size() - 1` в проверке:** последнее число в строке не сопровождается оператором **после** себя (строка просто заканчивается) — без этого условия последнее число никогда бы не попало на обработку, потому что цикл закончился бы раньше, чем встретился "следующий оператор".

**Почему `lastOp` инициализирован `'+'`, а не как-то иначе:** это трюк, чтобы **первое** число в строке обрабатывалось той же логикой, что и все остальные, без отдельного специального случая — "виртуальный `+` перед самым первым числом" эквивалентен просто "положить первое число в стек как есть".

## Важный нюанс: целочисленное деление и округление к нулю

C++ `int / int` **округляет к нулю** (truncation towards zero), а не "вниз" (floor). Для положительных чисел разницы нет, но для отрицательных — критично: `-7 / 2` в C++ даёт `-3` (к нулю), а не `-4` (floor, как в Python). LeetCode для этой задачи ожидает именно C++-семантику (truncation), так что стандартный оператор `/` уже даёт правильное поведение без дополнительной обработки — но стоит явно об этом знать, потому что в других языках/задачах округление может быть другим, и слепо полагаться на "деление есть деление" — не всегда безопасно.

## Сложность

`O(n)` по времени — один проход. `O(n)` по памяти в худшем случае (если строка — это, например, `"1+1+1+1+..."`, стек накопит по одному элементу на каждое слагаемое перед финальным суммированием).

## Связь с прогрессией задач и вакансией

Это прямое развитие темы приоритета операций, которая была отложена в LC224. Естественный **follow-up** здесь, который стоит проговорить на собеседовании: "а что если приоритетов не два уровня (`+`/`-` и `*`/`/`), а произвольное число, как в реальном языке запросов (`AND` крепче `OR`, но `NOT` ещё крепче `AND`)?" — стековый трюк "сдвиг на один оператор" из этого решения плохо масштабируется на **N** уровней приоритета — для этого используется общая техника **precedence climbing** (или её более явный вариант — **recursive descent** с отдельной функцией парсинга на каждый уровень приоритета: `parseOr()` вызывает `parseAnd()`, который вызывает `parseNot()`, и так далее вниз по убыванию приоритета) — это уже прямая архитектура реального парсера DSL, упомянутого в вакансии.
