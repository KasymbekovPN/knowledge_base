**Условие.** Даны два отсортированных по неубыванию массива: `nums1` длины `m + n`, где первые `m` элементов настоящие, а последние `n` позиций заполнены нулями под результат, и `nums2` длины `n`. Слейте `nums2` в `nums1` **на месте**, чтобы `nums1` стал отсортирован. Возвращать ничего не нужно, `nums1` меняется через ссылку.

**Сигнатура** (уже стоит в шаблоне как заглушка):

```cpp
void merge_sorted(std::vector<int>& nums1, int m, const std::vector<int>& nums2, int n);
```

**Ограничения:** `0 <= m, n <= 1000000`, `nums1.size() == m + n`, `nums2.size() == n`, значения по модулю не больше `1e9`.

1. Какая сложность по времени и по памяти?
2. Почему вы идёте с конца? Что сломается, если идти с начала?

**Цель:** O(m + n) по времени, O(1) дополнительной памяти. Сдвиги элементов при вставке (O(m·n)) на больших тестах не уложатся по времени. Если программа зависла, прервите её вручную, такой тест не прерывается сам.

	void merge_sorted(std::vector<int>& nums1,
					  int m,
					  const std::vector<int>& nums2,
					  int n) {
		
		switch((m != 0 ? 2 : 0) + (n != 0 ? 1 : 0)) {
			case 2: {
				nums1.erase(nums1.begin() + m, nums1.end());
				break;
			}
			case 1: {
				nums1 = nums2;
				break;
			}
			case 0: {
				nums1.clear();
				break;
			}
			default: break;
		}

		const std::size_t size{static_cast<std::size_t>(m + n)};
		
		std::size_t border_count{static_cast<std::size_t>(m)};
		for (std::size_t i1{0}, i2{0}; i1 < size;)  {
			if (border_count == i1) {
				std::swap(nums1[i1], nums2[i2]);
				++i2;
				++border_count;
			} else {
				if (nums1[i1] > nums2[i2]) {
					std::swap(nums1[i1], nums2[i2]);
				}
				++i1;
			}
		}
	}
