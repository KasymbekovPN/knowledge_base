

# Шпаргалка по сложностям

## Сколько операций допустимо

|n|Допустимая сложность|
|---|---|
|≤ 10|O(n!)|
|≤ 20|O(2ⁿ)|
|≤ 500|O(n³)|
|≤ 5 000|O(n²)|
|≤ 10⁶|O(n log n)|
|≤ 10⁸|O(n)|

## Сортировки

|Алгоритм|Лучший|Средний|Худший|Память|Устойчивая|

|Insertion|O(n)|O(n²)|O(n²)|O(1)|да|
|Selection|O(n²)|O(n²)|O(n²)|O(1)|нет|

|Radix (LSD)|O(d(n + k))|O(d(n + k))|O(d(n + k))|O(n + k)|да|

Нижняя граница для сортировок сравнением: Ω(n log n). `std::sort` это introsort (худший случай O(n log n), неустойчивый), `std::stable_sort` устойчивый, O(n log n) при достаточной памяти. `quickselect` и `nth_element`: в среднем O(n), в худшем O(n²).

## Ловушки сложности в C++

- Конкатенация `s = s + x` в цикле даёт O(n²), используйте `+=` или резервируйте.
- `substr` и копирование `vector`/`string` при передаче по значению стоят O(n).
- `erase`/`insert` в начало `vector` O(n), в цикле это O(n²) (используйте erase-remove).
- `unordered_map` деградирует до O(n) при плохом хеше, `map::operator[]` и `unordered_map::operator[]` вставляют ключ.
- `std::string::find` в худшем случае O(n·m).
- Амортизация: `push_back` O(1) в среднем, но разовая реаллокация O(n).

# Рекуррентности и мастер-теорема

## Откуда берётся рекуррентность

Рекурсивный алгоритм делит задачу на `a` подзадач размера `n/b` и тратит `f(n)` на разбиение и склейку результатов:

```
T(n) = a·T(n/b) + f(n)
```

Merge sort, например, это `a = 2`, `b = 2`, `f(n) = n` (слияние).

## Интуиция: дерево рекурсии

- На уровне `i` лежит `aⁱ` подзадач размера `n/bⁱ`.
- Уровней `log_b n`, в листьях суммарная работа `n^(log_b a)`.
- Ответ определяется тем, где работы больше: **в листьях**, **поровну на всех уровнях** или **в корне** (в самом `f(n)`).

## Мастер-теорема

Обозначим `c = log_b a` и сравним `f(n)` с `n^c`.

|Случай|Условие|Ответ|Что доминирует|
|---|---|---|---|
|1|`f(n)` растёт заметно медленнее `n^c` (`O(n^(c−ε))`)|`Θ(n^c)`|листья|
|2|`f(n) = Θ(n^c · logᵏ n)`, `k ≥ 0`|`Θ(n^c · log^(k+1) n)`; при `k = 0`: `Θ(n^c log n)`|все уровни поровну|
|3|`f(n)` растёт заметно быстрее `n^c` (`Ω(n^(c+ε))`) и выполняется регулярность `a·f(n/b) ≤ q·f(n)`, `q < 1`|`Θ(f(n))`|корень|

Для полиномиальных `f` условие регулярности выполняется автоматически.

**Алгоритм применения (30 секунд):** выписать `a`, `b`, `f` → посчитать `c = log_b a` → сравнить `f(n)` с `n^c` → выбрать случай.

## Разобранные примеры

|Рекуррентность|a, b|c|f(n)|Случай|Ответ|Где встречается|
|---|---|---|---|---|---|---|
|`T(n/2) + 1`|1, 2|0|1|2|`log n`|бинарный поиск|
|`2T(n/2) + 1`|2, 2|1|1|1|`n`|максимум делением пополам|
|`2T(n/2) + n`|2, 2|1|n|2|`n log n`|merge sort|
|`T(n/2) + n`|1, 2|0|n|3|`n`|quickselect (в среднем, грубо)|
|`2T(n/2) + n²`|2, 2|1|n²|3|`n²`||
|`4T(n/2) + n`|4, 2|2|n|1|`n²`||
|`8T(n/2) + n²`|8, 2|3|n²|1|`n³`|наивное умножение матриц|
|`3T(n/2) + n`|3, 2|≈1,585|n|1|`n^1,585`|Карацуба|
|`7T(n/2) + n²`|7, 2|≈2,81|n²|1|`n^2,81`|Штрассен|
|`2T(n/2) + n log n`|2, 2|1|n log n|2 при k=1|`n log² n`||

## Когда мастер-теорема не работает

1. **Вычитание вместо деления** (`T(n−1)`): раскрывайте цепочку вручную.
    - `T(n−1) + 1` → `O(n)` (рекурсивный обход списка)
    - `T(n−1) + n` → `O(n²)` (худший случай quicksort, insertion sort)
    - `2T(n−1) + 1` → `O(2ⁿ)` (перебор подмножеств)
    - `T(n−1) + T(n−2) + 1` → `O(φⁿ)`, φ ≈ 1,618 (наивный Фибоначчи)
2. **Неравные части:** `T(n/3) + T(2n/3) + n` → `O(n log n)` по дереву рекурсии (на каждом уровне не больше `n`, глубина `log_{3/2} n`). У quicksort при удачных разбиениях `n log n`, при перекосе `n²`.
3. **Нестандартное уменьшение:** `T(√n) + 1` → `O(log log n)`.
4. **Нет полиномиального зазора** между `f(n)` и `n^c` и `f` не вида `n^c · logᵏ n`: теорема неприменима.
5. **Деревья, графы, мемоизация:** не используйте теорему вовсе, считайте **число состояний × работа на состояние**. Обход дерева с формальной рекуррентностью `T(L) + T(R) + 1` это `O(n)`, потому что каждый узел посещается один раз. Динамическое программирование с мемоизацией: число различных состояний × цена перехода.

| -------------- | --------- |
| `T(n/2) + 1`   | `log n`   |

| `2T(n/2) + n`  | `n log n` |
| `T(n/2) + n`   | `n`       |

| `T(n−1) + 1`   | `n`       |
| `T(n−1) + n`   | `n²`      |

## Упражнения для самопроверки

1. `T(n) = 3T(n/3) + O(1)` → **Θ(n)** (c = 1, f = 1, случай 1)
2. `T(n) = 2T(n/4) + O(√n)` → **Θ(√n · log n)** (c = ½, f = √n, случай 2)
3. `T(n) = T(n/2) + O(n²)` → **Θ(n²)** (c = 0, случай 3)
4. `T(n) = T(n−2) + O(1)` → **Θ(n)** (вычитание, разворачиваем)
5. `T(n) = 2T(n/2) + O(n log n)` → **Θ(n log² n)** (случай 2, k = 1)
6. `T(n) = T(n/4) + T(3n/4) + O(n)` → **Θ(n log n)** (неравные части, дерево рекурсии)

## Как это говорить на собеседовании

> «Каждый вызов делит задачу на две половины, а склейка стоит O(n). На каждом уровне дерева рекурсии суммарно O(n) работы, уровней log n, значит O(n log n). По памяти: глубина рекурсии O(log n) плюс временный буфер O(n)».

Формальную мастер-теорему на интервью называют редко. Обычно достаточно рассуждения «сколько работы на уровень × сколько уровней». А для обходов деревьев и перебора достаточно сказать «каждый узел или состояние посещается один раз» либо «ветвление `a` на глубину `d` даёт `aᵈ`».
