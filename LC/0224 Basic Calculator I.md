
## Суть задачи

Дана строка, представляющая математическое выражение: числа, `+`, `-`, круглые скобки `(`, `)`, пробелы. Нужно вычислить результат. В LC224 (в отличие от LC227) **нет** `*` и `/` — только сложение, вычитание и скобки, что упрощает задачу (не нужно думать о приоритете операций между `+`/`-` и `*`/`/`).

Пример: `"1 + (2 - (3 + 4))"` → `1 + (2 - 7) = 1 - 5 = -4`.

```cpp
#include <iostream>
#include <string>
#include <stack>

namespace {
    constexpr int SIGN_MINUS{-1};
    constexpr int SIGN_PLUS{1};

    int calculate(const std::string &input) {
        std::stack<int> st;
        int result{};
        int sign{1};
        int num{};

        for (int i{}; i < static_cast<int>(input.size()); ++i) {
            if (const char c = input[i];
                isdigit(c)) {
                num = num * 10 + (c - '0');
            } else if (c == '+') {
                result += sign * num;
                num = 0;
                sign = SIGN_PLUS;
            } else if (c == '-') {
                result += sign * num;
                num = 0;
                sign = SIGN_MINUS;
            } else if (c == '(') {
                st.push(result);
                st.push(sign);
                result = 0;
                sign = SIGN_PLUS;
            } else if (c == ')') {
                result += sign * num;
                num = 0;

                const int prev_sign = st.top(); st.pop();
                const int prev_result = st.top(); st.pop();

                result = prev_result + prev_sign * result;
            }
        }

        result += sign * num;
        return result;
    }

    void run_test(const std::string& desc, const std::string& expr, const int expected) {
        const int result{calculate(expr)};
        std::cout << std::format("[{}] '{}' = {} : expected = {} : {}\n",
            desc,
            expr,
            result,
            expected,
            result == expected ? "OK" : "FAIL");
    }

}

int main() {
    run_test("Simple add", "1 + 1", 2);
    run_test("Simple sub", "10 - 5", 5);
    run_test("LC224", " 2-1 + 2 ", 3);
    run_test("Inner braces", "(1+(4+5+2)-3)+(6+8)", 23);
    run_test("Minus before brace", "1 - (2 - 3)", 2);
    run_test("Double minus", "1 - (2 + 3)", -4);
    run_test("Big number", "100 - (50 + 25)", 25);
    run_test("Only braces", "(1)", 1);
    run_test("Deep nesting", "1 + (2 - (3 + (4 - 5)))", 1);
    run_test("Negative result", "0 - 5", -5);

    return 0;
}

```

## Идея — знак как накопленное произведение, стек для скобок

Ключевая идея, которая делает решение элегантным: **не строить AST**, а поддерживать текущий "эффективный знак" перед каждым числом, обновляя его на лету, и использовать **стек** только для сохранения контекста при входе в скобки (что было "накоплено до" и какой знак стоял перед открывающей скобкой).

Состояние во время прохода по строке:

- `result` — накопленный результат на **текущем** уровне вложенности
- `sign` — знак, который нужно применить к **следующему** числу (`+1` или `-1`)
- `num` — текущее собираемое многозначное число

Правила обработки символов:

- **Цифра** → собираем многозначное число (`num = num * 10 + digit`).
- **`+`** → применяем накопленное `num` к `result` с текущим `sign`, сбрасываем `num`, ставим `sign = +1` для следующего числа.
- **`-`** → аналогично, но `sign = -1`.
- **`(`** → всё, что накоплено (`result` и `sign`) на **текущем** уровне, нужно "заморозить" и положить в стек — потому что после `)` вычисление вернётся на этот уровень и продолжит именно с этого состояния. Начинаем **новый** уровень: `result = 0`, `sign = +1`.
- **`)`** → закрываем текущий уровень: применяем последнее число, затем **вынимаем** из стека сохранённый `sign` (тот, что стоял **перед** открывающей скобкой — например, `-` перед `(2-7)`), умножаем результат текущего уровня на этот знак, и **добавляем** к результату внешнего уровня (тоже из стека).

## Сложность

`O(n)` по времени — один проход по строке, каждый символ обрабатывается константное число раз. `O(n)` по памяти в худшем случае — глубина стека равна максимальной глубине вложенности скобок (в худшем случае — каждый символ строки открывающая скобка, то есть `O(n)`).

## Связь с вакансией — построение AST/парсер выражений

Это explicit упомянуто в списке как параллель с **DSL для языка поисковых запросов**. Но важно понимать разницу в подходах между тем, что здесь реализовано, и настоящим построением AST:

Текущее решение **не строит дерево** — оно вычисляет результат "на лету", используя стек только для сохранения контекста. Это оправдано, когда конечная цель — **сразу получить число**, и грамматика простая (только `+`/`-`/скобки, без приоритета операций).

Для **настоящего DSL** поисковых запросов (например, `(title:foo OR title:bar) AND NOT category:spam`) обычно строят полноценное **AST** — потому что:

1. Нужна **множественная обработка** одного и того же распарсенного запроса (валидация, оптимизация плана, оценка стоимости выполнения, кэширование) — вычислить "число сразу" бессмысленно, результат — это структура, по которой потом ходят несколько разных проходов.
2. Приоритет операций сложнее (`AND` обычно связывает крепче `OR`, аналогично `*`/`/` крепче `+`/`-` в LC227/772) — грамматика с несколькими уровнями приоритета обычно реализуется через **рекурсивный спуск** (recursive descent parser) с отдельной функцией на каждый уровень приоритета, а не однопроходным стековым вычислением.

Стоит явно проговорить на собеседовании: то, что здесь реализовано, — хороший образец **однопроходного eval "на лету"**, полезный как компонент, но реальный query language parser для поисковой системы почти наверняка потребует полноценного AST.
