
# `compare_exchange_weak` vs `compare_exchange_strong`

## Разница в контракте

**`compare_exchange_strong`:** если `*this == expected`, гарантированно выполнит запись и вернёт `true`. Никаких ложных неудач.

**`compare_exchange_weak`:** может вернуть `false`, **даже если** `*this == expected` на самом деле выполнялось в момент проверки. Это называется **spurious failure** (ложная неудача) — стандарт явно это разрешает.

```cpp
std::atomic<int> x{5};
int expected = 5;

// weak МОЖЕТ вернуть false, хотя x действительно равен 5
bool success = x.compare_exchange_weak(expected, 10);
// если success == false, expected перезаписывается текущим значением x
// (в данном случае expected снова станет 5, если x не менялся)
```

## Почему вообще существует "ложная неудача"

На архитектурах без честной атомарной CAS-инструкции (в первую очередь **ARM, PowerPC** — LL/SC архитектуры: load-linked/store-conditional) CAS реализуется как пара инструкций:

```
LL   r1, [addr]       ; load-linked: запомнить адрес под наблюдением
CMP  r1, expected
BNE  fail
SC   desired, [addr]  ; store-conditional: сохранить, ЕСЛИ адрес
                       ; не был затронут с момента LL кем-либо ещё
```

`SC` может провалиться не только если значение изменилось, но и по посторонним причинам: **прерывание** (interrupt) между LL и SC, **context switch**, даже иногда просто попадание в ту же кэш-линию другого адреса (в зависимости от гранулярности отслеживания на конкретном ядре). Это и есть spurious failure — CAS не удался не потому что значение не совпало, а потому что сама LL/SC-транзакция была "сорвана" внешним событием.

**На x86 честный `CMPXCHG`** такой проблемы не имеет — там нет LL/SC, есть настоящая атомарная инструкция с гарантированным результатом. Поэтому на x86 `compare_exchange_weak` и `compare_exchange_strong` **компилируются в один и тот же код** — spurious failure там просто не возникает, weak физически не отличается от strong. Разница проявляется только на ARM/PowerPC.

## Почему `strong` "дороже" на ARM

Чтобы дать гарантию "никогда не провалится ложно", `strong` реализуется как **цикл вокруг** LL/SC внутри самой функции:

```
// Псевдокод того, что делает compare_exchange_strong на ARM:
retry:
    LL   r1, [addr]
    CMP  r1, expected
    BNE  real_fail
    SC   desired, [addr]
    BNE  retry          // если SC провалился спонтанно — повторить САМИМ,
                         // не отдавая "false" наружу
real_fail:
    return false
success:
    return true
```

То есть `strong` — это `weak` в скрытом внутреннем цикле retry. Если вызывающий код и так вызывает CAS в цикле (а это стандартный паттерн для любого lock-free алгоритма — push/pop в стеке, enqueue/dequeue в очереди), использование `strong` создаёт **два вложенных цикла**: внешний (ваш) и внутренний (скрытый внутри `strong`).

## Почему `weak` предпочтителен именно в циклах

```cpp
// Ваш паттерн из Treiber stack (напоминание):
while (!head.compare_exchange_weak(old_head, new_node, ...)) {
    // повторная попытка и так здесь, снаружи
}
```

Если использовать `strong` в этом же месте — вы получаете двойной retry: внутренний цикл `strong` уже перепробовал spurious failure несколько раз **прежде чем** вернуть `false` внешнему циклу, который снова начнёт всё заново (перечитает `head`, пересоберёт `new_node->next` и т.д.). Это чистый оверхед — работа внутреннего цикла попросту выброшена, потому что внешний код всё равно немедленно повторяет попытку с нуля.

**С `weak`:** при spurious failure вы сразу возвращаетесь во внешний цикл, который и так должен обрабатывать "не получилось — пробуем снова" — никакой лишней работы, ложная неудача просто сливается с обычной "неудача из-за конкурентной модификации" и обрабатывается тем же кодом.

## Когда наоборот нужен `strong`

Если CAS вызывается **не в цикле**, а один раз (например, "установить флаг инициализации ровно один раз, и если не получилось — сделать что-то другое, не связанное с повтором"):

```cpp
std::atomic<bool> initialized{false};
bool expected = false;

if (initialized.compare_exchange_strong(expected, true)) {
    do_expensive_initialization();
} else {
    // используем уже инициализированное состояние
}
```

Здесь `weak` был бы **опасен**: spurious failure заставил бы код пойти по ветке "уже инициализировано", хотя на самом деле инициализация ещё не произошла — а повторной попытки тут нет, ошибка останется незамеченной. `strong` гарантирует, что `false` означает именно "значение не совпало", а не "CPU решил сорвать LL/SC транзакцию".

## Практическое правило

|Контекст|Что использовать|
|---|---|
|CAS внутри `while`-цикла (retry logic и так есть)|`compare_exchange_weak` — избегаем двойного retry|
|CAS однократно, без внешнего цикла ретраев|`compare_exchange_strong` — нужна гарантия точного результата|

Это тоже частый вопрос на собеседованиях именно потому, что ответ "просто используй weak, он быстрее" — неполный: правильный ответ должен объяснять LL/SC архитектуру и то, что на x86 разницы физически нет, а решающий фактор — наличие/отсутствие внешнего retry-цикла, а не платформа сама по себе.

```cpp

#include <iostream>
#include <format>
#include <memory>
#include <thread>
#include <atomic>
#include <vector>

namespace {

    template <typename T>
    class TreiberStack {
        struct Node {
            T data;
            std::shared_ptr<Node> next;
            explicit Node(T data) : data{std::move(data)} {}
        };

        std::atomic<std::shared_ptr<Node>> head;

    public:
        void push(T value) {
            auto new_value{std::make_shared<Node>(std::move(value))};
            new_value->next = head.load(std::memory_order_relaxed);
            while (!head.compare_exchange_weak(
                new_value->next,
                new_value,
                std::memory_order_acq_rel,
                std::memory_order_relaxed)) {}
        }

        bool pop(T& result) {
            auto old_value{head.load(std::memory_order_acquire)};
            while (old_value && !head.compare_exchange_weak(
                old_value,
                old_value->next,
                std::memory_order_acq_rel,
                std::memory_order_acquire)) {}

            if (!old_value) return false;

            result = std::move(old_value->data);
            return true;
        }
    };

    void producer_worker(const int id, TreiberStack<int>& stack) {
        stack.push(id);
    }

    void consumer_worker(const int id, TreiberStack<int>& stack) {
        if (int value{};
            stack.pop(value)) {
            std::cout << std::format("{} ", value);
        }
    }
}

int main() {
    constexpr int NUM_THREADS{10};

    TreiberStack<int> stack;

    std::vector<std::thread> threads;
    threads.reserve(NUM_THREADS * 2);

    for (int i{}; i < NUM_THREADS * 2; ++i) {
        if (i % 2 == 0)
            threads.emplace_back(producer_worker, i, std::ref(stack));
        else
            threads.emplace_back(consumer_worker, i, std::ref(stack));
    }

    for (auto& thread : threads) thread.join();

    std::cout << "\nDone";

    return 0;
}

```
