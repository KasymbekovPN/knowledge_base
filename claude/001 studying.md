
---

Есть ли у связки claude + vscode конкретное место для хранения few-shot в рамках одного проекта, чтобы они не были разбросаны по всему проекту

---

Да, такое место есть, и это один из самых важных приёмов для постоянной работы. Давайте проверю актуальные детали, чтобы не дать устаревшую информацию. Уточню одну важную вещь: то, что вы видите в VS Code как плагин, — это интерфейс к **Claude Code**, и именно у Claude Code есть встроенный механизм проектной памяти. Few-shot примеры стоит хранить именно через него. Вот как.

## Главный файл: `CLAUDE.md` в корне проекта

Создайте файл `CLAUDE.md` в корне репозитория. Claude Code читает его в начале каждой сессии — ещё до того, как вы что-либо напишете. Это и есть то самое «одно место», которое вы ищете. Он коммитится в git и работает на всю команду.

Но класть туда сами длинные примеры целиком — плохая идея, файл раздуется. Лучше использовать **импорты**: в `CLAUDE.md` вы оставляете ссылки, а примеры лежат отдельными файлами.

## Рекомендуемая структура

```
my-project/
├── CLAUDE.md              ← точка входа, коммитится
├── .claude/
│   └── examples/
│       ├── api-endpoint.ts      ← эталонный эндпоинт
│       ├── error-handling.ts    ← как обрабатывать ошибки
│       └── unit-test.test.ts    ← образец теста
└── src/...
```

А в самом `CLAUDE.md`:

```markdown
# Conventions

При написании кода следуй образцам:
- Новый API-эндпоинт — по образцу @.claude/examples/api-endpoint.ts
- Обработка ошибок — строго как в @.claude/examples/error-handling.ts
- Юнит-тесты — структура и стиль из @.claude/examples/unit-test.test.ts

Не используй `any`. Не меняй публичный API без явного запроса.
```

Синтаксис `@путь/к/файлу` — это директива импорта. Поддерживаются и относительные, и абсолютные пути (например, @docs/api.md или @~/.claude/my-project-instructions.md), рекурсивные импорты до глубины 5. При первом импорте из внешних расположений срабатывает диалог подтверждения для безопасности. Содержимое подтянутых файлов автоматически попадает в контекст Claude, так что примеры не разбросаны — они собраны под `.claude/examples/` и подключены из одной точки.

Удобный момент: директивы импорта не выполняются внутри код-блоков и inline-кода, поэтому документировать их в примерах безопасно.

## Полезные детали

**Вложенные `CLAUDE.md`.** Если у вас монорепо или чёткое разделение, можно класть `CLAUDE.md` в подпапки. Файлы CLAUDE.md в подкаталогах загружаются только когда вы работаете внутри этих подпапок, что держит активный контекст сфокусированным. Так, например, примеры для фронтенда не будут грузиться, когда вы работаете в бэкенд-папке.

**Не путайте с auto-memory.** Помимо `CLAUDE.md` у Claude Code есть автоматическая память, где он сам копит наблюдения о проекте. Но это другое: auto-memory привязана к машине, не синхронизируется между машинами и не делится с командой — это личный блокнот Claude о проекте. Для few-shot примеров, которые должны быть общими и под контролем версий, нужен именно `CLAUDE.md` + импортируемые файлы.

**Личные примеры — в `CLAUDE.local.md`.** Если какие-то образцы только для вас и не должны попадать в общий репозиторий, есть `CLAUDE.local.md` для приватных, специфичных для разработчика заметок.

## Почему это лучше, чем вставлять примеры в каждый промпт

Вы один раз описываете эталоны, и дальше в любой сессии достаточно сказать «добавь эндпоинт для X» — Claude уже знает, по какому образцу его делать, потому что `CLAUDE.md` подгрузился автоматически. Это ровно то, к чему вы шли: единое, версионируемое, не разбросанное по проекту место.

Официальная документация по памяти, если захотите глубже (excludes, настройки, приоритеты загрузки): https://code.claude.com/docs/en/memory
