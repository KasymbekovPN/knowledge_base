Хороший вопрос, и тут есть важный нюанс: слово «skills» в экосистеме Claude означает две разные вещи. Уточню актуальное состояние, потому что эта область быстро менялась.Хорошо, теперь могу дать чёткую картину. Skills — это, пожалуй, самая мощная и при этом недооценённая фича для твоего случая. Разложу по порядку.

## Что такое Skill

Skill — это переиспользуемый «плейбук» для агента. Это SKILL.md файлы, которые расширяют то, что Claude Code умеет делать. Когда ты устанавливаешь skill, ты даёшь агенту специализированный набор инструкций, шаблонов и контекста, к которому он может обратиться для определённого класса задач.

Технически всё просто: каждый skill — это папка, содержащая минимум один SKILL.md файл с frontmatter (name и description) и телом-содержимым.

## Ключевое отличие от CLAUDE.md (это важно понять на старте)

Ты уже знаешь про `CLAUDE.md`. Разница принципиальная и определяет, что куда класть:

CLAUDE.md загружается в каждую сессию проекта. Skills загружаются условно, на основе описания. То есть `CLAUDE.md` всегда в контексте, а skill подтягивается только когда он реально нужен.

Как агент решает, нужен ли skill: Claude читает однострочное описание во frontmatter каждого skill и сопоставляет его с твоим запросом. Расплывчатое описание вроде «помогает с кодом» сработает редко. Конкретное описание вроде «когда пользователь запускает npm test и тесты падают» сработает надёжно. Описание — несущая конструкция.

Простое правило выбора: слэш-команды явные — ты печатаешь /commit и она выполняется. Skills неявные — Claude сам решает их загрузить на основе контекста. Используй слэш-команды для действий, которые хочешь запускать вручную. Используй skills для контекста и знаний, которые Claude должен подтягивать автоматически, когда это уместно.

Иными словами: правила, применимые ко всему репозиторию всегда → `CLAUDE.md`. Специализированные знания для конкретного типа задач, которые нужны лишь иногда → skill.

## Зачем это тебе при разработке

Это решает ровно ту проблему, ради которой ты раньше спрашивал про few-shot. Skills — это как перестать копипастить один и тот же workflow в Claude Code каждую сессию. Ты один раз описываешь, как у вас пишутся тесты / эндпоинты / миграции, и агент сам применяет это, когда берётся за такую задачу — без раздувания постоянного контекста.

Хороший минимальный пример из практики — skill для написания тестов:

```markdown
---
name: test-writer
description: |
  Use this skill when writing or expanding tests.
  Covers Vitest, Playwright, and house-style preferences.
---
# Test writing conventions

## Framework selection
- Use Vitest for unit and integration tests.
- Use Playwright for end-to-end tests that need a browser.
- Do not introduce Jest. The repo no longer has Jest configured.

## Style
- Prefer integration tests over unit tests when the cost is similar.
- Do not mock the database.
```

Это сокращённая версия реального примера, где минимальный skill — это один файл: ~/.claude/skills/test-writer/SKILL.md. Теперь, когда ты просишь «напиши тесты для этого модуля», агент сам подтянет эти правила.

## Куда класть файлы

Два расположения, по аналогии с тем, что ты уже знаешь про CLAUDE.md:

**Личные skills** (доступны во всех твоих проектах): `~/.claude/skills/<имя>/SKILL.md`

**Проектные skills** (коммитятся, работают на команду): `.claude/skills/<имя>/SKILL.md` в корне репозитория.

Расширение в VS Code — это тот же движок Claude Code, так что skills работают в нём идентично терминалу. Никакой отдельной настройки не нужно: положил папку — агент её увидит.

## Как создать свой (самый простой способ)

Можно писать руками, но проще через мета-skill, который создаёт другие skills. Самый быстрый способ собрать skill — использовать Skill Creator, мета-skill, чья работа — строить другие skills. Для пользователей Claude Code его нужно сначала установить: `/plugin install skill-creator@anthropic-agent-skills`. После этого просто описываешь словами, что должен делать skill, и он генерирует структуру за тебя.

## Готовые skills

Не обязательно писать всё с нуля. Anthropic держит публичный репозиторий Agent Skills — это самодостаточные папки с SKILL.md, от творческих задач до технических и enterprise-воркфлоу. Многие из них open source (Apache 2.0). Есть и большие community-коллекции, следующие универсальному формату SKILL.md, организованные по категориям и устанавливаемые одной командой.

Приятный бонус для переносимости: базовый формат SKILL.md (name + description + markdown-инструкции) работает во всех крупных AI-агентах, принявших открытый стандарт Agent Skills, включая Claude Code, OpenAI Codex CLI, Cursor, Gemini CLI и GitHub Copilot. Специфичные для Claude Code фичи безопасно игнорируются агентами, которые их не поддерживают. Хотя на практике Cursor не использует формат skills Claude Code, а Codex принял похожую систему, и форматы сходятся, но полная переносимость пока не гарантирована.

## Как это складывается вместе

Зрелый рабочий процесс в 2026-м описывают как «control stack»: правила проекта, переиспользуемые skills, ограниченные суб-агенты и детерминированные инструменты вокруг модели. Для тебя на старте практичная последовательность такая:

1. `CLAUDE.md` — общие правила и конвенции проекта (всегда активны)
2. **Skills** — специализированные плейбуки под повторяющиеся типы задач: «писать тесты», «новый API-эндпоинт», «ревью на безопасность»
3. **Слэш-команды** — для действий, которые хочешь дёргать вручную

Так ты перестаёшь объяснять одно и то же каждую сессию, а агент сам применяет нужный контекст в нужный момент.

Официальный бесплатный курс Anthropic по skills, если захочешь системно (там как раз разбирают frontmatter, описания-триггеры и progressive disclosure): https://anthropic.skilljar.com/introduction-to-agent-skills
