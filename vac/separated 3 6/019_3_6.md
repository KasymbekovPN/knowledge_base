### https://hh.ru/vacancy/134318672

Это, по сути, повторная публикация ранее разобранной вакансии Zecurion (136486867, оценка 9/10) — тот же работодатель, та же суть роли, но здесь текст сделан с большим акцентом на процессы и культуру разработки, а не на конкретные технические детали.

**Вакансия: 9/10** — Team Lead C++ (Руководитель группы разработки ПО), Zecurion (крупный ИБ-игрок, DLP/DCAP-системы, 10000+ организаций-клиентов), Москва (преимущественно офис, лёгкий гибрид обсуждается, м. ВДНХ), опыт 3-6 лет.

**Чем предстоит заниматься:**
- Создавать среду для качественной разработки: процессы, коммуникации, культура код-ревью и взаимной ответственности
- Синхронизировать техническую команду с продуктом и бизнесом: приоритеты, сроки, управление ожиданиями
- Снимать организационные и процессные блокеры
- Принимать ключевые архитектурные решения — через фасилитацию, а не единолично
- Поддерживать баланс между скоростью доставки и техническим качеством

**Требования:**
- 5+ лет коммерческой разработки на C++, из них 2+ года в роли лида/тимлида/техлида
- Глубокое понимание Linux/Unix, сетевых технологий, архитектуры высоконагруженных систем
- Опыт выстраивания процессов в продуктовой команде: планирование, ретроспективы, метрики, работа с техдолгом
- Навыки people-менеджмента: мотивация, делегирование, развитие инженеров
- Умение переводить бизнес-задачи на технический язык и обратно
- Опыт в ИБ, DLP или смежное (не строго обязательно)

### https://hh.ru/vacancy/137045412

**Вакансия: 9/10** — Embedded-разработчик/Разработчик ПО для STM32, FreeTech («Свободные технологии», производственная компания — автоматизация и мониторинг инженерных систем зданий, коммерческого холода, промышленных процессов), Москва (офис/гибрид, м. Авиамоторная), от 150 000 ₽/мес, опыт 3-6 лет.

Система уже в промышленной эксплуатации — задачи связаны как с новым функционалом, так и с поддержкой/повышением надёжности работающих устройств.

**Задачи:**
- Разработка встроенного ПО для устройств на базе МК **STM32**
- Настройка и использование периферии МК: **GPIO, ADC, DAC, UART, SPI, I2C, timers, watchdog, DMA, PWM, CAN**
- Реализация логики сбора, обработки и фильтрации данных с датчиков
- Работа с промышленными интерфейсами связи: **CAN и RS-485**
- Реализация и поддержка протоколов обмена с оборудованием и верхним уровнем
- Отладка встроенного ПО на аппаратных стендах, макетах, опытных образцах
- Поиск проблем: обмен данными, ЭМП, нестабильная связь, сбои питания
- Взаимодействие с инженерами-схемотехниками, разработчиками верхнего уровня

**Требования:**
- Опыт разработки встроенного ПО от 3 лет
- Уверенное C для МК, опыт с **CMSIS и HAL**
- Понимание архитектуры **ARM Cortex-M**
- Опыт с периферией STM32 (полный список выше)
- Практический опыт с **CAN и RS-485**
- Опыт с **Modbus RTU** поверх RS-485
- Keil uVision, STM32CubeMX, VS Code + GCC
- Чтение электрических схем
- Понимание принципов надёжного embedded-ПО: обработка ошибок, watchdog, контроль состояний, восстановление после сбоев
- Git

**Будет плюсом:** FreeRTOS, CANopen, bootloader/обновление прошивки, работа с energy-independent memory (Flash/EEPROM), опыт с промышленной автоматикой, CI/CD для embedded, Python для скриптов

---

**Хорошо бьётся:**
- **STM32, CMSIS/HAL, ARM Cortex-M** — прямое совпадение (продвинутый уровень)
- **CAN, RS-485** — прямое совпадение
- Периферия (GPIO/ADC/DAC/UART/SPI/I2C/timers/watchdog/DMA/PWM) на регистровом уровне — прямое совпадение с работой над терминалами защит и блоком измерения температур
- Логика сбора, обработки и фильтрации данных с датчиков — прямая параллель с историческим embedded-опытом
- **Понимание принципов надёжного embedded-ПО (обработка ошибок, watchdog, восстановление после сбоев)** — прямое совпадение с защитными алгоритмами терминалов защит
- Чтение электрических схем — базовая embedded-практика
- Git — есть
- Modbus RTU (концептуально) — промышленный протокол, знакомая логика через провайдеры опроса
- Взаимодействие со схемотехниками (не самостоятельное проектирование) — более мягкая форма hardware-взаимодействия

**Разрыв:**
- FreeRTOS (плюсом) — не подтверждено явно
- Bootloader, работа с Flash/EEPROM (плюсом) — новая практика управления прошивками
- CANopen (плюсом) — новый промышленный протокол
- 8-летний перерыв в активной embedded-практике — тот же системный вопрос, что и в других вакансиях

---

Это один из сильнейших embedded-матчей во всей подборке: требования почти дословно описывают ваш исторический опыт — не просто работа с периферией STM32 на регистровом уровне, но именно принципы построения надёжного embedded-ПО (обработка ошибок, watchdog, контроль состояний, восстановление после сбоев), что прямо соответствует защитным алгоритмам, которые вы разрабатывали для терминалов защит электрооборудования. Домен (промышленная автоматизация и мониторинг инженерных систем) также концептуально близок к вашему основному опыту.
