### https://hh.ru/vacancy/136705638

**Обязанности:**
- Разработка, тестирование и совершенствование алгоритмов движения для робототехнических комплексов
- Тестирование моделей в симуляторах (**Gazebo или V-REP**)
- Разработка решений для системы управления движением на основе достижений робототехники и **биологии**
- Собственные исследования и эксперименты
- Интеграция системы с существующим ПО роботов
- Тестирование на реальных роботах

**Требования:**
- Знания в области робототехники, информатики
- C++/Python
- Linux, bash, docker
- Опыт работы в области робототехники
- **Опыт работы с ROS/ROS2**
- **Понимание принципов биологии и нейрофизиологии, связанных с походкой человека и животных**
- Опыт с алгоритмами навигации и управления движением
- Опыт разработки систем управления движением в симуляционной среде
- Опыт с сенсорами IMU, Lidar, 3D-камеры
- Английский для чтения документации

**Желательно:** кандидаты наук/профессора в области робототехники, использование нейросетей для алгоритмов движения

---

**Хорошо бьётся:**
- C++ — сильная сторона
- Linux, Docker (средний) — совпадает
- Python (базовый) — есть

**Существенный, специализированный разрыв (это ядро роли):**
- **ROS/ROS2** — устойчивый пробел, характерный для всех робототехнических вакансий подборки
- **Биология и нейрофизиология походки человека/животных** — совершенно новая, узкоспециализированная научная область, не пересекающаяся ни с одним направлением вашего опыта
- Симуляционная разработка систем управления движением (Gazebo/V-REP) — новая область
- Алгоритмы навигации и управления движением — специализированная робототехническая математика, отсутствует
- IMU/Lidar/3D-камеры как сенсорный стек — новая предметная область

---

Это одна из самых узкоспециализированных вакансий в подборке — она требует не только ROS2-экспертизы (устойчивый пробел для всех робототехнических позиций), но и специфического научного бэкграунда на стыке биомеханики, нейрофизиологии и робототехники (биоморфные алгоритмы походки), что фактически описывает роль научного сотрудника-исследователя, а не инженера-программиста в привычном понимании. Формулировка "желательно кандидаты наук/профессора" подтверждает исследовательский, а не инженерно-прикладной характер позиции.

### https://hh.ru/vacancy/137011506

**Вакансия: 2/10** — Robotics Software Engineer (C++, Python, ROS2), «Аксион Софт» (технологический стартап — универсальный "мозг" для управления сложной техникой), Москва (офис/гибрид, м. Воронцовская/Калужская), опыт 3-6 лет.

**Чем предстоит заниматься:**
- Разработка ПО для робототехнических систем на C++ и Python под Linux
- Разработка и интеграция компонентов на базе **ROS/ROS2**
- Алгоритмы автономной навигации: **Global Planning, Local Planning, Obstacle Avoidance**
- Работа с алгоритмами **SLAM** и локализации, включая **AMCL**
- Сенсорное слияние данных (**Sensor Fusion**) с использованием **EKF/UKF**
- Алгоритмы управления и движения робота: **PID-регуляторы**, кинематика
- Работа с данными **2D/3D LiDAR и RGB-D** сенсоров, использование **PCL**
- Тестирование в симуляции и на реальном оборудовании (**Gazebo/Webots/Isaac Sim**)

**Требования:** уверенное C++/Python под Linux, практический опыт ROS/ROS2, разработка ПО для робототехники, знание алгоритмов навигации/планирования/локализации/SLAM, AMCL, понимание EKF/UKF, теория управления/PID/кинематика, опыт с LiDAR/RGB-D, опыт с Gazebo/Webots/Isaac Sim.

**Плюсом:** ML/AI в робототехнике

---

**Хорошо бьётся:**
- C++ — сильная сторона
- Python (базовый) — есть
- Linux — вероятно есть
- ПИД-регуляторы (концептуально) — прямая параллель с устройством плавного пуска

**Существенный, комплексный разрыв (это ядро роли):**
- **ROS/ROS2** — устойчивый пробел, характерный для всех робототехнических вакансий подборки
- **SLAM, AMCL, локализация** — специализированная робототехническая математика, отсутствует
- **EKF/UKF сенсорное слияние** — тот же класс задач фильтрации Калмана, что и в вакансии «Ориент Системс» (навигация), отсутствует
- **PCL (Point Cloud Library), работа с LiDAR/RGB-D** — специализированная обработка 3D-данных, отсутствует
- Gazebo/Webots/Isaac Sim — симуляционные среды, новые

---

Это одна из наиболее технически насыщенных робототехнических вакансий в подборке — она требует одновременно ROS2-экспертизы, SLAM/локализации, сенсорного слияния через EKF/UKF-фильтры и обработки облаков точек (PCL), причём каждая из этих областей по отдельности уже была системным пробелом в других вакансиях. Общий C++/Python/Linux даёт минимальную базу, но совокупный объём новой специализированной робототехнической математики здесь один из самых больших среди всех разобранных позиций.

### https://hh.ru/vacancy/134160545

Место работы — **Санкт-Петербург**, формат полностью удалённый, зарплата от 512 000 до 768 000 ₽/мес — одна из самых высоких в подборке.

**Вакансия: 2/10** — Разработчик (Medical Imaging), «ГравиЛинк», Санкт-Петербург (удалённо), опыт 3-6 лет. Глобальная AutoML-платформа для медицинских специалистов — загрузка размеченных медицинских данных (КТ, МРТ, рентген) → обученная модель для классификации.

Компания использует **собственный язык программирования MPL** — нетипичный, кастомный стек.

**Нам важно, чтобы вы:**
- Имели твёрдые фундаментальные знания математики и ИТ
- Имели реальный опыт программирования на любом ОО-языке (не в учебных проектах)
- **Имели опыт fullstack-разработки: backend, frontend и интеграции между ними**
- Имели опыт работы с базами данных, Docker
- Знали сетевые протоколы, писали сетевой код
- Умели проектировать API/сервисы для больших файлов и долгих операций
- Были готовы разбираться в специфике medical imaging (форматы данных, пайплайны загрузки)

**Обрадуемся, если:** опыт с медицинскими данными, опыт с ML, автотесты/observability/production-debugging

---

**Хорошо бьётся:**
- Твёрдые фундаментальные знания математики и ИТ — сильная сторона
- Реальный опыт программирования на ОО-языке — сильная сторона (C++)
- Базы данных, Docker — совпадает
- Сетевые протоколы, сетевой код — концептуально близко к NBI-модулю
- Проектирование API/сервисов для больших файлов и долгих операций — концептуально знакомо через архитектуру интеграционных систем

**Существенный разрыв:**
- **Fullstack-разработка (backend + frontend)** — ваш опыт в основном backend/системный, frontend-часть отсутствует
- **Собственный язык программирования MPL** — совершенно новый, нетиповой стек, изучение которого потребуется с нуля независимо от предыдущего опыта
- Специфика medical imaging (форматы КТ/МРТ/рентген, пайплайны) — новая предметная область
- ML (обрадуемся) — не глубокий опыт

---

Это привлекательная по компенсации и формату (полностью удалённо) позиция, но с существенным техническим барьером — компания использует собственный проприетарный язык программирования (MPL), что означает необходимость изучения совершенно нового инструмента независимо от предыдущего опыта, плюс требование к fullstack-разработке (включая frontend, которого в вашем опыте нет) и погружение в специфику медицинской визуализации. Общие фундаментальные навыки (математика, сетевой код, работа с большими файлами) дают базу для разговора, но реальная продуктивность потребует значительного времени на адаптацию к нетиповому стеку.
