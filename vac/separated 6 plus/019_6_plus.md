## Разборы вакансий

### https://hh.ru/vacancy/136996777

**Вакансия: 9/10** — Руководитель группы/ведущий разработчик встраиваемого ПО, «Тул Лэнд», Химки (офис), опыт 3-6 лет (формально ниже вашего, но реальный уровень ответственности выше). Небольшая группа разработки ПО для аппаратных изделий: встроенное ПО контроллеров, ПО управления/мониторинга/диагностики и контрольно-проверочной аппаратуры (КПА).

Руководитель подчиняется главному конструктору, работает совместно с разработчиками электроники, конструкторами и инженерами-испытателями.

**Чем предстоит заниматься:**
- Руководить командой из **2-3 разработчиков**: ставить задачи, контролировать сроки/качество, проводить технические ревью, развивать сотрудников
- Участвовать в разработке архитектуры и ключевых модулей ПО
- Разрабатывать и сопровождать встроенное ПО для **STM32** и аналогичных МК
- ПО для настройки, мониторинга, диагностики и испытаний изделий
- Организовывать взаимодействие встроенного ПО с ПО КПА, стендами, внешними устройствами
- Участвовать в отладке аппаратно-программных комплексов с электронщиками и испытателями
- Организовать процессы командной разработки: Git, code review, сборка, релизы
- Развивать автоматизированное тестирование
- Поддерживать техническую документацию

**Основные требования:**
- Опыт разработки embedded ПО на C от 4 лет
- Практический опыт с STM32 или аналогичными МК
- Уверенное знание периферии MCU: **GPIO, таймеры, PWM, ADC, DMA, прерывания, watchdog, Flash**
- Опыт построения архитектур РВ, работа с **FreeRTOS** или другой RTOS
- Практический опыт: **UART/RS-485, CAN, SPI, I²C, Ethernet**; Modbus — преимущество
- Навыки отладки: **SWD/JTAG, отладчик, осциллограф, логический анализатор, CAN-анализатор**
- Понимание принципов работы МК-устройств, чтение несложных электрических схем
- Опыт разработки сервисного/диагностического/КПА ПО на **Python, C# или C++**
- Git, code review, CI/CD или автоматизация сборки
- Опыт автоматизированного тестирования
- Опыт технического лидерства, наставничества или управления небольшой командой
- Готовность совмещать управление и самостоятельную инженерную работу

**Будет плюсом:** ПО для промышленной автоматики/силовой электроники/приводов/источников питания/зарядных устройств/измерительного оборудования, проектирование БД для журналов/испытаний/телеметрии, Linux/Docker/PostgreSQL/SQLite, испытательные стенды, CANopen/J1939/UDS/MQTT/OPC UA, релизы firmware (загрузчики, OTA, версионирование), использование AI-инструментов для ускорения разработки

**Хорошо бьётся:**
- **Руководство командой из 2-3 разработчиков** — прямое совпадение (ваш диапазон 3-10 человек, включает и меньшие команды)
- **STM32** — прямое совпадение (продвинутый уровень)
- **CAN, UART/RS-485, SPI, I²C** — прямое совпадение с историческим embedded-опытом (терминалы защит, устройство плавного пуска)
- Периферия MCU (GPIO/таймеры/PWM/ADC/DMA/watchdog/Flash) на регистровом уровне — прямое совпадение с блоком измерения температур
- SWD/JTAG, осциллограф, логический анализатор — базовая embedded-практика (2013-2018)
- Постановка задач, контроль сроков/качества, технические ревью, развитие сотрудников — прямое совпадение с управленческим опытом
- Готовность совмещать управление и инженерную работу — соответствует стилю "играющего тренера"
- Git, code review — есть
- Сервисное/диагностическое ПО на C++ — сильная сторона
- Промышленная автоматика/силовая электроника/приводы/источники питания (плюсом) — прямая параллель с устройством плавного пуска (управление электродвигателем)
- **AI-инструменты для ускорения разработки (плюсом)** — прямое совпадение с реальным опытом (Claude API)

**Разрыв:**
- FreeRTOS конкретно — не подтверждено явно, хотя embedded real-time опыт даёт хорошую базу
- Ethernet на аппаратном уровне — частично новый интерфейс
- Modbus, CANopen/J1939/UDS/OPC UA (плюсом) — новые промышленные протоколы
- Linux/Docker/PostgreSQL (плюсом) — частичное совпадение
- Релизы firmware (загрузчики, OTA) — новая практика управления версиями прошивок

---

Это один из самых сильных матчей во всей подборке: масштаб управления (небольшая команда 2-3 человека при подчинении главному конструктору) точно соответствует нижней границе вашего диапазона, базовые embedded-требования (STM32, CAN, периферия на регистровом уровне) почти дословно совпадают с историческим опытом, а домен силовой электроники (плюсом) — концептуальная параллель с устройством плавного пуска. Формат "играющего тимлида" (управление + личное участие в разработке и отладке) — именно тот стиль работы, в котором вы существуете последние годы, а упоминание AI-инструментов как плюса резонирует с вашим реальным опытом использования Claude API.
